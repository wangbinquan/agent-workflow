# RFC-370：维护服务冷生命周期的清单与发布

本批只发布维护服务和监工的冷创建、当前生命周期准入、失权停止新工作，以及等待原实际尾部和 Worker ACK 的接口。原立即启动入口、普通暂停／恢复、原维护行为和两个 provider 的实际释放路径保留。完整十九个 owner、三个真实启动根、H7／A-T7／A-G、各层 CS adapter 和先 M0 实际部署再 M1～M4继续开放，AW 尚未部署 CS。

有限 SOURCE-R4 已独立复核并由根消费：51 项＝7 owned／40 control／4 evidence，首／closing／末三轮完整 EOF 身份相同，末轮七个实际文件与冻结稿全文相同，有效、稳定 PASS，功能 findings 为零。R1 的两项、R2 的两项与 R3 的一项失败记录保留。R4 只修正普通 pause 后失权的恢复意图；旧 A 的 resume 仍拒绝，后继 B 仍须等待实际尾部、旧 ACK 和新 ready。详见[维护设计与回归](maintenance-cold-lifecycle.md)。

原 scoped census 对这个已通过的五个 TypeScript 文件执行一次：两个生产、三个测试。四个原生成规则全文保持，6,863 份非本批源码从确切基底 `540168eceeabe9a70ba6030dbbd5cb8a79db78c2` 的 Git blob 读取；事件投影候选、累计用量持久化／性能和脑图反问在途源码均排除。输出仅写入本批临时材料，十三份清单继续使用原生成规则和判据。本机没有运行 AW test／typecheck／build／服务／E2E，也没有第二次整批 census。
