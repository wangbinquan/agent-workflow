# RFC-372 左侧问题树精修

用户在实际页面中指出折叠箭头难看、目录信息密度太低，要求重新设计整棵树。本修正沿用已批准的工作区及弹窗合同，只改变目录呈现，不增加任务状态或生成接口。

## 现状与目标

日常 AW 实测 1113 × 898 视口中目录宽 240px，分类行 72px、长问题行 76px。单独的状态行、较大的上下留白与字符三角箭头使六道题也不能同时看全。

采用紧凑的两行标题树：分类约 32px，普通长问题约 44px，短标题不强行撑成双行。目录宽调整为 280–320px；手机仍使用原单面板切换。完整问题正文继续在弹窗或聚焦区阅读，选中不能把树行突然撑高。

## 交互与视觉

- 折叠控件沿用公共按钮，使用 14px 描边 SVG chevron，24px 点击区域；旋转表示展开，悬停和键盘焦点明确。点击箭头只折叠，点击标题才选择并打开问题。
- 题号、两行标题预览与状态同处一行；分类右侧展示已确认/总题数。问题状态使用形状与颜色区分并保留可访问文字；有未完成后代时补充紧凑计数，不能让本题绿色掩盖子题待处理。
- 每层缩进 14px，连接线只延续确有后续兄弟的祖先，在最后一个子项处收束。最多绘制五层导线；更深处保留真实 ARIA 层级、实际父题与深度文字，不能伪装成同级。
- 标题的完整文字保留在 DOM 与原生悬停提示，触屏点击仍可读取全文。选中背景轻量，文字保持清晰，不依赖单一颜色传递状态。
- 搜索保留原结果列表语义和祖先路径；键盘上下、左右、Home/End、Enter/Space 及虚拟列表继续可用。折叠后必须有一个可达的键盘停靠项，不把焦点留在不参与 Tab 的箭头上。
- 复用 TextInput、VirtualList、MindmapStatus 与既有按钮、颜色变量；不引入第二套树数据、图标依赖或自制窗口化。

## 完整实现后集中验证

1. 编写导线延续、最后兄弟、深度上界、折叠不打开、父题/后代状态分离与标题不丢失的回归。
2. 对已有真实录制 E2E 增加实际行高、同屏密度、清晰 SVG 箭头与折叠后焦点断言；保留完整任务续跑与最终文档检查。
3. 全部实现和用例写完后，集中运行定向组件、投影与录制 E2E；不重跑整仓本地 gate。
4. 在日常 AW 的已完成真实任务检查展开/折叠、长标题、搜索、弹窗往返、深浅主题与 320/390/1024/1440px 布局，保存前后截图与尺寸。
5. 范围内独立功能检视、精确提交、推送后跟踪对应 CI。原共享架构清单阻塞和其他会话的失败单独保留。

## 用户追加：多级分类配置与系统内置规则

现有模型输出和工作区支持多段 `categoryPath`，配置入口却只有一层 ChipsInput。补齐真实配置能力，不把“一层标签”冒充多级编辑器。

- `mindmap.categories` 保持原字段，兼容原来的单层字符串；新增接受非空字符串数组作为完整路径。读取旧字符串时按单段路径解释，不拆分名称中的斜杠，不添加另一份分类事实。编辑器在用户保存分类修改时写入完整路径数组。
- 配置使用公共 `CategoryTreeEditor`，复用表单和按钮，支持添加一级分类、选中分类后添加子分类、重命名（同步整条子树前缀）、删除分类及其后代。名称最长 120 字，整棵配置最多 40 个分类节点；不同父级允许同名，同一父级拒绝重复或空名。删除不触碰历史任务的快照，工作流沿原修改/撤销机制保存。
- 行为按完整路径控制，不用显示名称当全局 ID。选中当前分类时可见完整路径；深层缩进有上限但显示实际层级。按钮、输入、错误及操作结果都可通过键盘到达。提交前的输入草稿不改写工作流，取消不丢原配置。
- 系统统一内置分类/提问规则，首次 self/cross 反问及后续追问都使用：按相关领域组织层级，优先采用已配置的最具体路径；宽泛类别按有意义的子主题细分；优先问影响决策的未决点，覆盖相关兄弟方向，避免重复已答内容；分类路径与父问题依赖分开。
- 配置字段改为“补充关注点（选填）”，说明分类和追问规则由系统提供，空值可正常提问。原 instructions 值继续传递，不替用户删除已填内容。节点内补充方向同样是可选业务偏好。
- 首次提示词和追问共用一个规则文本，追问读取原任务快照的配置路径。分类目标继续直接追加该分类的同级题；指定父题继续追加其直接子题；根级补问可使用完整分类路径。原协议、问题数量、nonce 和最终提交边界保持。

补充测试：旧平面配置与新多级配置往返、斜杠名称、40 节点边界、分类新增/重命名/删除/取消、清空关注点仍含内置规则、self/cross 与 follow-up 的配置路径接线。全部实现与用例编写完成后统一进入验证。

### 日常 AW 第三次真实模型任务

任务“多级分类与内置提问 · 真实模型验收 2026-10-13”，ID `01M4TB2FRHBMGTXJZVMSPF9NMK`，在日常 AW 的原数据目录运行。工作流 ID `01M4TAQK87FTHK6X1FX2DQZX1T`，原反问轮 `01M4TB3ZF4NGBS36CKR8RRETYT`。实际运行时为 OpenCode，模型为 `opencode-go/deepseek-v4.1-flash`，未使用模型 Mock。

通过页面配置“性能 → 服务性能 / 数据库 → 慢查询”和“可靠性 → 故障恢复”，补充关注点留空；页面实际验证三级新增、父级重命名连带后代、删除及原撤销恢复。初始模型按这三条叶子路径生成 3 题。逐题回答并确认后，对慢查询执行空指引补问，实际追加 4 道同级题；对其中索引优化补充业务方向，追加 1 道子题；再在根级补“性能 → 数据库 → 连接池”，追加 1 题。九题全部确认后沿原停止反问按钮提交，最终 output 为 1950 字符文档，任务状态 `done`。

### 视觉与交互实测

新目录分类行 32px、问题行 44px，真实 ARIA 层级到第 5 层；父题已确认而子题待答时单独显示子题待处理数量。验收检查了 1440/1024/390/320px、浅色与深色、搜索/折叠/重新展开、弹窗与聚焦工作区。320px 的问题弹窗左右边界为 8/312px，文档宽度仍为 320px，长问题和选项在弹窗正文内滚动，确认操作可达。分类配置的树与工作区沿用同一个公共 SVG 折叠控件。

真实画布又发现约 40% 缩放时三级分类标签因碰撞留白过大而隔层消失；缩略标签高度从 30px 改为 24px，保留 12px 文字、状态点及同一命中矩形。新增回归使用真实层级投影/布局检查全部分类标签及逐节点点击命中，不用截图颜色相似性代替行为验证。用户的原主题“跟随系统”及浏览器默认视口在验证后恢复。

可复查的私有原始证据位于 `.agent-workflow/rfc372-real-acceptance-20261013/`：`hierarchy-actual-*`、`hierarchy-final-design.md`、`category-editor-light.png`、`category-editor-dark.png`、`outline-390.png`、`hierarchy-modal-320.png` 和集中验证日志。设计文档不发布指向本机服务或忽略目录的 Markdown 链接。
