## 1. 数据和执行边界

现有工作流反问节点、`clarify_rounds`、问题 ID、答案 JSON、逐题协作草稿、提交与 human-gate continuation 是唯一事实来源。脑图是问题列表的投影，不增加 Task 执行周期、设计材料消费者或第二条释放任务的机制。

- workflow：保留 `interactionMode: questions | mindmap`；脑图配置只包含分类提示与追问指引。旧节点缺省 questions。
- question：原 id/title/kind/options 不变，增加可选 `mindmap`，包含 `categoryPath: string[]`、`parentQuestionId?: string`。分类路径产生虚拟分组节点；问题 ID 保持原答案关联。
- answer/draft：增加可选当前确认依据；确认绑定当前问题和答案内容。保存答案清除原确认。原问卷不要求确认，字段缺省保持既有行为。
- round：模式由冻结配置/保存的问题元数据确定；历史轮次使用已保存内容，不读取当前编辑工作流来重新解释答案。
- 分类及父问题结构由服务端校验：ID 唯一、父引用存在、无循环、保留模型输出顺序。非法输出反馈为原协议错误，不默默丢失问题。

不新增上述内容以外的持久模型；草稿和最终答案都经原接口和事务。现有数据库已经有问题/答案/草稿 JSON，不为分类树另建表。

## 2. 模型协议和原执行流程

原 `workflow-clarify` envelope 和 nonce 保持。脑图模式仅追加明确的分类输出说明与例子。普通问答的提示词及解析限制保持原行为。初轮仍按既有提问批量；追加追问每次最多一小批，累计问题不套单轮输出的截断上限。

业务 Agent 仍由现有运行器发起反问，原 `createClarifyRound` 持久化问题和开门。完成时原 SubmitClarifyAnswers -> seal -> dispatch -> continuation 处理，脑图不 mint run、不自行恢复任务、不增加交付页面或等待材料状态。

## 3. 分支追问

在一个未提交问题上点击“继续追问”，请求包含 round、父问题、请求 ID 及所依据的当前问题和答案版本。服务端读取实际问题/草稿，复用现有运行时调用设施生成少量子问题；提示词携带当前分支、祖先问答和分类，不复制无限全图。

2026-10-13 扩展原请求的生成目标：`parentQuestionId` 与 `categoryPath` 二选一；非空分类路径读取该前缀下全部问题及有效答案，追加题直接放入该分类且不设置父题；根路径 `[]` 读取本轮上下文，由模型为新题给出分类。具体问题仍携带祖先链。两种目标复用原生成、幂等、取消及写回锁；分类分支全部封存后不接受追加，部分封存时以封存的最终答案覆盖旧草稿。上下文与指引总长度沿用上限，过大时明确拒绝。

新增问题写回同一 `questionsJson`。生成在事务外执行；写回时在原 Task/round 的事务锁下复核轮次仍开放、父问题和依据仍相同。提交已发生或回答已改变时返回冲突，保留现有问答。新增 ID 从请求身份派生，持久标记请求来源，使超时重放不会重复追加。用户在生成期间可以查看其他分支，提交需等待正在处理的追问结束或取消。

脑图提交额外携带读取时的问题集合摘要；它由当前完整问题内容派生，与原业务 iteration 分开。追加与提交在原 Task/round 锁内核对同一当前集合，服务端同时要求全部当前未锁定问题都有有效回答和匹配该问题/答案的确认。集合已变化时返回冲突并保留草稿，要求刷新审阅新增题；不能让原 quick finalize 的补空答案逻辑跳过新问题。这样即使另一标签页未收到更新、且追问已经完成，旧集合也不能提交。普通问卷保留原提交条件。

追问不新建业务运行，不改变 Task 状态，不把新问题自动视为已回答或已确认。失败与取消直接留在工作区处理，不引入独立提案、采纳、消费生命周期。

生成端口归 collaboration 内部所有；task-execution 的原生执行适配器声明自己需要的运行 ID、任务 ID、请求 ID、提示词和取消信号。两个 daemon bootstrap 通过原路由装配入口检查类型兼容并注入适配器，task-execution 不反向导入 collaboration 的端口，内部端口也不额外公开。此边界只调整类型依赖，生成、取消和任务续跑的运行时代码保持。

## 4. 单一工作区

原反问详情页面继续拥有 answers、draft durability controller、WS invalidation 和提交 mutation。脑图组件只接收 questions、answers、locked IDs、onChange/onConfirm/onFollowup 等回调；不维护第二份答案或持久化系统。

- 全景：中心为本轮主题，分类为分组，问题/子问题为叶或分支；展示所有轻量节点的布局，按视口裁剪绘制，不挂载所有完整表单。
- 聚焦：同一选中节点、同一 QuestionForm；分类可看虚拟化列表，问题可看子问题及祖先路径。
- 状态：未回答、待确认、已确认；已经经原集中答题提交的题目显示既有锁定状态。分类从全部后代聚合，折叠和视口外节点不从统计中消失。
- 回答变动令本题确认失效，确认不等于已提交。所有问题已填且确认后显示全绿；用户仍明确提交，沿用原继续/停止反问的含义。
- 草稿失败、多人修改、刷新恢复与离开保护复用原能力，不能在本地写失败时显示已保存。
- 平移和拖选区分点击；缩放以指针为锚；选择/回答/确认不自动改变视口；双击不缩放。搜索定位、键盘、可见焦点、320/390px 窄屏和主题均可用。

用户追加的正式呈现见 [UX 重设计](./ux-redesign-20261013.md)：同级横排、后代纵向；左侧目录按真实分类与父题关系渲染，保留虚拟化；全景点击问题/分类用公共 Dialog 居中显示，聚焦视图沿用同一正文组件。弹窗关闭不重置相机、答案或生成，切换问题后仍可取消原请求。答案、确认与原整轮提交均无第二套状态。
