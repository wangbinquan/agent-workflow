# RFC-372：现有反问的脑图模式

> 状态：In Progress。2026-10-12 用户明确选择轻量方案，并要求删除已经实现的冗余内容。本版取代此前“脑图反问与设计交付”的扩大范围。

## 产品目标

在既有 `clarify` / `clarify-cross-agent` 上增加脑图显示模式。模型仍按现有反问协议提出问题，只增加分类与父问题信息。用户在全景脑图和聚焦工作区中处理同一份问题、答案和确认，完成后沿现有提交、派发与续跑流程继续任务。

## 本次范围

1. 原反问节点增加普通问答 / 脑图问答切换及分类提示配置。
2. 提示词引导模型按分类提问；原 `workflow-clarify` 输出增加可选分类路径和父问题 ID，旧问答协议保持兼容。
3. 一个页面中的全景画布、聚焦问题列表与答案编辑，共享选择、草稿及确认。原 `QuestionForm`、草稿持久化、多人更新和提交能力直接复用。
4. 颜色展示未回答、待确认、已确认；分类节点由全部后代聚合。回答改变后该答案的确认失效。工作区全绿表示本轮问题均已回答并确认。
5. 用户可在一个问题下继续追问，模型小批返回子问题，追加到当前未提交轮次。只增加问题，不提交答案、不推进任务；失败可重试，已接受请求不重复追加。
6. 平移、指针锚定缩放、搜索定位、折叠、键盘和窄屏；不提供“放大此分支”或双击放大。画布用轻量投影及视口裁剪，详情只渲染选中问题，广列表虚拟化。
7. 点击现有提交动作后复用原反问问答反馈、self/cross 路由、多来源等待、会话模式及正常续跑。

## 明确删除的扩大范围

独立设计 session/node/快照与版本确认体系、必答覆盖台账、条件规则引擎、范围基线、依赖失效图、4+1 图件核验、独立 AI 提案及采纳状态机、Task entry/host occurrence、设计交付和消费戳、独立材料预算/精简审阅/精确快照文件、模板提取回流和 workflow 保存回执扩展均移出本次。对应本会话生产代码、路由、配置、依赖和专属测试一并清理，不留下隐藏的第二条执行链。

已有历史 Git 提交不改写。已发布冗余表通过新版本的向前迁移及 schema 清理退役；历史迁移文件保留供顺序升级。其他会话的并发改动完整保留。
