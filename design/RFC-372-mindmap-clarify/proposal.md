# RFC-372 提案：脑图反问与设计交付

> 状态：In Progress；2026-10-12 用户明确批准实施。全景与聚焦共享数据和状态，审阅留在工作区；正式版取消分支放大并完善画布交互。
> 技术合同见 [design.md](design.md)，实施顺序见 [plan.md](plan.md)，原型范围见 [prototype.md](prototype.md)。

## 1. 要解决的问题

现有反问适合一次性的少量选择题。复杂设计需要保留人的原始判断、逐层探索条件与例外、检查相互依赖，并在确切版本上确认。仅增加问卷题数或把聊天记录画成树，不能证明设计已经满足工作流预置要求，也不能可靠地把结果交回业务 Agent。

新增“脑图反问”交互模式，让工作流作者预置需要讨论的问题和完成标准，让使用者在一个可恢复的工作区里回答、深入、核对图件、处理复核事项，最后将不可变设计快照交给准确的接收者。

## 2. 用户旅程

1. **作者配置**：在现有反问节点上选择脑图模式，编辑递归模板。分别配置必答程度、追问方式、适用条件、完成标准和重新进入规则。保存沿用现有工作流编辑行为。
2. **框架开图**：必答或用户明确发起时，宿主在合法进入点建立完整模板骨架并等待人处理。模型不可用仍能手动设计。按需模式保留源 Agent 请求入口。
3. **人作判断**：看到问题、为什么问、何时算解决，填写原话、选择或有类型的事实。普通保存不调用 AI；明确“继续深入”或“检查本分支”才调用。
4. **就地确认**：在设计工作区直接确认当前判断、标准、图件和范围。分支聚合包含未加载后代，整棵树所有适用义务满足即显示审阅完成，不另设审阅清单。控制答案变化时，只让实际受影响的项重新复核。
5. **明确完成**：工作区全局审阅完成后，简短确认采用范围和接收对象，冻结快照并继续工作流。正常交付自动处理；材料超限、容量未知或输入变化时在同一工作区处理，关闭后可稍后继续。完成与交付不再占用独立页面。
6. **以后继续**：关闭页面保留进度；历史快照可读。技术重试沿用同一周期，真实重新进入按配置处理。旧快照遇到新来源输入时明确核对适用性或重新开图。
7. **沉淀模板**：选择有价值分支，提取通用问题、条件和标准，在独立提取稿中修改并查看差异。明确“应用到工作流”才保存正式新版本；当前任务仍用已冻结模板。

## 3. 已采用的产品裁决

| 决策                                              | 用户可见结果                                                                            |
| ------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 用 `interactionMode` 扩展现有 self/cross 反问节点 | 原拓扑、入口与问卷继续有效；脑图内容不是工作流 DAG                                      |
| 原话、AI 提议、采用表述和人的确认分开             | 保存、采纳与确认互不代替；不把模型输出当作人的同意                                      |
| 全景与聚焦共用一份设计                            | 全景画布查看完整结构与完成/待深入分布，聚焦工作区处理具体判断；切换保留节点、草稿及状态 |
| 不设业务层级上限，分开设计全景和局部渲染          | 全景用轻量拓扑与语义缩放，聚焦用分段读取和有限内容卡；深层内容一直计入完整状态          |
| 必答由模板与覆盖台账决定                          | 隐藏、折叠、删除或移出范围不能消除必答义务                                              |
| 工作区内就地确认，保留独立记录                    | 全局全绿即审阅结束，无须进入另一个清单再确认                                            |
| 完成确认与原任务状态承载交付                      | 无独立交付页；多来源等待或材料异常仍有准确状态和恢复入口                                |
| 必答骨架不依赖模型启动输出                        | AI 失败可手工完成，重试不会重新建立同一张图                                             |
| 模板回流使用正式版本保存                          | 不引入与当前产品不符的“保存后再发布”生命周期                                            |

## 4. 完整范围与实施节奏

最终范围包含：递归模板、三态适用条件、标准与实质深度、范围与依赖失效、4+1 图件、短 AI 动作及部分采纳、原话与证据、self/cross、explicit/each_iteration、双运行时、持久快照、消费与恢复、模板回流和旧问卷回归。

首先以小模板贯通开图、人工确认、快照、完成和 asker 执行的真实链路，随后逐步加入完整内容模型、全景/聚焦、AI/图件、cross/大材料及模板回流。第一个纵向闭环是实施里程碑，不能作为整个 RFC 完成的替代。详细验收保留原 85 条编号，累计补充 27 条，总计 112 条目标用例。
