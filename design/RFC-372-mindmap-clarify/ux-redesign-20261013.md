# RFC-372 工作区 UX 重设计

> 2026-10-13，UX 修正与用户追加交互设计。原 v6 的单一问题、答案、草稿、确认及提交合同继续有效。节点方向、横排与弹窗的实现、独立功能检视和集中本地验收已完成；已在日常 AW 中以真实模型完成六题及最终文档，再固化为 System Mock E2E。发布及 hosted CI 独立记录，见 [真实验收](./real-aw-ux-acceptance-20261013.md)。

## 用户追加：同级横排、节点方向与问题弹窗

1. **同级横向、深入纵向。** 一个节点的直接子项使用同一层级的横排；每个子项为自身后代预留包围盒。不同分支的深度不影响兄弟的层级。大宽度保留可读比例，通过平移、搜索和小地图到达，不自动把所有文本缩成点。
2. **全景点击节点打开公共 Dialog。** 点击问题或分类后使用居中的大弹窗；问题全文仅出现一次。桌面提供充分阅读行宽，手机占满可用视口。弹窗使用原 Dialog 的焦点约束、Escape、关闭与焦点恢复。关闭仅改变呈现，保留答案、确认、节点指引、正在生成的请求、选中节点及画布相机。可在弹窗内确认、追问、取消生成或转到下一道待处理题；不能只能到被遮住的背景上取消。聚焦作答仍使用整页的问题区域，不强制逐题开弹窗。
3. **分类节点也可补充提问方向。** 比如选择“性能”，输入“还要考虑数据库性能，关注索引、慢查询与连接池”，使用该分类下现有问题及已答内容作为上下文，并要求只补充未覆盖的方向。追加题目直接归入选中分类，和已有服务性能问题并列，不能伪装成某道服务性能题的子问题。子分类维持完整路径；根节点允许全图补问，由模型提供每题的分类。
4. **具体问题继续深入。** 选中问题时沿用已有父题和祖先回答；新的问题仍是其直接子题。两类生成目标在弹窗标题、说明和请求中明确区分，不让用户推测。
5. **复用既有生成与追加链。** 原 `POST /api/clarify/:id/followup` 请求保持兼容，目标为 `parentQuestionId` 或 `categoryPath` 二选一。分类目标携带原分支问题/答案的依据；追加前在原事务及锁下复核，生成期间编辑该分类的答案或追加别的题时拒绝迟到结果。原幂等请求、取消、同轮单请求、已结束轮次及封存题规则继续适用，不增加表、独立会话或第二条续跑路径。
6. **可恢复状态。** 指引和错误按节点保存；已有回答及确认不因新题生成而清空。新题为未回答，分类与全图计数立即更新；成功给出可主动查看的入口，不打断用户正在填写的另一题。全部已封存且不可再答的分支不提供生成按钮。

增量验收：分类/根节点方向、同分类新题横排、子分类路径、普通父题兼容、保存后刷新、请求重复/迟到/取消/关闭轮次、弹窗打开关闭与相机/答案不变、移动端长选项/操作完整可达、生成中关闭和返回仍可取消。新增实际模型任务在用户日常 AW 中执行分类方向与弹窗，再以实际问答记录补入 System Mock；此前完成的真实任务及失败证据保留。

## 真实问题与原因

本机任务 `01M4SK0C3RQH0FPWSBQHER3FES` 使用日常实例、真实 OpenCode 模型生成问题。设计反问包含三个方向、五个问题和两层深入；跨 Agent 反问又产生三道带长说明的确认题。

1. 目录虽然收到深度优先的节点序列，但 `MindmapWorkspace` 把每项画成相同的按钮，没有深度、父子连线、逐行展开控件和分类/问题区分。分类、子分类及追问看起来全是同级。
2. 现有布局每深入一层固定横移 240、叶间仅 48；只有一条子链的父子共享纵坐标。真实五题会被拉成细长横线，再被初始适应全图缩到约 25%。长标题与碰撞剔除进一步使节点只剩点或省略号。
3. 现有全景常驻目录、画布、答题三栏；小于 1200px 时目录变成顶部 110px 横带。1113px 浏览器实测中，问题详情只有 280px，长选项变成几十行，按钮移到视野外。
4. 详情重复渲染完整标题；切换问题保留上一题的详情滚动位置。页面、目录、详情多重滚动导致用户看到新题的尾部，无法确定正在回答什么。
5. 本题状态、后代汇总、草稿保存、整轮提交未明确区分。全部现有题确认但仍生成追问时，文案仍表示可以提交；已提交的历史轮次也继续出现相同提示。

对应源码为 `MindmapWorkspace.tsx`、`mindmap.css`、`projection.ts`、`layout.ts`、`draw.ts` 与原 `clarify.detail.tsx`。数据中的父问题关系正确，主要缺陷在显示投影和空间分配，不能靠调整一点字号收口。

## 信息架构

同一页面提供“全景脑图”和“聚焦作答”。两者共用选中问题、原始题目、答案、确认及追问请求；切换只改变视图。

页面由紧凑任务上下文、单行工具区、主体、整轮操作区组成。任务标题仅出现一次，完整任务名可以换行；发起节点和轮次降为次要信息。原系统导航继续可达，工作区可收起目录扩大画布。

### 全景脑图

- 主体为可收起的目录与整块画布。未选题时不预留空白详情栏。
- 采用自上而下的脑图：主题 → 分类 → 子分类 → 问题 → 追问。各分支按实际卡片尺寸及后代包围盒分配空间，兄弟分支留出明确间隔。长单链向下延展，避免几个问题就拉成横向细线。
- 分类与问题使用不同结构：分类展示名称和“已确认 / 总题数”，问题展示题号、问题标题预览、本题状态；有追问的题目额外显示未完成的子题数量。选择高亮与回答状态分开，不能用绿色代替所有信息。
- 默认以可读尺度打开，保留全部结构；大图允许超出视口，提供小地图、搜索定位与显式“完整结构”概览。概览展示全体节点及状态，低倍率只保留分类和重点标签，不承诺在一屏内同时读完 5000 道题的全文。每个节点的完整内容始终可在问题面板读取。
- 普通点击选择节点并打开居中弹窗；不自动缩放，不因回答、确认或生成结果重新适应全图。拖拽平移、滚轮平移、Ctrl/⌘ + 滚轮缩放、键盘及触摸沿原合同打磨。保留显式全图概览，不增加“放大此分支”。
- 节点详情使用现有公共 Dialog 居中显示，桌面最大 860px、窄屏接近满屏；画布尺寸和相机不随弹窗开关重新布局。关闭或“返回脑图”回到原视口，也可在弹窗内切入聚焦作答。

### 聚焦作答

- 左侧为相同目录，主区域为完整问题；不再在中间重复绘制一列分支列表。
- 题目标题只显示一次，自然换行。题号、本题状态、所属分类、直接父问题在其上方明确呈现。深层祖先用可展开路径，不把一串完整问题名塞进固定高度的面包屑。
- 选项标题、说明和推荐理由保留可读行宽；正文不定高、不裁切、不靠悬停才能读取。自定义回答沿用原字段及长度约束。
- 本题操作区放“确认回答”和“下一个待处理”，追问作为同一区域的次要操作。确认后停留原题，用户主动进入下一题。已确认答案仍可修改，修改后就地明确显示“已修改，需重新确认”。
- 切换题目时只将问题正文滚到顶部。目录保持原位置，选中项不在可视区时才最小滚动定位；画布相机保持。
- 展开“继续追问”后显示可选指引和直接父问题。指引按题保存，避免切换题目后把另一题的追问内容带过来。生成期间显示所属分支、进行中状态和取消入口；可继续回答其他题。成功后给出“新增 N 题，查看”入口，不抢走正在填写的表单。

## 目录的真实层级

目录按 `categoryPath` 与 `parentQuestionId` 派生，不按数组索引或追加时间推测父子关系。真实示例：

```text
数据一致性                         已确认 3 / 3
└─ 并发冲突控制
   └─ Q2 并发抢订策略              本题已确认
      └─ Q4 网络超时后的幂等处理    本题已确认
         └─ Q5 幂等键冲突与有效期  本题已确认
```

上例短标题只用于说明层级；产品保存的问题全文不被替换。正式目录的标题可换行，未选中项允许两行预览，点击后在问题区展示全文；不得把标题截断当作完整问题展示。

- 分类行、问题行、追问行有明确区别；分类不显示题号，题目不是 checkbox。
- 展开箭头只控制展开；点击标题只控制选择，避免两个行为混在一个操作里。
- 折叠仅影响可见行。分类和父问题的汇总仍包含隐藏后代；搜索可命中隐藏题，定位时自动展开必要祖先。
- 搜索结果明确是结果列表，并给出所属路径；不把过滤后的孤立题伪装成同级树。
- 100 层深度不能靠无限缩进挤掉正文：目录对超长祖先路径折为明确的路径入口，展示真实深度、直接父问题与当前分支；展开路径可逐级跳转。该显示压缩不得改写父引用，全部问题仍可由目录和搜索访问。
- 继续复用 `VirtualList` 的动态测高。虚拟行保留真实层级语义和键盘展开/移动能力，选择变化不触发整个目录回顶。

## 状态与完成动作

| 事实                         | 用户看到的反馈                                      |
| ---------------------------- | --------------------------------------------------- |
| 本题无有效回答               | 未回答                                              |
| 本题有回答、确认依据不匹配   | 待确认；修改后提示需重新确认                        |
| 本题已确认但存在未完成子题   | 本题已确认，另标“子题 N 项待处理”；整个分支仍未完成 |
| 某分类所有问题及追问已确认   | 分类全绿，确认数等于总题数                          |
| 追问正在生成                 | 顶部和所属分支显示生成中；整轮提交不可用且解释原因  |
| 草稿正在保存或失败           | 沿原持久化反馈明确显示；不冒充已保存                |
| 所有当前题确认且没有在途追问 | 显示“本轮已确认，可提交”                            |
| 原提交已完成                 | 显示“本轮已提交”，只读查看；不再提示可以提交        |

审阅在回答与确认过程中完成；不增加审阅清单或交付页面。整轮底栏沿用原“提交并继续反问 / 提交并停止反问”，保留 cross 的持久停止语义及必要确认说明。最终文档仍进入原任务输出。

## 响应式与大图

以工作区实际可用宽度决定布局，不再单看浏览器是否超过 1200px。桌面目录建议 260–300px；问题正文优先获得约 560–860px 可读宽度；窄屏用“目录 / 脑图 / 问题”切换同一个工作区内容。

320px、390px、1024px 和 1440px 均不得出现页面横向溢出、标题/选项被固定高度裁断、操作按钮不可达。触摸操作不依赖 hover。画布允许有意的空间平移，正文只纵向滚动。选中题发生变化时按阅读起点定位；主题、搜索结果、错误提示和长无空格字符串均在容器内换行。

5000 节点、300 同级、100 深度仍通过轻量投影、Worker 布局、视口绘制及虚拟目录处理；不把所有完整问卷挂到 DOM。布局与状态分开：回答/确认只重绘状态，不触发布局或相机变化。

## 实施边界与顺序

范围仍是 RFC-372 已有工作区，不增加业务表、设计 session、覆盖台账、第二条任务续跑链或新的交付体系。优先复用原公共控件与样式、QuestionForm、VirtualList、草稿 controller 和原提交 mutation。显示改动落在 frontend 的 clarify 层；分类目标仅扩展 shared 原合同与 collaboration 原 followup 操作/存储适配器。实际模型记录进入现有 system-mocks 的模型边界回放。

1. 用真实长标题、两层追问、未回答/待确认/已确认混合状态形成可操作原型，完成设计复核。
2. 落实目录投影/层级语义、纵向布局、两视图布局和问题面板，以及保存/生成/历史状态。
3. 一次写完相应纯函数、组件、长内容/多尺寸、真实旅程 System Mock 测试，再集中验证。
4. 在同一日常 AW 的真实任务中检查更新后的历史问题与最终输出；必要的新问答仅走真实模型。System Mock 只作为随后确定性的回归证据。
5. 精确路径提交，跟踪对应 SHA 的 CI。并发会话的错误只保留证据。

## 验收重点

- 原始实际数据中的 Q2 → Q4 → Q5 在目录与脑图中父子完全一致。
- 长标题、200 字以上选项、推荐理由和自定义答案能完整阅读；没有标题重复。
- 在详情尾部切换到另一题，显示新题顶部，目录与画布不跳回初始位置。
- 展开/折叠、搜索隐藏题、切换两视图、刷新后答案和确认事实一致。
- 本题确认和分支完成区别清晰；正在生成与已提交状态不误报可提交。
- 真实模型任务生成最终文档、Task 为 done；固定回放涵盖实际答案、两层追问、一次非法回复后的重试和最终文档。
- 页面尺寸、深色/浅色、键盘/触摸、5000 节点压力按原 L13/L14 覆盖；原普通反问不变。
