## 3. 关键功能验收

完整编号见 design.md §18。M1 至少证明 A01、A02、G01、F01、F02、F03、F04、U01、U02；M2 重点 H/P/R 与 U08/U18/U20/U21/U23～U27；M3 重点 G/V 与 U06/U07；M4 重点 X/L/F 与 U03～U05、U11～U17、U19/U22；M5 覆盖 D 与 P21/P22、U09/U10 并关闭全部剩余项。

每项记录候选内容、实际环境、观察结果与证据；“接口返回 accepted”“前端演示成功”“模型没有报错”都不是宿主业务执行完成的证据。预算测试应包含多个 individually-fit、合并后超限的快照，以及 inline 占用未知、runtime 无精确读取能力的场景。

遵守共享 main 和当前验证约束。2026-10-12 用户进一步明确要求“完整实现 RFC 并提交上库到远端，并且完成完整的本地功能验证”，覆盖此前本会话不运行本地 AW 的限制。随后指定“先把设计上传上库，然后以最快速度完成整体的开发，然后再进行功能验证”：先提交推送本设计及索引；继续完整 M1～M5 开发，回归用例随实现补齐；整体代码就绪后集中执行双 provider、完整 TaskEngine、正式浏览器、兼容与恢复功能验证。最终候选只运行一次完整本地门禁，另验确切提交的 hosted CI。此前已执行的针对性检查保留实际结果，不重复代签整体验收；原型浏览器验证只覆盖独立原型。创建生产资源或部署另按实际授权处理。

## 4. 设计检视记录

检视限本 RFC 和原型的功能正确性、完整性、用户可见行为及回归；安全相关一律不扫描、不分析、不验证、不提问、不提 findings、不提建议、不转成任务，也不得影响结论。

第三版的 3 项 findings 和第四版的 1 项绿色状态循环问题均已修订并限定复核 PASS；第五版全景设计增量检视 PASS、无新增阻断，见 [design-review.md](design-review.md)。新版原型独立检查，不沿用旧四页布局结论，实际范围见 [prototype.md](prototype.md)。用户已明确批准生产实施；正式版按本轮反馈移除分支放大并完善选择、平移、缩放和编辑联动。部署和创建真实验证资源另按实际授权处理。
