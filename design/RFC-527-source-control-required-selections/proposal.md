## 1. 背景

source-control 的组合层在调用方没给时自己造本机实现：

- **一直由回落造、生产路径在用的**：单机部署的候选交付与冲突合并（部署选择是 `null`，daemon 的数字员工与开发自动化装配把它转回
  `undefined` 再交入，绑定按请求造本机 effect）；单机部署的仓库镜像与手动刷新（HTTP 装配把 `null` 的远端转成不给）；单机维护 worker 的仓库
  准备、草稿区与工作区维护文件系统（worker 效果为 `null`）；单机部署的工作区排除档案本身就是经“不给就造本机的”选择助手造出来的。
- **只服务用例的**：员工案例工作区、隔离工作区、仓库 git 工作区、工作区读取与上传内容的选择（daemon 都给）；选择助手里只为用例存在的
  `legacyRunGit` 与按请求的 `runGit`；没有工作区作用域时的提交预览索引（生产没有读提交预览的调用方）。
- **不是回落的**：仓库提交绑定在作用域没有托管提交操作时跑进程内的提交用例——这是模块自己的主路径，托管作用域只是把同一用例放进卷里执行。

S12 第 1 项点名的“装配处把可空选择项转回 `undefined` 的写法”还剩六处：数字员工与开发自动化装配里候选与冲突合并的四处（随本模块的
回落一起），daemon 应用装配里托管的输入文件留存与任务恢复两处（消费方把“没给”当作“没有这项能力”，不造本机实现）。

## 2. 目标

- **G1 必填注入**：上述回落改为调用方给出，只为回落存在的选项与参数一并删去；选择助手（source-control 的 public 合同）保留名字，选择必填、
  只做核对（排除档案的选择没有生产调用方，删去）。
- **G2 装配处显式构造**：单机部署的候选交付与冲突合并的部署选择改为本机实现（不再是 `null`），daemon 删去这四处 `null` → `undefined` 的转换（输入文件留存、任务恢复与 HTTP 装配的
  CrewStation 事件入口的消费方改取可空值、显式判 `null`，删去另三处）；
  仓库镜像由 bootstrap 按远端是否为 `null` 显式选本机或托管一支；维护 worker 在单机时显式给出本机的准备、草稿区与维护文件系统。同一组工厂、
  同一组参数、同样的构造时机。
- **G3 门与用例**：RFC-521 门删去全部适配器回落登记，进程内提交用例的三处按 `option` 登记（design §6），适配器回落 19 → 0、`SUCCESSORS`
  清空；用例经测试助手显式给出与此前缺省相同的对象。

## 3. 非目标

- 单机选择整体收进 `bootstrap/standalone.ts`（与维护 worker 的单机效果一并另立后继）；S12 的第 3～6 项；任何行为、接口与界面变化。

## 4. 用户可见变化

无。

## 5. 验收标准

- **AC-1**：这些回落不再存在；RFC-521 门的实测与登记逐条相等，适配器回落 0 条、`SUCCESSORS` 为空；bootstrap 不再把部署选择的 `null` 转回
  `undefined`。
- **AC-2**：daemon、维护 worker 与单机部署得到的对象与此前相同（同一组工厂、同一组参数、同样的构造时机）；单机的候选推送照旧带本机夹具会话；
  用例显式给出的选择与此前缺省相同。
- **AC-3**：bootstrap 不深取 source-control 的 infrastructure；public surface 不升；计数不升（降的收紧到实测）。
- **AC-4**：受影响用例全部通过；推送后 exact SHA 的 GitHub Actions 全绿（环境性红格逐格归因、如实记录）。
