## 1. 背景

MCP 的连通性探测（`POST /api/mcps/:id/probe`）在单机部署里于进程内连上 MCP 服务器、列出工具等；探测的开始时间与 MCP 配置写入的因果时间
戳共用一个时钟（`mcpProbeNow()`），让“探测结果是否反映当前配置”的判断落在同一条时间线上。探测的选项与时钟挂在一个进程级的测试接缝上
（`resource-catalog/composition/mcpProbeOperations.ts` 的模块级 `probeOptionsOverride`，由 `__setMcpProbeOptionsForTesting` 写）：用例借它换掉
客户端工厂与时钟，生产里它恒为空。同一进程里的两份应用共用这一份接缝。架构报告的模块级可变单例清单里这一文件 1 条（全仓 56 条）。

## 2. 目标

- **G1 每份应用一个探测环境**：组合根为每份应用建一份 MCP 探测环境（探测选项与探测 / 写入共用的时钟），交给进程内探测执行器、探测用例与
  MCP 写入时钟；生产里没有选项，客户端与时钟取默认。
- **G2 测试接缝随应用走**：用例把选项经应用的测试接缝交进去，不再写进程级状态；两份应用的选项互不可见。
- **G3 门与用例**：新增 RFC-538 用例（运行时文件没有模块级状态与测试接缝函数；组合根只建一份环境并交给三处；两份环境各用各的选项与时钟；
  带负对照）；读旧形状的用例与锁随改；模块级可变单例清单 56 → 55。

## 3. 非目标

- 其余 55 条模块级可变单例（见 RFC-537 收口时的三类）。
- 探测本身（连接、超时、结果的持久化与新鲜度判断）、托管部署的探测执行器与 MCP 写入的因果时间戳算法不变。

## 4. 用户可见变化

无。

## 5. 验收标准

- **AC-1**：`mcpProbeOperations.ts` 没有模块级状态与测试接缝函数；组合根为每份应用建一份探测环境，进程内探测、探测用例与 MCP 写入时钟用
  同一份。
- **AC-2**：探测与写入的结局不变（生产取默认客户端与 `Date.now`）；两份环境各用各的选项与时钟，选项在每次探测时读取。
- **AC-3**：模块级可变单例清单 56 → 55，计数不升；钉住旧形状的锁随改，新增 RFC-538 用例并登记 guard-manifest。
- **AC-4**：受影响用例全部通过；推送后 exact SHA 的 GitHub Actions 全绿（环境性红格逐格归因、如实记录）。
