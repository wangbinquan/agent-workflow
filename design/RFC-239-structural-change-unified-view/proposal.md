# RFC-239 · 「结构变更」统一视图:合并文本 diff 与结构页签的叙事式变更呈现

- 状态:Draft(待用户批准)
- 前置:RFC-021(工作目录 diff)、RFC-083/085/086/087/088/089(结构化 diff 系列)、RFC-091(diff 文件夹树)、RFC-010(markdown 渲染 diff)、RFC-236/237(系统 agent 基建)
- 触发:2026-07-30 用户「任务详情界面的结构页签……变更的呈现方式还是没法让人直观看到代码结构的变更情况,你需要调研下当前实现与业界优秀实践,优化下这个整体功能」

## 1. 背景与问题

任务详情「产物」下现有两个平行子页签:「工作目录 diff」(RFC-021,unified 文本 diff + 文件树 + 已看进度)与「结构」(RFC-083 系列,符号级结构 diff:摘要卡 + 风险导览 + 树/关系图/影响面/依赖/调用链 5 选 1 视图)。数据层已经相当丰富(8 语言 tree-sitter 符号 diff、类关系边、影响面、调用链、SCIP 深度模式、三粒度),但用户实际使用中仍「没法直观看到代码结构的变更情况」。

### 1.1 实测诊断(2026-07-30,本机真实任务)

1. **平台典型场景令「diff 审查式」设计失效**。agent 任务的主流产出是「从零生成大片代码」或「大规模重构」(实测 snake 任务:18 文件/28 类/213 方法**全部 added**)。此时:风险分级全 safe → 「破坏性」摘要卡与导览卡(walkthrough 只取 breaking/risky)整体消失;每行灰字人话解释退化为同义反复(`+ class SnakeGame` 旁写「新增 class SnakeGame」,满屏皆是);import 变更与类/方法平铺,且容器分组按字典序把 `java.awt`/`javax.swing` 等 import 组排在真正的类之前——首屏一半是 import 噪音。
2. **没有任何一处能「一眼看全局」**。摘要只是几个文字 pill(无比例/热区);左栏文件树只有文件名,无变更计数与风险线索,无法判断先看哪个文件;右栏一次只呈现一个文件;树/图/影响面/依赖/调用链 5 个视图互斥,不能并置。
3. **关系图没有赚到它的位置**。包级图边无差别、交叉如麻;类级图 28 类即毛线团(整屏长卡片 + 横穿画布的边);它画的是「改动类的关系现状」而非「结构变了什么」。
4. **结构页签没有评审闭环**。文本 diff 有「已看 N/M + 勾选折叠」;结构页签没有任何进度机制;两页签间互跳单向且丢行号(只选中文件,不定位 hunk)。
5. **一批 as-built 缺陷**:文件重命名呈现为「全新增」(变更文件枚举无 rename 检测);`onJumpToHunk` 丢弃行号;文本 → 结构反向互跳缺失;影响面列表纯文本不可点;scratch 任务空态无解释(实测:一个完成的重构任务显示「本次改动无可识别的结构变化」,无任何原因提示);多仓在前端锁死 task 粒度(后端已支持 node 粒度多仓)。

### 1.2 业界调研结论(摘要)

调研 GitHub 新版 Files Changed、SemanticDiff、difftastic、CodeRabbit(Walkthrough/Overview/Atlas)、Greptile、CodeSee(停运教训)、AppMap、JetBrains/VS Code、CodeScene、Google Critique/Gerrit、GumTree 与变更解缠学术线,收敛 8 条原则(全文见本目录 `research-notes.md` §二):

- **P1 叙事先行**:首屏回答「改了什么、按什么顺序看」;面板堆叠不产生直观,顺序才产生直观。
- **P2 意图/模块分组**:把 N 文件 × M 符号重组为少数几个组,机械性变更整组折叠。
- **P3 先降噪**:import/纯搬移/纯重命名聚合成一行计数,「已隐藏 N 处」保持可展开的信任契约。
- **P4 结构锚点内嵌 diff**:sticky 符号头、符号级徽标叠加在 diff 上;结构信息的终局是 diff 的增强层,不是平行页签。
- **P5 图必须 gated**:常驻依赖图被 CodeSee 停运证伪;图作为按需下钻。
- **P6 风险要有证据**;**P7 注意力与进度是呈现的一部分**;**P8 多轮修复评审 delta 的 delta**(P6 部分体现、P8 本 RFC 不做,见非目标)。

## 2. 目标

**一句话**:把「工作目录 diff」+「结构」合并为单一「**结构变更**」子页签——左栏常驻「分组总览」(模块/性质分组 + 权重 + 风险 + 已看进度),右栏是「结构注解过的 diff 主体」(符号概要 + sticky 锚点 + 精确互跳),非代码产物(markdown 文档/配置等)一并纳入分组呈现,关系图/影响面/调用链/依赖降为按需下钻,并提供「手动触发 + 落盘缓存」的 AI 变更导读。

分解为可验收的 G1–G8:

- **G1 页签合并**:「产物」下子页签由 输出/工作目录/工作目录 diff/结构 4 个变为 输出/工作目录/**结构变更** 3 个。旧 URL tab 值(`worktree-diff`/`worktree-structure`)重定向到新页签,深链不断。
- **G2 双栏信息架构**:左栏常驻分组总览(第一层 = 变更分组,第二层 = 文件;组头带一句话描述位、权重条、符号/行计数、severity 点、组内已看进度),右栏为选中文件的详情(符号概要区 + diff 区)。文件的「已看」勾选、总进度条、键盘导航(↑↓/Home/End/Space)自 RFC-021/091 迁移保留。
- **G3 非代码产物一等呈现**:markdown/配置/资源等非代码文件按性质分组进入左栏(文档/配置/依赖/其他),右栏 diff 正常呈现;markdown 文件提供「渲染视图」(复用 RFC-010 能力)与文本 diff 切换。
- **G4 结构内嵌 diff**:右栏文件详情 = ①文件级符号变更概要(嵌套折叠树:类 → 成员;import 聚合一行;全 added 文件默认折叠到容器级)+ ②unified diff(hunk 归属的符号以 sticky 行/沟槽标注)。符号行 ↔ hunk 双向精确定位(带行号,不再只选文件)。
- **G5 降噪**:import 变更聚合;`added+safe` 不再逐行输出同义反复解释;纯 rename/move(体未变)聚合呈现;所有聚合行可展开,并显示被聚合数量。
- **G6 图与深视图降为下钻**:关系图/影响面/调用链/依赖变更从「5 选 1 平级视图」改为右栏工具条上的按需入口(全宽覆盖层);关系图新增「聚焦当前选中组/文件」能力(喂过滤后的文件集,缓解毛线团);影响面列表可点击(跳转对应符号/diff)。
- **G7 AI 变更导读(手动 + 缓存)**:页面提供「生成 AI 导读」按钮,任务成员可触发;后台经系统 agent 基建(`runSystemAgent`)生成 `{总述, 每组一句话, 推荐阅读顺序}`,落盘缓存,此后所有访问者直接读缓存,可重新生成。静态呈现不依赖 AI:未生成时组头显示确定性模板句。
- **G8 as-built 缺陷修复**:rename 检测统一(结构侧变更枚举加 `--find-renames`,与 `renamedFrom` 呈现打通);跳转带行号;空态诊断化(scratch/无 base/GC/真无变更各给原因与去处);多仓放开 node 粒度(前端);范围(task/node)与引擎(基线/深度)选择器保留。

## 3. 非目标(v1 明确不做)

- **patchset 式多轮 delta**(「相对上一轮已评审版本的增量」):本平台 retry 产生独立 node_runs,「范围=各节点」已部分覆盖;完整 patchset 语义(评审基线记录、轮间 diff)独立成后续 RFC。
- **关系图的 before/after delta 可视化重做**(图仍呈现「改动类 + 关系现状」,本 RFC 只加聚焦过滤与入口降级)。
- **AI 自动触发**(任务终态自动生成导读):已决策手动 + 缓存;不加 settings 开关。
- **评论/标注体系**(协作页签已有反问/评审通道,不在 diff 内做行级评论)。
- **CodeScene 式历史耦合/热区证据**(需要跨任务 git 历史聚合,数据面不在本 RFC)。
- **文本 diff 折叠未变更区域/word-wrap 等 diff 渲染器本体增强**(保持 `DiffFileBody` 现状,只在其外围加符号锚点)。
- 不改 opencode 运行时、agent 输出协议、结构 diff 引擎的语言/精度能力(tree-sitter/SCIP 现状不动)。

## 4. 用户故事

- **US-1(看全局)**:作为任务发起人,任务完成后打开「结构变更」,3 秒内知道:改动集中在哪几个模块、规模多大、有没有破坏性风险、文档/配置动没动;不需要逐文件点开。
- **US-2(从零生成)**:agent 从零写了一个 18 文件的项目。我在左栏看到按包分组的 6 个组(各带「N 类 M 方法」与权重条),点开 `ui` 组 → 选 `Renderer.java` → 右栏先看到「class Renderer:+14 方法 +8 字段(import +12 已聚合)」的概要树,点 `render()` → diff 滚动到该方法定义处。
- **US-3(重构评审)**:agent 把 `sources/` 目录重组。左栏「搬移」聚合显示「12 个文件重命名/移动,其中 3 个有内容修改」;重命名文件不再呈现为「删除 + 全新增」,概要区显示 `原 src/a.ts → src/core/a.ts` 与真实的符号级修改。
- **US-4(文档产出)**:agent 产出了 `docs/*.md` 与 `README.md` 修改。左栏「文档」组显示 2 文件 +180 行;点开后右栏默认渲染视图(标红/标绿的富文本),可切回文本 diff。
- **US-5(AI 导读)**:我点「生成 AI 导读」,约十几秒后页面顶部出现两三句总述,每个组头出现一句人话(「Swing 绘制层:窗口、菜单与画布渲染」),并给出推荐阅读顺序;我关掉页面再进来,导读仍在(缓存);同事打开同一任务直接看到,无需再生成。
- **US-6(深下钻)**:我怀疑 `GameSettings` 改动影响面大,在右栏工具条点「影响面」,覆盖层列出调用方,点击某调用方跳到对应文件的 diff 位置;点「关系图」并勾选「聚焦当前组」,只看 `config` 组相关的类关系。
- **US-7(空态可解释)**:一个 scratch 空间任务没有 git 可识别变更,页面明确说明原因并指路「输出」「工作目录」页签,而不是干巴巴一句「无结构变化」。
- **US-8(键盘评审)**:我用 ↑↓ 在文件间移动、Space 标已看,组头显示组内进度,顶栏显示总进度——与旧「工作目录 diff」页签的肌肉记忆一致。

## 5. 验收标准(AC)

- AC-1:任务详情「产物」组仅含 3 个子页签;`?tab=worktree-diff` 与 `?tab=worktree-structure` 均落到「结构变更」页签且不报错;既有 e2e/单测中对旧 tab 的引用全部迁移。
- AC-2:左栏第一层为分组(代码按顶层模块/包;非代码按 文档/配置/依赖/其他;纯搬移聚合组),组头含:名称、文件数、符号或行计数、severity 点(存在 breaking/risky 时)、权重条、已看进度;第二层文件行含 basename、变更计数、已看勾选。多仓任务第一层先按仓分组。
- AC-3:右栏概要树:嵌套(容器 → 成员)、import 聚合一行且标注数量、全 added 文件默认折叠到容器级、`added+safe` 符号行不渲染解释句;概要行点击 → diff 滚动到对应 hunk 首行并高亮;diff hunk 沟槽/sticky 显示所属符号名,点击 → 概要树对应行高亮。
- AC-4:重命名文件(git 判定 R,含 rename+edit)在概要区显示 `renamedFrom`,其符号变更基于旧新内容真实 diff(而非全 added/全 removed 两份);纯 rename(相似度 100%)进「搬移」聚合。
- AC-5:markdown 文件详情默认渲染视图、可切文本;渲染视图正确标注增删(复用 RFC-010 组件契约)。
- AC-6:图/影响面/调用链/依赖 4 个下钻入口按数据可用性显示;影响面条目可点击且跳转正确;关系图「聚焦选中组/文件」时只渲染该子集的卡片与边。
- AC-7:AI 导读:未生成 → 按钮态;生成中 → 进度态(可离开页面,回来恢复);成功 → 总述 + 组句回填 + 阅读顺序,落盘后二次进入直接呈现;失败 → 错误态 + 可重试;非任务成员不可触发(403),但可读已生成缓存。生成请求幂等(同任务并发触发只跑一个)。
- AC-8:空态矩阵各给差异化文案:无 base commit(409)/worktree 缺失且无落盘(410)/scratch 任务无 git 变更/GC 后 node 快照被裁/readonly 节点/真无变更。
- AC-9:范围选择器在多仓任务放开「各节点」选项(后端既有能力);单仓行为与现状一致。
- AC-10:`bun run typecheck && lint && test && format:check` 全绿;所有新纯函数(分组、join、hunk↔符号映射、聚合)有单测;所有被有意变更的旧锁定测试逐条更新并注明 RFC-239 意图,不删除。
