## 1. 背景

两个模块的组合层在调用方没给时自己造本机实现：

- **system-operations**：本机系统运维（`backup` / `restore` 命令）的数据库配置与 provider 运行期、daemon 启动时的数据库准备、daemon 宿主生命周期
  与运行期查询、数据库迁移模块与手动迁移的配置、演示种子的完成标记、打开前恢复。其中 `backup` / `restore` 的数据库配置、CLI 迁移的配置与种子
  标记在生产路径上一直由回落造；daemon 把部署选择里表示“单机”的 `null` 转回 `undefined` 再交给回落（RFC-294 S12 第 1 项点名的写法）；打开前恢
  复的组合层入口已经没有生产调用方。
- **development-automation**：开发自动化、平台工作项与任务输入上传的证据库，开发自动化的准入查询、需求物化器的文档写入器与暂存，开发交付里不给
  暂存时的旧版流水线证据桥。daemon 都显式给出，这些回落只服务用例；旧版流水线证据桥连一个使用方都没有了。

这些回落让依赖藏在组合层里：哪一份是生产对象、哪一份只是给用例的方便，从调用处看不出来。

## 2. 目标

- **G1 必填注入**：上述 16 处改为调用方给出，只为回落存在的选项一并删去。daemon 的数据库准备改为调用方按部署选择显式选“托管安装”或“本机文
  件”一支；没有生产调用方的入口（组合层的打开前恢复、两个 `select*` 助手、旧版流水线证据桥与任务输入上传的懒建证据库）删去，用例要用的原样移进
  测试助手。
- **G2 装配处显式构造**：bootstrap 在原来回落发生的位置显式给出同样的对象（同一组工厂、同一组参数、同样的读取时机）；单机选择经组合层交出，
  bootstrap 不深取模块的 infrastructure。
- **G3 门与用例**：RFC-521 门删去 16 条登记，适配器回落 67 → 51；用例经测试助手显式给出与此前缺省相同的对象。

## 3. 非目标

- 单机选择整体收进 `bootstrap/standalone.ts`（与维护 worker 的单机效果一并另立后继，见 design §8）；两个模块 infrastructure 里的 `select*`
  助手；其余模块的回落；任何行为、接口与界面变化。

## 4. 用户可见变化

无。

## 5. 验收标准

- **AC-1**：这 16 处回落不再存在；对应选项必填、只为回落存在的选项与入口删去；RFC-521 门的实测与登记逐条相等，适配器回落 51 条。
- **AC-2**：daemon、CLI 命令与维护入口得到的对象与此前相同（同一组工厂、同一组参数，配置在同样的时机读取）；用例显式给出的选择与此前缺省相
  同。
- **AC-3**：bootstrap 不深取两个模块的 infrastructure；public surface 不升；计数不升（降的收紧到实测）。
- **AC-4**：受影响用例全部通过；推送后 exact SHA 的 GitHub Actions 全绿（环境性红格逐格归因、如实记录）。
