## 2. PR 拆分建议

**两个 PR**（CLAUDE.md §RFC workflow 第 5 条允许说明后拆分）：

- **PR-A `feat(review): RFC-326 锚点解析 + 决策事务化 + REST 打包`**：T1–T12。它自身闭合（REST 面已可用、网页无回归），先推让 CI 在干净 checkout 上验证事务重构的等价性，再叠 MCP 与前端。推前自查三条曾被设计门点名的守卫：`lifecycle-grep-guard`、`rfc317-architecture-ledgers`（manifest 两向）、`scheduler-audit-s10`。
- **PR-B `feat(review): RFC-326 MCP 门工具 + 网页偏移高亮 + e2e`**：T13–T22。

两个 PR 都在 `main` 上直接推（本仓不建分支），各自按 exact SHA 盯 CI 到绿；`packages/shared` 有改动，**三个包各自单跑**（`bun run test:shared` / 相关 backend 文件 / `test:frontend` anchor 与 rehype 用例），别只跑 backend。
