## 1. 背景

provider 构造数据库时做两件按句柄的绑定，各记在一张进程级的侧表里：

- **行规则错误翻译**（`platform/persistence/schema/rowRules.ts`）：`bindSchemaRowRuleErrors(handle, codes)` 给原生会话的执行方法套一层，把触发器抛出
  的行规则错误翻成领域错误；为了不套两次，已套过的会话记在模块级 `WeakSet`（`boundSessions`）里。
- **单行写入**（`platform/persistence/singleInsert.ts`）：PostgreSQL 客户端用 `bindSingleInsert(db, insert)` 给它的根库登记带代际围栏的单行
  INSERT，记在模块级 `WeakMap`（`inserts`）里；`insertOne(db, …)` 按库对象取（事务等派生句柄取不到，走普通写入）。

两张表都按对象记，但放在模块级，进程里所有库共用一份登记处。架构报告的模块级可变单例清单里这两个文件各 1 条（全仓 50 条）。

## 2. 目标

- **G1 侧表归句柄**：已套行规则翻译的标记记在会话对象自己身上；带围栏的单行写入记在根库对象自己身上——两张模块级表删去。
- **G2 结局不变**：行规则错误照旧翻成领域错误、同一会话不会套两次、事务照旧在进入时套上；单行写入照旧只在根库对象本身上走围栏，派生
  句柄与包着根库的代理照旧走普通写入。
- **G3 门与用例**：新增 RFC-542 用例（两个文件没有模块级状态；两个库各记各的；派生句柄与包着根库的代理取不到根库的单行写入；同一会话只套一次；带负对照）；
  模块级可变单例清单 50 → 48。

## 3. 非目标

- 其余 48 条模块级可变单例（平台持久化的 schema 选择与历史运行时、句柄上下文自身的登记表、日志器配置等另立或待定）。
- 行规则的定义、翻译出的错误与围栏 INSERT 的 SQL 不变。

## 4. 用户可见变化

无。

## 5. 验收标准

- **AC-1**：`rowRules.ts` 与 `singleInsert.ts` 没有模块级集合；标记与单行写入记在各自的对象上。
- **AC-2**：行规则翻译与单行写入的结局不变（只套一次、事务照套；围栏只在根库对象本身、派生句柄与包着根库的代理走普通写入）。
- **AC-3**：模块级可变单例清单 50 → 48，计数不升；新增 RFC-542 用例并登记 guard-manifest。
- **AC-4**：受影响用例全部通过；推送后 exact SHA 的 GitHub Actions 全绿（环境性红格逐格归因、如实记录）。
