## 合同核实

- `workgroup_messages.trigger_message_id` 是 nullable self-FK，删除 parent 时 `SET NULL`，删除
  task 时整组 cascade；旧行保持 null，不猜测回填。
- fresh 与 adopted message-turn 都从同一持久 shard max 解析直接父级；human→agent 与
  agent→agent 共用 resolver，self-mention 与 max 之后的消息被排除。
- 同一 message-turn 的合法 `wg_messages` 与 `wg_result` 全部继承同一 parent；leader、
  assignment、system、dropped note 等非唯一父级路径显式写 null。
- room 只从当前已授权 payload 的 message map 解析 preview；坏指针不追加查询。引用只展示一层。
- `triggerMessageId` 不被 prompt renderer 消费；null / non-null fixture 的 prompt bytes 相同。
- 前端引用是语义 button；显示作者与两行正文，可鼠标或键盘跳转、聚焦、静态高亮，并尊重
  reduced-motion。390px 下引用和消息都没有水平溢出。

### 全后端随机化套件说明

全后端随机化套件在并行 RFC-230 工作树持续变化期间跑了两轮，均只出现一个、且彼此不同的
非 RFC-229 单例失败：

- seed `575337941`：7374 pass / 25 skip / 1 fail；失败的 `scheduler.test.ts` 按同 seed
  单文件复跑 **20 pass / 0 fail**；
- seed `3736731964`：7383 pass / 25 skip / 1 fail；失败的
  `rfc097-task-status-cas.test.ts` 按同 seed 单文件复跑 **36 pass / 0 fail**。

因此不把“完整 backend suite 全绿”列为本实现证据；RFC-229 定向集、两处原 seed 隔离复跑及
其余门禁均为绿。未运行远端 CI。
