# RFC-602：模块查询按需读取与完整子任务分页

- 状态：In Progress。
- 范围授权：用户 2026-11-25 明确要求优化历史全表读取、资源摘要逐页查找、仓库组整图快照和子任务固定 500 条限制，补齐功能、性能、边界用例，完成验证后提交。本 RFC 记录该已授权范围的实施设计。
- 总纲：遵循 [RFC-294](../RFC-294-backend-layered-target-architecture/proposal.md) 的 owner、查询下推、单份业务语义和 provider 边缘差异。

## 1. 问题与目标

上一轮模块合同审视已确认四个限制。历史查询每次解码单表完整归档；精确资源摘要通过 500 条列表逐页查找；仓库组单组用例也读取全部组、节点和辅助表；任务详情只获取前 500 个子任务，后续子任务可能被误判为不可达。

本 RFC 将读取成本与所需页面、对象或相关子图关联，同时保持现有完整结果和失败语义。历史采用持久派生查询投影，原归档仍为不可变事实源；资源使用精确主键读取；仓库组按用例读取可达范围；子任务增加窄分页合同，前端完整消费游标后发布结果。

## 2. 验收

- AC-1：历史索引构建完成后，重新创建 reader 的冷请求也不读取完整归档；四类查询与 record 点读保持完整 DTO、排序、游标和错误语义。升级/初始化自动构建、失败不发布半份结果、可重试。
- AC-2：六类精确资源摘要命中/缺失均一次有界 SELECT，结果与现有目录投影一致，不受目标在排序中的位置影响。
- AC-3：仓库组 layout/get/preview/launch 不加载无关图与辅助表；currentGroup 只读一行；更新祖先及兄弟冲突、全局 OCC、强制删除及完整列表语义保留。
- AC-4：子任务超过 500 条仍能完整获取并正确导航；请求逐页有界、同父共享、支持取消/重试/刷新；中途失败或未完成不会成为子任务不存在的证据。
- AC-5：所有实现与用例写完后集中验证，涵盖 SQLite/PostgreSQL、真实前端 hook/组件、功能/性能/边界/失败；相关回归、类型/格式及 exact-SHA CI 通过后交付。

## 3. 范围边界

不恢复旧 code-round writer，不修改历史归档字节或冻结 epoch-1 材料，不截断原本要求完整的 delivery correlation、stage、仓库组列表结果。完整输出的成本允许随实际输出量增长。历史首次构建必须扫描旧包，但正常查询不得回退整包扫描。查询预算不是生产吞吐或 P95/P99 SLA。
