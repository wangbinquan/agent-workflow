## 设计门

首轮功能设计复核提出三项：刷新期旧子任务数组不能作缺失证据；find 保留旧 ID 索引缺项诊断；强制重建必须有可调用生产入口。设计已分别补充 isFetching 消费者规则、独立 record 事实索引与 `db rebuild-code-history-index` 接线，独立功能闭环复核 PASS。用户当前明确指令已授权四项优化的实现、验证与提交；不扩张到独立能力变更。

## 验证证据

T1–T5 生产实现与全部用例完成后才开始集中功能验证。首轮后端 51 文件执行 667 条（646 通过、21 失败），逐项归因修复后按受影响范围用新进程复验，未重跑全部 51 文件。前端 5 文件有效结果合计 96 条通过；前后端完整类型检查、当前任务范围 ESLint/异步规则/Prettier、依赖边界与 schema-history 检查通过。定向复验已完成：22 文件 334 条中唯一剩余的 PostgreSQL 统计信息用例补 ANALYZE 后，子任务全文件 27 条通过。新增 CLI receipt 的精确导出清单同步后，入口守卫 17 条通过；RFC-294 只执行相关的跨模块依赖和 public surface 两项合同检查，均通过。

升级资产已生成：epoch-2 的 0003–0012 十条单表 add-table edge，每版包含 contract、SQLite plan、PostgreSQL plan，以及分别在真实 PostgreSQL 15/16/17/18 生成的 catalog，共 70 个新增资产。0000–0002 原有资产未修改；此处记录生成结果，不替代升级行为验证。

## 最终本地证据

将每个文件最近一次有效执行与未受影响的首轮结果合并，排除并发 RFC-603 的无关测试文件：后端相关验证共 57 个文件、718 条通过；其中 RFC-294 仅计实际选择的两项合同检查，不代表该文件全部执行。前端 5 个文件、96 条通过。修复范围重跑，未重启完整本地 gate。

独立功能实现门最终均 PASS。历史门发现并关闭三项：SQLite 异步发布必须使用统一 transaction；metrics 小数/极大窗口按整数时间域保持原语义；派生记录须按 frozen 列集合与 migration key 核对身份。对应双库及真实 HTTP 回归全部通过。

静态检查为 backend/frontend 完整 tsc、任务范围 ESLint/异步规则/Prettier、依赖规则与 schema-history。首次宽范围 lint/typecheck 读到了并发 RFC-603 未完成内容；未修改对方文件，后续完整类型检查通过，任务范围 lint 通过。提交只包含本 RFC 路径，精确 SHA 的服务端 CI 另行跟踪并在会话交接记录。

性能结果是查询次数、实际取回行数、参数与索引计划、HTTP 页数和取消/发布时机的确定性预算，不是生产 P95/P99 压测。PG15/16/17/18 均生成真实 catalog；行为验证使用 SQLite 与 PG17，不能描述成四个 PG major 的全量行为验收。
