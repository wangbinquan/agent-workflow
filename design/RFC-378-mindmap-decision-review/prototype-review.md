# RFC-378 原型与设计检视记录

日期：2026-10-18（America/Los_Angeles）。本记录只覆盖可交互原型与设计合同，不代表生产实现、CI、真实模型生成或正式部署验收。

## 可操作范围

原型源：`prototype/mindmap-decisions.html`。默认案例有 4 个问题、3 个已确认回答；可从全景进入聚焦作答、修改答案与决定补充、主动或引用追问、追加同分支问题、复核并生成演示结果。页面顶部明确标注追问和输出是演示。工作流模板入口演示现有代理选择及生成流程，不创建真实资源。

## 浏览器实际走查

使用 Chrome，通过真实控件操作；不是仅检查源码。追问采用固定案例和本地计时器，以下“成功/失败”均指原型的演示状态。

| 场景 | 实际结果 |
| --- | --- |
| 未确认就提交 | 复核显示当前答案、依据、代价、未知与安排；提交被阻止并提示剩余 1 个未确认回答，可定位修改。 |
| 修改后重新确认 | 已确认回答从 4/4 变回 3/4，问题目录与按钮同步；编辑待验证内容同样撤销旧确认。 |
| 草稿恢复 | 编辑“缺少真实爽约数据；不把忘记签到直接视为爽约。”、清空负责人，刷新后内容、空值及未确认状态保持。仅证明原型状态存储。 |
| 已决定仍有未知 | 把未签到问题改为已决定，待验证内容和复核时间仍可编辑，并在复核及结果保留。 |
| 主动追问 | 具体思考入口展开可编辑指引，用户点击生成后在原分支追加 2 个问题，原答案保留。 |
| 选区追问 | 实际拖选“未签到时，是否自动释放？”，引用区准确显示该文字；无选区时可直接自由输入。 |
| 取消 | 生成中点击取消，指引原文和所有答案保留，可以再次生成。 |
| 生成期间切题 | 生成时转去验收题，追加完成后仍停留在验收题，不抢走当前阅读位置。 |
| 新问题不代选 | 新问题无已选选项、无决定标注、无预填待验证事实；多选作答后可保持未标注并确认。 |
| 失败与恢复 | 在独立失败情境预览中，首次生成失败后保留指引，提供重试；重试成功追加 2 个问题。此为原型错误夹具，不代表托管服务已修复。 |
| 复核与演示结果 | 完成 6 题后提交一次，结果保留依据、代价、暂定、未知、负责人尚未指定，以及已决定题目的复核安排。 |
| 提交后回看 | 从结果返回只读脑图，再点“查看已生成结果”可回到同一结果，不重复提交。 |
| 窄屏与外观 | 实际检查 1024px 复核、320px 聚焦和 390px 全景；根元素 scrollWidth/clientWidth 分别为 992/992、288/288、358/358，无横向溢出。浅色正常预览，深色使用仅更改外观和失败情境的独立预览夹具。 |

## 独立功能设计门

按 `AGENTS.md → CLAUDE.md §Codex review → docs/dev-gotchas.md` 的按路径限定独立子代理备选，在本会话内执行只读检视。范围为 proposal、design、plan、research 和原型，以及其中明确引用的现行源码合同。没有联系其他独立 session，没有运行测试或服务，没有改生产代码。

结论：**当前修订没有未关闭的 P1/P2 功能 findings，可进入用户对具体原型与 RFC 的审核。**

发现并关闭两项 P2：

1. 已决定题目的未知/负责人/复核时机原先会隐藏。修正为字段独立于成熟度，详情、复核与结果均保留。
2. 追问新题原先预填暂定状态和一条待验证判断。修正为无预选、无预填；decision.status 可选，补充字段可独立填写，规范化后的空对象视为无 decision，保持旧确认哈希兼容。

合同核对另明确 `ClarifyRoundDtoSchema.draftAnswers` 内联 schema 也需贯通可选 decision。旧问题模式、草稿/归属/封存、原提交 mutation 与托管 binding 复用方向未发现具体阻断。
