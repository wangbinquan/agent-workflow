## 1. 背景

三个模块的组合层在调用方没给时自己造：

- **intent 的 apply**（`composition/apply.ts`）：资源会话绑定（连同里面的插件 / 技能工件属主、ACL 归属读面与一个 MCP 事务生命周期）、工件生
  命周期（连同工件内容与旧版技能工件的兼容绑定）。daemon 只给了工件内容、两个工件属主、ACL 归属读面与工件生命周期，资源会话绑定与旧版兼容绑
  定一直由回落在生产路径上造。
- **intent 的维护**：恢复场景的工件生命周期与维护命令的草稿区。它们在维护 worker 里被调用，单机部署的 worker 效果是 `null`，于是一直由回落造
  本机实现。
- **code-capability 的代码历史**：读取器缺省是“未绑定”的空实现；daemon 总是传入。
- **memory 的注入查询**：daemon 总是传入。

这些回落让依赖藏在组合层里：哪一份是生产对象、哪一份只是给用例的方便，从调用处看不出来。

## 2. 目标

- **G1 必填注入**：上述 11 处改为调用方给出。intent apply 只收已经装好的资源会话绑定与工件生命周期，只为回落存在的选项一并删去；工件生命周期
  必须给出工件内容与旧版兼容绑定；恢复场景必须给出工件生命周期；维护命令必须给出草稿区；代码历史必须给出读取器；记忆必须给出注入查询。
- **G2 装配处显式构造**：daemon 的 intent 装配在 bootstrap 里构造资源会话绑定与旧版兼容绑定（与此前回落造的对象相同）；维护 worker 在没有托
  管效果时取 intent 的单机选择（工件内容与草稿区），不再落到模块组合层。
- **G3 门与用例**：RFC-521 门删去 11 条登记，适配器回落 78 → 67；用例经测试助手显式给出与此前缺省相同的对象。

## 3. 非目标

- 维护 worker 的单机效果整体收成一份（另立后继，见 design §8）；其余模块的回落；任何行为、接口与界面变化。

## 4. 用户可见变化

无。

## 5. 验收标准

- **AC-1**：这 11 处回落不再存在；对应选项必填、只为回落存在的选项删去；RFC-521 门的实测与登记逐条相等，适配器回落 67 条。
- **AC-2**：daemon 与维护 worker 得到的对象与此前相同（同一组工厂、同一组参数，MCP 事务生命周期照旧每份装配新建）；用例显式给出的选择与此前
  缺省相同。
- **AC-3**：bootstrap 不深取模块的 infrastructure（intent 新增的单机选择经组合层交出）；public surface 不升；计数不升。
- **AC-4**：受影响用例全部通过；推送后 exact SHA 的 GitHub Actions 全绿（环境性红格逐格归因、如实记录）。
