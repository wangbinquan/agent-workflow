## 1. 背景

source-control 有两组守护进程级的状态放在模块级：

- **仓库批量导入**（`infrastructure/local/repositoryBatchImport.ts`）：批次表与跨批次的克隆信号量（`let globalConcurrency`、`let globalInFlight` 与
  等待队列）都在模块级，`__resetBatchImportForTests()` 清空。HTTP 的批量导入操作、实时策略查批次发起者（`batchOwnerUserId`）与 daemon 会话
  的批次回收计时器（`startBatchImportGc`）三处装配点各自 import 这些函数，靠同一份模块状态碰面。
- **缓存仓库列表的读缓存失效**：存储端口文件（`ports/repositoryWorkspaceStore.ts`）的 `let repositoryFacetCacheEpoch` 是全进程的切面缓存代次——
  任何一个存储实例写缓存仓库就加一，所有实例的切面缓存随之作废；镜像缓存（`infrastructure/local/repositoryMirrorCache.ts`）的
  `let repoPageFlights` 是按数据库句柄合并在途页读取的表，写路径删掉对应条目，不带参数的失效调用整表换新（只有用例这么调）。存储实例在
  十来处按需构造、都在同一个库上，所以失效信号要跨实例；但它按进程而不是按数据库计。

架构报告的模块级可变单例清单里它们共 4 条（全仓 43 条）。

## 2. 目标

- **G1 批量导入归实例**：`createRepositoryBatchImports()` 构造一份批量导入（批次表与信号量），批量导入的各函数收下它；daemon 应用的组合构造
  一份，交给 HTTP 操作与实时策略的发起者查询，并经应用运行期交给会话的回收计时器；删去模块级状态与重置函数。
- **G2 读缓存状态归数据库**：platform 的数据库句柄上下文多一格“按数据库的模块状态”（键由使用方模块持有，事务与原生会话共用）；缓存仓库的
  切面代次与在途页读取合并改为这一格里的按库状态，由 SQL 存储读写；删去模块级代次、合并表与它们的失效函数，写路径统一调存储的
  `invalidateCachedRepoFacets()`。
- **G3 结局不变**：一个 daemon 里只有一份批量导入，并发上限、批次回收与发起者查询照旧；切面缓存的 5 秒有效期与写后立即作废照旧，同一查询的
  在途页读取照旧合并。
- **G4 门与用例**：新增 RFC-548 用例（三个文件没有模块级状态、删去的名字不在；两份批量导入互不相见；同一个库上的存储共用代次与在途合并、
  不同库互不影响；带负对照）；读旧接口的用例随改；模块级可变单例 43 → 39。

## 3. 非目标

- 其余 39 条模块级可变单例（schema 历史运行时的登记 2 条另立；RFC-546 的两类待用户确认）。
- 批量导入的 WebSocket 广播不动；切面缓存的有效期、计算方式与页面形状不变。

## 4. 用户可见变化

无。

## 5. 验收标准

- **AC-1**：三个文件没有模块级可变状态与重置函数；批量导入由组合构造并交入；读缓存状态挂在数据库句柄上下文上。
- **AC-2**：批量导入、切面缓存与在途页合并的结局不变。
- **AC-3**：模块级可变单例 43 → 39、计数不升；新增 RFC-548 用例并登记 guard-manifest；读旧接口的用例随改。
- **AC-4**：受影响用例全部通过；推送后 exact SHA 的 GitHub Actions 全绿（环境性红格逐格归因、如实记录）。
