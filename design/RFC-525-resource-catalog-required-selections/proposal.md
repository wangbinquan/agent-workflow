## 1. 背景

resource-catalog 的组合层在调用方没给时自己造本机实现：

- **技能内容**：技能目录的六项内容存储、版本推进的树存储、内容可用性的版本查询，以及“不给内容绑定就只交出根目录”的选择助手。daemon 总给
  部署选择的绑定（两种部署的绑定都把这些成员给全），这些回落只服务用例。
- **资源包**：包读取的技能内容、插件与技能的工件属主、维护场景的工件恢复。daemon 给部署选择的；资源包命令（CLI）只给插件安装器，单机维护
  worker 的效果是 `null`——这两条路径一直由回落造本机实现。
- **插件与 MCP 探测**：插件安装器（daemon 总给部署选择的）；MCP 探测的执行器，单机的 MCP 诊断显式交 `undefined`，于是一直由回落走进程内。

## 2. 目标

- **G1 必填注入**：上述 16 处改为调用方给出；内容绑定的树存储与包内容改为必填（两种绑定本来都给），只为回落存在的选项一并删去。
- **G2 装配处显式构造**：资源包命令、维护 worker 与单机 MCP 诊断在原来回落发生的位置显式给出同样的本机实现（同一组工厂、同一组参数）；单机选
  择经组合层交出，bootstrap 不深取模块的 infrastructure。
- **G3 门与用例**：RFC-521 门删去 16 条登记，适配器回落 51 → 35；用例经测试助手显式给出与此前缺省相同的对象。

## 3. 非目标

- 单机选择整体收进 `bootstrap/standalone.ts`（与维护 worker 的单机效果一并另立后继）；其余模块的回落；任何行为、接口与界面变化。

## 4. 用户可见变化

无。

## 5. 验收标准

- **AC-1**：这 16 处回落不再存在；对应选项必填、只为回落存在的选项删去；RFC-521 门的实测与登记逐条相等，适配器回落 35 条。
- **AC-2**：daemon、资源包命令、维护 worker 与 MCP 探测得到的对象与此前相同；用例显式给出的选择与此前缺省相同。
- **AC-3**：bootstrap 不深取 resource-catalog 的 infrastructure；public surface 不升；计数不升（降的收紧到实测）。
- **AC-4**：受影响用例全部通过；推送后 exact SHA 的 GitHub Actions 全绿（环境性红格逐格归因、如实记录）。
