# RFC-240 — 评审 diff 词档表格 cell 级细化（C′）

## 背景

RFC-012 为解决词级 diff 打碎 GFM 表格的问题,选定方案 A:词档把整张表原子
化为单个占位符 token——表要么 unchanged、要么整删、要么整增。文档里明确
记录了代价:"表内 cell 级 word-diff 退化为『整表 del + 整表 ins』,可接受"
(design.md §备选方案对比),并注明 cell 级细化"未来若需要,再立 RFC"。

2026-07-30 的表格碎裂修复(RFC-012 勘误一~六轮)之后,情况变化:

1. **痛点实证**:重表格的评审文档里,改一个 cell 就把整张表红绿各显示一遍,
   噪音随表体积线性放大;行档虽能行级呈现,但用户在词档(默认档)的直觉
   预期是"只有变的那格亮"。
2. **前置设施齐备**:当年否掉方案 C 的两大难点已在修复过程中落地——
   `tableStructureKey`(表头+分隔符)可靠配对同一张表的前后版本;
   `wrapTableRowCells` + 分隔符零 marker 不变量保证 cell 内 marker 安全;
   结构变化的整表回退路径与畸形段兜底重建均有 44 条渲染级测试锁定。

用户于 2026-07-30 会话中拍板:采用 **C′**(词档表格 cell 级细化),否决
D(全词路径两段式重写)——理由是 D 会牺牲正文的跨段词级匹配语义(用户
明确不接受),且其独有收益无实际痛点支撑。用户同时表达行配对偏好:**按
相似度配对**而非按位置。

## 目标

词档(granularity='word')下,当左右两侧存在**结构键逐字节相同**(表头行
与分隔符行完全一致)但内容不同的表格配对时:

1. 该表**只渲染一次**(单 `<table>`),而不是旧表+新表两张;
2. 未变化的行原样呈现,无任何高亮;
3. 被修改的行按 cell 呈现:仅发生变化的 cell 内出现"旧值红 + 新值绿"的
   内联词级高亮,其余 cell 干净;
4. 新增/删除的行整行绿/红(源码中存在的每个 cell 包 marker;GFM 按声明
   列数隐式补齐的空列是渲染属性、不带 marker);全空 cell 的增删行以单
   空格 marker 色块占位,保证可见;
5. 删除行与新增行之间**按相似度配对**决定谁和谁做 cell 级对比,配不上的
   整行呈现。

## 非目标

- **结构变化**(表头改名/列数/对齐,即结构键不同)维持现行为:旧表整红 +
  新表整绿。结构键不同意味着 cell 对齐没有可靠依据,细化收益与歧义不成
  比例。body 行 cell 数超过分隔符声明列数(GFM 会截断超列)时同样整对
  回退现行为。
- **仅首 `|` 风格表**:与 RFC-012 `findTableBlocks` 一致;无首 pipe 的
  GFM 表从未进入表格保护,本 RFC 不改变该边界。
- **行档/块档不动**;正文与结构变化表的行为保持,**显式例外仅三项既有
  缺陷修复**(全局生效,见 design §共享原语):含「偶数反斜杠 + `|`」的
  表格行 cell 边界修正;「多反引号定界、内容含反引号」code span 的原子化
  修正;词级 diff 公共缀提取的字素簇安全回退(IVS/ZWJ/组合标记不再被
  拆散)。除此之外跨段词级匹配等正文语义逐字节保留。
- **blockquote 内表格不细化**(现状:内联 marker 或整块呈现,已有测试锁
  定),与 `findTableBlocks` 只识别顶层表的既有边界一致。
- 不做"表格整体移动/互换"的移动检测(已由结构键折叠 + 兜底重建覆盖,
  RFC-012 勘误四~五轮)。
- 不改 `DiffView` / `MarkdownDiffView` 的公开接口与三档 UI。

## 用户故事

1. 评审者在词档对比两版设计文档,文档含一张 30 行参数表,新版只改了其中
   一行的默认值:页面上仍是一张表,只有那一格里"旧值划红、新值标绿",
   其余 29 行零噪音。
2. 新版在表中追加两行参数:同一张表尾部两行整行绿。
3. 新版把表头从"参数/默认值"改成"名称/取值":退回旧表整红 + 新表整绿
   (结构变化,现行为),不产生任何裸 `|` 或错位。

## 验收标准

- [ ] 同结构键单 cell 修改:渲染恰一张 `<table>`;变更 cell 内同时存在
      `.diff-del` 与 `.diff-ins`;其余 cell 与行无任何 diff span;文本层
      无裸 `|` 泄漏。
- [ ] 同结构键行增/删:单表内整行绿/红。
- [ ] 相似度配对:删除行与新增行中"明显是同一行的编辑"配对做 cell 级
      对比;完全无关的行不硬配。
- [ ] 结构键不同:与现行为逐字节一致(既有 44 条渲染级回归零变化)。
- [ ] identical 不变量与既有锁定测试同形:word/line 对「以换行结尾、
      不含 U+E000–U+E00F」的输入逐字节一致;block 段落规范化后等价
      (line 尾换行补齐与 block 空行折叠是既有全档语义,非本 RFC 引入)。
- [ ] `bun run typecheck && lint && test && format:check` 全绿;既有全部
      diff 相关测试零回归。
