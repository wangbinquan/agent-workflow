# RFC-293：Intent 持续迭代工作台

- 状态：Done（实现 `53c57080`；exact-SHA CI / visual / Windows / integration 全绿）
- 日期：2026-08-12
- 用户最终裁决：2026-08-13
- 关联：RFC-234、RFC-235、RFC-291

## 1. 背景

当前 Intent 详情页把长会话和产物放在同一个页面滚动流中。会话滚到下方后，右侧产物随页面一起离开视口；
宽屏又受 `max-width` 限制，左右大量空间没有被利用。资源挂载位于会话底部，运行中不可操作，挂载后还要用户
手工再发一条消息才能生成可提交的新草稿。

真实工作也不是“生成一次、提交、结束”：

- 提交前会连续完善多轮；
- 提交只是一个可用检查点，提交后仍会继续迭代；
- 某一轮结果不合格时，需要废弃该候选并重新生成；
- 运行中发现缺资源时，应能先调整工作上下文，让系统在本轮结束后自动续跑，或停止本轮立即刷新。

## 2. 用户最终产品边界

RFC-293 只解决工作流和使用体验，不引入新的安全子系统，也不收缩 Intent 的执行能力。

Intent Builder 继续复用现有 `runSystemAgent`、runtime profile 和资源装配路径。它与当前普通 Agent 一样使用已有的
provider、认证、配置、命令、hooks、agents、plugins、skills、MCP、文件、网络和子代理能力。本 RFC 不增加：

- sealed/sandbox runtime；
- credential、proxy、CA、mTLS adapter；
- containment、supervisor、auth lease；
- capture quarantine、历史数据库清洗或新的输出审查；
- 新的 capability admission/fail-closed 分支。

现有登录、Intent owner、资源 ACL、apply journal、context revision 和单轮 single-flight 规则保持原样；它们是既有
系统合同，不在本 RFC 中扩张。

## 3. 目标

### G1：会话与产物始终同时可见

桌面端详情页占满可用宽度和高度。会话与复核各自滚动，滚动任一侧不移动另一侧。宽屏右栏拿到全部剩余空间，
workflow canvas 和资源预览不再被 1400px 封顶。

### G2：工作上下文成为一级操作

已挂载资源、待应用变更和刷新状态显示在两栏上方。一个“管理工作上下文”对话框一次性暂存增加与移除，保存时
只发一个请求。

### G3：上下文更新自动生成新版

- 空闲保存：应用 delta 并立即预留下一轮；
- 运行中保存：持久化排队，本轮结束后自动应用并续跑；
- 运行中也可选择“停止本轮并立即刷新”；
- 应用失败时保留 delta 供调整、重试或放弃；
- 不要求用户再输入“请重跑”。

### G4：提交前后持续迭代

同一个 Composer 根据当前来源工作：

- 有 current draft：继续完善该草稿；
- 刚提交且无 current draft：基于最新提交检查点继续；
- 尚无草稿：继续当前对话。

提交成功只创建不可变检查点并清空 current candidate，会话、上下文、历史和 Composer 都继续可用。

### G5：候选可废弃重跑

current draft 可执行“废弃并重新生成”。废弃不会删除历史，也不会回滚已提交资源。新的生成成功后产生新 revision；
失败时被废弃版本仍保持只读且不可提交，用户可对失败轮重试。

### G6：问题与资源建议一次处理

当 agent 同时返回 questions 和 mount suggestions 时，界面合并成一个“当前待办”，用户一次提交答案与资源决策，
服务端只预留一个后续 turn。

## 4. 核心交互

```text
┌ 标题 / 生命周期动作 ────────────────────────────────────────────────┐
│ 目标 ───── 生成 ───── 复核 ───── 提交检查点 ↻                     │
├ 工作上下文  Agent ×2 · Workflow ×1 · +3   [本轮后刷新] [管理] ─────┤
├────────────────────────┬───────────────────────────────────────────┤
│ 构建会话                │ 草稿 v7 · 基于已提交 #3                  │
│ 独立滚动                │ 独立滚动 / canvas / op preview           │
│                        │ [继续完善] [废弃并重新生成] [复核并提交]  │
│ 当前待办                │                                           │
│ Composer                │                                           │
└────────────────────────┴───────────────────────────────────────────┘
```

- 页面 header、journey 和工作上下文条固定在 workbench 上方；
- 桌面两栏分别拥有唯一纵向滚动容器；
- 左栏宽度 `clamp(360px, 32%, 620px)`，右栏使用剩余宽度；
- 1080px 以下切换 Build/Review tabs；两个 panel 保持状态，只有活动 panel 可见；
- 左侧仅在用户已接近底部时跟随新事件；向上阅读时保位并显示“回到最新”；
- 版本列表可回看 current、committed、superseded、discarded；历史版本没有 mutation action。

## 5. 功能合同

### 5.1 Working-set change

一次请求描述完整 delta：`additions[]` 与 `removals[]`。同一 session 最多一个未终结 change；排队中的 change 可被
显式替换或取消。状态为：

```text
queued -> applying -> applied
   |          |         |
   +-> canceled         +-> generated by reserved turn
              +-> failed -> retry / replace / dismiss
```

delta 应用与下一轮 reservation 在一个数据库事务中完成，因此不会出现“资源已挂载但没有自动续跑”的中间状态。
本轮运行时更新只改变下一轮 context；不会尝试热注入已启动的模型进程。

### 5.2 Draft lifecycle

- `current`：唯一可提交候选；
- `committed`：已有成功 commit receipt 的不可变检查点；
- `superseded`：被更高 revision 替换；
- `discarded`：用户明确废弃；
- activity 与 lifecycle 正交：生成新版期间 source current 仍可查看，但提交暂时禁用。

### 5.3 Iteration

- refine-current 必须绑定 current draft id/hash；
- continue-checkpoint 必须绑定最新 `commitSeq`；
- regenerate 必须绑定 current draft id/hash，并在同一事务中记录 discard、清 pointer、写 user turn 和 reserve；
- stale tab 只 refetch，不得复活旧 draft；
- retry 只针对最新 terminal generation error，questions 不显示 retry。

## 6. 非目标

- 不给已启动进程热注入上下文；
- 不增加资源数量上限；
- 不改变六类资源的创建、更新、ACL 或提交语义；
- 不提供已提交资源回滚；
- 不增加 layout 拖拽持久化；
- 不删除 legacy mount API，旧调用继续按原合同工作；
- 不引入任何新的 runtime 安全或能力限制。

## 7. 验收标准

- **AC-1**：长会话滚到底后右侧产物仍在视口；反向同理。
- **AC-2**：桌面详情页不再受 1400px 封顶，右栏使用全部剩余宽度。
- **AC-3**：工作上下文入口位于两栏上方，一次保存可同时增加、移除多类资源。
- **AC-4**：空闲保存上下文后自动生成新版，无需手工消息。
- **AC-5**：运行中可排队；本轮结束后 delta 只应用一次并自动续跑一次。
- **AC-6**：运行中可停止并刷新；停止和 queue 不产生两个 successor。
- **AC-7**：queued change 可替换/取消；failed change 可调整、重试或放弃。
- **AC-8**：提交前可连续 refine 任意多轮，只有 latest current draft 可提交。
- **AC-9**：提交后 session 仍 active，Composer 明示基于最新检查点继续。
- **AC-10**：discard + regenerate 原子；旧 draft 只读且永久不可提交，已提交资源不回滚。
- **AC-11**：regenerate/refine 失败后可重试；不会错误复活 discarded draft。
- **AC-12**：questions 与 mount suggestions 一次提交，只产生一个后续 turn。
- **AC-13**：宽屏、1080px tabs、390×844、light/dark、键盘和 axe serious/critical 通过。
- **AC-14**：Intent 仍走现有普通 runtime 能力路径；本 RFC 没有新增 capability rejection。
- **AC-15**：后端 normal、stale、重复、并发、取消、失败、重启恢复路径有测试，E2E 覆盖完整用户主线。
