# RFC-250 UX 审计移交：Onboarding 路线与 outcome 关联

- 日期：2026-08-03
- 状态：Follow-up finding；未 supersede RFC-211，未获 production 实施批准
- 来源：RFC-250 全前端 UX 审计与独立设计门

## 当前源码 finding

- RFC-211 当前权威形态与实现都是三张 spotlight tour 卡；zh-CN 入口仍承诺“四条路线 / Skill”。
- First Task 的 task submit 以 raw click 推进；Workflow 到模板步骤即结束；Workgroup 到 launch 按钮即结束。
- route 前缀或稳定 DOM marker 不能证明当前 step 发起的 mutation 已成功，旧页面/旧结果可能误推进。

## Follow-up 设计硬要求

RFC-211 follow-up 必须先由用户选择：

1. 保留权威三卡形态并把入口/步骤/结束结果文案改为真实三条；或
2. 明确 supersede RFC-211 顶部三卡决策，另行批准第四条 managed Skill 路线及完整成功闭环。

任何 save/submit/launch outcome 推进都必须关联当前 attempt，而不是只看 route/DOM：

```ts
interface TourOutcomeReceipt {
  tourId: TourId
  stepId: string
  attemptId: string
  kind: 'resource-created' | 'resource-saved' | 'validated' | 'task-created'
  resourceId?: string
  taskId?: string
}
```

只有当前 step 真实 action 的 fulfilled mutation/receipt 可发布；迟到、重复、其它 resource、reload 后没有
active attempt 的事件不得推进。route/DOM 只负责定位已证明 outcome 的目标。实施前需独立 RFC-211
follow-up 设计门与用户批准；RFC-250 不修改 Onboarding production。
