## 1. 背景

模块组合层里有一类“没给就自己造一个”的写法：`input.x ?? createFile…()`、`selected === undefined ? createLocal…() : selected`、参数缺省值
`history = createUnbound…()` 等。plan 的基线按名字数（`?? create… / compose…(` 50 处、`=== undefined ? create…(` 14 处、`?? new X(` 1 处）。
按语法树把“回落一侧是调用或 `new`”的位置全部数出来，全部模块的组合层共 99 处、51 个文件：

- **72 处适配器回落**：回落到名字带 File / Local / Native 的工厂、以本模块持久化为底的默认实现、拒绝一切的空实现、`select*` 助手里的内联本机
  默认，或 `local*` 一类的本机分支。其中 10 处的工厂不以 create / compose 起名
  （`localRuntime` / `localStart`、`probeMcp`、`lazyEvidenceBlobs`、`resolveDatabaseProviderRuntimeForRestore`、本机 git 的三个提交步
  骤、`Object.freeze` 包着的内联本机默认），按名字数会漏掉。
- **27 处中性默认**：日志器、时钟与 id、由注入的根推出的路径、本组合自有对象的惰性构造、调注入的工厂或在两种注入形态间选择、业务选项、纯计
  算、进程内推送与限流。

现在没有任何东西钉住它们：新的回落可以加在任何组合文件里而没有一处变红；后继按模块清偿时也没有一份精确清单可对。

## 2. 目标

- **G1 全模块门**：新增 `tests/architecture/rfc521-composition-adapter-fallbacks.test.ts`，覆盖全部模块的组合层（判定与 RFC-515 门相同），按
  语法树找出全部回落构造；每个文件实测的被调用者与登记表逐条相等，清单外的回落与陈旧条目都报红。
- **G2 精确清单**：design §3 列出全部 99 处：中性默认各带类别（封闭的 9 类），适配器回落按模块指定后继；适配器回落的总数钉为实测 72，只减不
  增。
- **G3 后继拆分**：S12 第 1 项余下的清偿按模块分六步（design D3），每步把该模块登记的适配器回落改为必填注入、删去登记、下调总数。

## 3. 非目标

- 改动任何生产代码（清偿由后继各步做）；S12 的其余各项（导入期单例、模块级可变单例、直接定时器、按本地工厂签名定型的槽位）。

## 4. 用户可见变化

无。

## 5. 验收标准

- **AC-1**：门覆盖全部模块的组合层；实测与登记表逐文件、逐条相等；清单外的回落与清单里已不存在的条目都报红；适配器回落总数 = 72，每个有适配
  器回落的模块都指定了后继。
- **AC-2**：每种回落写法（`??`、`??=`、`||`、`||=`、两向的缺失判断条件、`if` 赋值、参数与解构缺省值、调用链与 `await` / `as` 包裹）都有会红
  的负对照；不构造的回落（字面量、已有对象、惰性函数）与组合层以外的文件不判。
- **AC-3**：生产代码不变；public surface 与计数不升。
- **AC-4**：受影响用例全部通过；推送后 exact SHA 的 GitHub Actions 全绿（环境性红格逐格归因、如实记录）。
