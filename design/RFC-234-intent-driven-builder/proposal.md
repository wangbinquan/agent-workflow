# RFC-234 意图驱动的资源构建（Intent Builder）— proposal

状态：Draft v2（2026-07-28 落档；7 轮 27 问用户澄清 + Codex 设计门一轮 6 P0 + 8 P1 +
2 P2 全采纳折入（修订账 design §14），待用户批准后实施）。

## 1. 背景

平台的六类资源（Agent / Skill / MCP / 插件 / 工作流 / 工作组）目前只能手工创建与编辑。
用户提出：给平台一个"说出目标，平台替你把整套东西搭出来"的入口——使用者输入工作目标与
过程描述，平台启动一个运行时 agent 自动创建/编排所需的工作流或工作组，过程中缺什么
Agent / Skill 就顺带创建；生成后还能继续用自然语言迭代调整；所有改动在提交前以变更集
形式清晰可视化，使用者确认后才落为真实资源。已有资源同样获得"意图修改"能力。

仓内已有三块直接先例（研究结论，锚点见 design.md）：

- **RFC-167 动态工作流**：工作组 dynamic 模式里已存在"目标 → LLM 生成 DAG → 人确认 →
  确定性执行"闭环，但仅任务内临时产物、仅 agent-single 节点、固定成员池、无多轮会话。
- **RFC-101 记忆→技能 fusion**：AI 修改资源 → diff 呈现 → 人批准 / 驳回带反馈重跑的
  完整审批闭环先例。
- **memory distiller / runtime smoke**：两条非任务"系统 agent"执行链路（临时目录 +
  封印二进制 + 一次性私有 store + containment + 信封输出 + 设置页 System Agents 运行时
  配置）。本 RFC 是第三个使用者，按既约抽公共原语。

**需要显式推翻的历史决定**：RFC-199 曾裁定"不在工作流编辑器引入 AI 自动生成"。本 RFC
经用户拍板推翻其中"AI 生成"一半（入口铺开到全局页 + 各资源页 + 编辑器工具栏）；
"prompt 输入框不是唯一创建入口"一半继续成立——手工路径完整保留。

## 2. 目标

1. **意图会话**：持久多轮会话。使用者用自然语言描述目标（可选提示产物类型，不强制），
   平台每轮启动一次性系统 agent 运行，产出结构化**变更集**（新增/修改六类资源的完整
   描述）或**反问问题单**；使用者可继续输入调整、回答反问、显式挂载既有元素，反复
   收敛；一个会话可多次"生成 → 确认提交"，提交后仍可继续调整再提交。
2. **变更集确认**：提交前以"变更清单卡片 + 字段级 diff"为基本盘，附加工作流画布只读
   预览（改前/改后切换）、工作组结构预览、Skill 文件树逐文件 diff、prompt 正文
   markdown 渲染 diff。修改类条目逐元素选择"直接修改 / 新增副本"；整包 all-or-nothing
   提交，单一事务落库。
3. **意图修改既有元素**：从元素详情/编辑页发起，平台把该元素及其**依赖闭包**（工作流→
   引用 agents→各自 skills/MCP/插件…）以**文件 dump 形式放进一次性工作目录**——不以
   opencode agent/skill 运行时形态注入——并配完整提示词说明。agent 可对闭包内元素提出
   修改；写权限边界不变（仅 owner/管理员可写；他人/内置资源只有"复制为新私有元素"
   选项）。
4. **安全边界**：意图 agent 走非任务系统链路——临时工作目录、封印二进制、一次性私有
   store、containment 隔离；工具面收窄为"文件读写仅限工作目录"，禁 Bash / 禁 MCP /
   禁子进程 / 模型调用外无网络。**agent 永远接触不到平台数据库与家目录**；变更全部
   经信封输出，由平台在使用者确认后通过六类资源的 canonical service 函数落库
   （actor = 会话 owner，非 system/admin）。
5. **运行时可配**：设置页 System Agents 新增"意图构建"卡片：runtime 选择（缺省继承
   defaultRuntime）、输出语言、单轮超时与输出上限、会话轮数预算、管理员自定义追加
   指令。

## 3. 非目标（v1）

- **不支持删除**任何资源实体（工作流内部删节点属修改）。删除继续走各资源页手工路径。
- **不关联仓库**：不把用户 repo 内容喂给意图 agent（"给这个仓库定制工作流"场景留待
  后续 RFC）。
- **无会话协作成员制**：会话仅创建者可见（管理员可见用于审计）；类似任务 collaborator
  的多人共聊留待后续。
- **无一键启动**：提交后只给资源跳转链接，不代发任务/工作组。
- **无自动试跑**：静态校验（schema / workflow validator / 引用解析）全做，但不真实
  执行生成的工作流来验证。
- **无会话级 opencode session 回放 UI**：每轮仅保留最小诊断（失败码 + stderr 尾部）。
- **Skill 不支持二进制文件**；辅助文件限纯文本。
- 意图 agent 不能引用/操作平台用户身份（用户列表、user id 一律不进 prompt）。

## 4. 用户故事

- **US-1 从零编排**：作为使用者，我描述"我要一个先实现、再按文件分片审计、最后修复的
  流水线"，agent 反问澄清（如审计维度、是否需人工评审），随后产出：1 个工作流（含
  git wrapper + fanout + 评审节点）+ 2 个新 Agent + 1 个新 Skill 的变更集；我在确认
  界面看全部改动、微调命名后整包提交，六个资源以我为 owner、private 落库。
- **US-2 意图修改**：作为使用者，我在某工作流编辑页点"意图修改"，说"给审计节点加一个
  安全维度，输出单独端口"；agent 在 dump 里读到工作流 YAML 与引用 agent 的定义，产出
  对工作流与我拥有的审计 Agent 的修改；确认时我对该 Agent 选择"新增副本"以免影响其他
  工作流，平台自动把工作流改指副本。
- **US-3 引用他人资源**：闭包里有同事授权给我的 public agent；agent 只能建议"复制为
  新私有元素"，原件不动。
- **US-4 反问收敛**：agent 对分片粒度拿不准，该轮产出问题单而非变更集；我用结构化
  选择题回答，下一轮它带答案重新生成。
- **US-5 复用而非重复建设**：从零创建时 agent 拿到我可见的资源清单摘要，直接引用我已有
  的 `code-reviewer` agent 而不是再造一个；重名自动避让，平台预检兜底。
- **US-6 并发保护**：会话进行中我在另一页面改了目标工作流；确认提交被版本围栏拦下，
  提示元素已变化，我一键把新版本拉进会话重新生成后再提交。
- **US-7 管理员配置**：作为管理员，我在设置页把意图构建 runtime 指到自建高上下文
  profile，并追加"命名一律 kebab-case"的团队指令。
- **US-8 审计回看**：资源详情页可见"来自意图会话 X 第 N 次提交"标注（仅会话可见者
  可见）；会话页可回看全部对话与历次提交的变更集快照。

## 5. 关键拍板（7 轮 27 问，全部用户裁决）

| --- | --- | --- |
| D1 | 资源范围 | 六类全覆盖（含 MCP、插件） |
| D2 | 删除 | 不支持 |
| D3 | 闭包修改 | 允许改闭包内元素；确认环节逐元素选"直接修改 / 新增副本"；他人/内置仅副本 |
| D4 | 工作流节点 | 完整节点能力（wrapper/评审/反问/跨agent反问/IO 全支持） |
| D5 | 入口 | 全局意图页 + 六类资源列表/详情/编辑页快捷入口（显式推翻 RFC-199 相应半条） |

| D7 | 目标类型 | 不强制预选，agent 自判（可选提示） |
| D8 | 反问 | 支持；反问=该轮产出问题单，答后下一轮重生成 |
| D9 | 提交粒度 | 整包 all-or-nothing |
| D10 | 呈现 | 清单+字段 diff 基本盘；画布预览/工作组结构/Skill 文件树/markdown diff 四项全要 |
| D11 | 并发冲突 | OCC 拒绝 + 引导"拉新基线重新生成" |
| D12 | 信封 | 复用 `<workflow-output nonce>` + 单 `changeset` 端口（另 questions/summary 固定端口） |
| D13 | 链路 | 系统 agent 链路（非任务）；抽 runSystemAgent 公共原语 |
| D14 | 工具面 | 读写限工作目录；禁 Bash/MCP/网络。设计门修订：收敛为**只读**文件工具白名单（`intent-read-v1` 冻结枚举，经 RFC-224 资格认证；不支持该 profile 的 runtime 配置期拒绝）——信封成为唯一输出通道 |
| D15 | MCP 密钥 | 双向脱敏：dump 中 `‹redacted›` 占位；生成物密钥字段只能占位，确认界面补填真值后才可提交 |
| D16 | 人类成员 | 占位 displayName+职责；确认界面由使用者绑定真实用户或删除；用户身份不进 prompt |
| D17 | 仓库上下文 | v1 不关联 repo |
| D18 | 既有资源 | 默认注入完整可见清单摘要；被挂载/申请的元素展开详情 |
| D19 | 目标挂载 | 使用者显式挂载 + agent 可在信封申请。设计门收紧：申请只生成**待批准建议**，使用者逐项点头后才进入下一轮 dump（不存在自动挂载，防注入内容自主扩大披露） |
| D20 | Skill 形态 | 多文件、纯文本；可执行脚本后缀确认界面显著警示 |
| D21 | 设置项 | runtime + 输出语言 + 单轮超时/输出上限 + 会话轮数预算 + 自定义追加指令 |

| D24 | 命名冲突 | 呈现时预检+确认界面就地改名；提交复验兜底 |

## 6. 验收标准

- AC-1 全局意图页可新建会话、看历史列表；六类资源列表页有"意图创建"、详情/编辑页有
  "意图修改"入口，后者进入已预挂载目标元素的新会话。
- AC-2 一轮生成产出的变更集在确认界面完整呈现：新增/修改卡片、字段级 diff、四类附加
  预览（画布/工作组结构/Skill 文件树/markdown diff）全部可用。
- AC-3 反问轮产出问题单并以结构化表单作答；答案进入下一轮上下文。
- AC-4 提交为单一事务 all-or-nothing：任一元素校验失败/围栏冲突/插件安装失败时零资源
  落库（已装插件缓存清理），错误结构化回到会话。
- AC-5 修改类条目可逐元素选择"直接修改 / 新增副本"；选副本时引用它的同批元素自动改指
  副本；他人/内置资源无"直接修改"选项。
- AC-6 OCC：挂载基线过期时提交被拒，UI 提供"拉取新基线"动作；重新生成后可提交。
- AC-7 意图 agent 运行期间：cwd 为一次性临时目录（app-home 私有 scratch，成功即删、
  失败留档并由 boot/小时 GC 收口）；工具面=只读文件白名单（`intent-read-v1`），无写/
  无 Bash/MCP/网络；containment admit 通过；平台库/家目录不可达；不支持该 profile 的
  runtime 在设置校验期被拒（fail-closed）。
- AC-8 dump 与 prompt 中：MCP 敏感值全部 `‹redacted›`；不含任何平台用户 id/用户名；
  测试双层锁定（源码 grep 锁 + 运行时断言）。
- AC-9 变更集只能经信封进入平台；落库走六类 canonical service（actor=会话 owner），
  raw SQL 零出现；新资源 ACL 为 owner+private+零 grants。
- AC-10 设置页 System Agents 出现"意图构建"卡片，五项配置生效（runtime 校验复用
  resolveInternalAgentRuntime；删 runtime 时引用检查纳入）。
- AC-11 会话/变更集留存可回看；资源详情显示来源标注（仅会话可见者可见）。
- AC-12 `bun run typecheck && lint && test && format:check` 全绿 + binary smoke +
  新增 e2e（桩 runtime）通过；i18n 双语对称。
- AC-13 提交幂等与崩溃收敛：同 `clientMutationId` 重放返回原回执零副作用；插件预装/
  skill 预 stage/事务前后/发布/清理五断点崩溃后，boot 收敛为"零可见半成品或完整
  roll-forward"（apply journal 台账）。
- AC-14 确认绑定：commit 必须携带与确认页一致的 `draftRevision+draftHash` 并通过
  context epoch CAS；晚到的生成轮只归档不上位；agent 的挂载申请需使用者逐项批准后
  才进入下一轮上下文。
