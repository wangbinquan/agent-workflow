## 1. 背景

架构报告的模块级可变单例清单还有 66 条。其中 5 条是挂在进程级集合上的登记表，分属 task-execution 与 runtime-management：

1. **终态看门**（task-execution `infrastructure/executionWatch.ts`）：进程级的 `taskId → 等待者` 表。子调用节点等子任务结束、开发自动化的动作执行
   等宿主任务结束，都在这张表上登记；daemon 会话的已提交事件消费者在任务转入终态时唤醒它们（另有轮询兜底）。表是进程级的：同一进程里的
   两份会话共用一张，测试要靠导出的 reset 清它。
2. **执行参与者**（`infrastructure/local/agentExecutionEffect.ts`）：本机任务代理运行签发给执行请求的不透明参与者，背后是一张进程级的
   `参与者 → 本机持久化与节点执行` 表，本机调用解析时查它。
3. **迁移对照范围**（`infrastructure/migration/oracle/scope.ts`）：epoch 迁移的选择对照快照把“这批行的比较范围”记在进程级的
   `行数组 → 范围` 表里，对照的取行助手查它。
4. **工作区读取能力**（`infrastructure/workspaceRead.ts`）：任务工作区读取作用域的能力对象另记在一个进程级集合里；作用域自身已经按“未关闭且
   是同一个对象”判定，这个集合与作用域一一对应，不需要是进程级的。
5. **材料引用**（runtime-management `infrastructure/local/agentMaterialCompiler.ts`）：本机代理材料的编译器与材料定义把 `计划对象 → 材料引用`
   记在进程级表里，所有会话、所有运行共用。

后四张都以对象为键（弱引用），不会在会话之间串值，但它们是 design §3 常驻规则 5 点名的 `bind*` 侧表：谁签发、谁解读本该由签发它的实例自己
持有，不需要进程级的登记处。

## 2. 目标

- **G1 终态看门由会话构造**：`createTaskTerminalWatch()` 建一份看门（登记、唤醒），每个 daemon 会话在装配 task-execution 时与子任务预算同处建
  一份：子调用节点经运行期选项、动作执行经开发自动化的装配读这一份，会话的已提交事件消费者唤醒这一份。`executionWatch.ts` 不再有模块级
  状态与 reset。
- **G2 参与者自带解读**：签发的参与者是只有本机执行效果能读的对象（私有字段），解析时按它自己的字段取回本机持久化与节点执行，不查表。
- **G3 对照范围随行数组走**：对照快照把范围记在它自己建的行数组上（不可枚举的符号属性），取行助手从数组本身读。
- **G4 能力登记表归读取作用域**：每个工作区读取作用域自带一张私有的能力登记表，判定照旧是“未关闭、是同一个能力对象、在登记表里”。
- **G5 材料引用归材料定义**：每份材料定义建自己的引用表，交给它建的编译器；同一次运行里编译与查引用走同一份定义（此前就是如此）。
- **G6 门与用例**：新增 RFC-535 用例（五个文件没有模块级可变集合与导出的登记 / reset；看门两份会话互不唤醒；参与者、对照范围与材料引用
  各自的解读与负对照）；读旧形状的锁与用例随改；模块级可变单例清单 66 → 61。

## 3. 非目标

- 其余 61 条模块级可变单例（`transport-projections` / ws 的登记、配置生效监听、平台持久化的 schema 绑定、platform / util 的进程级缓存等）：
  另立后继；需要保留的进程级缓存由后继 design 提出、经用户确认后修订 design §14 口径。
- 看门的语义（先读后登记再读、轮询兜底、行被删时给 `missing`、中止时给 `aborted`）、参与者“只由签发它的本机实现解读”、对照的范围判定、
  工作区读取的生命周期与材料引用的取值规则（同一计划同一引用、带源计划的取源计划的引用）都不变。

## 4. 用户可见变化

无。

## 5. 验收标准

- **AC-1**：`executionWatch.ts` 没有模块级状态与 reset；看门每个 daemon 会话一份，子调用节点、动作执行与已提交事件消费者用同一份；两份会话
  互不唤醒。
- **AC-2**：参与者、对照范围、工作区读取与材料引用不再有进程级侧表；各自的解读与判定与此前相同（含签发者之外的对象被拒、范围不全时拒绝、
  关闭后的能力被拒、同一计划同一引用）。
- **AC-3**：模块级可变单例清单 66 → 61，计数不升；钉住旧形状的锁随改，新增 RFC-535 用例并登记 guard-manifest。
- **AC-4**：受影响用例全部通过；推送后 exact SHA 的 GitHub Actions 全绿（环境性红格逐格归因、如实记录）。
