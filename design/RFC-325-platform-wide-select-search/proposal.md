# RFC-325 全平台下拉框搜索能力

状态：Done（2026-08-25）
关联：RFC-036（Select 自定义 popover 起源）、RFC-165（`searchable` opt-in 首次引入）、RFC-173（MultiSelect / usePopoverPosition 抽取）、RFC-250（Select 禁用项与三态空行契约）、RFC-198（前端源码棘轮）

## 1. 背景

用户诉求原文：**「给平台所有的下拉框都要配置搜索能力」**。

按源码实测（2026-08-25，`packages/frontend/src`）盘出的现状：

| 控件                             | 调用点     | 搜索现状                                                             | 源码锚点                                        |
| -------------------------------- | ---------- | -------------------------------------------------------------------- | ----------------------------------------------- |
| `Select`（RFC-036 自建 popover） | **153 处** | `searchable` 是 **opt-in**，只有 **25 处**显式传，**128 处没有搜索** | `components/Select.tsx:130`                     |
| `MultiSelect`                    | 17 处      | **默认已带搜索**（`props.searchable !== false`）                     | `components/MultiSelect.tsx:116`                |
| `UserPicker`                     | —          | 服务端 `GET /api/users/search` 已有                                  | `components/UserPicker.tsx`                     |
| `RuntimeParameterPicker`         | —          | 自带搜索框已有                                                       | `components/RuntimeParameterPicker.tsx:522-541` |
| 原生 `<select>`                  | **0 处**   | 早已全部替换为自建控件                                               | 全仓 grep 仅剩注释提及                          |

所以缺口精确落在 `Select` 这一个共享原语上。三条对用户可感知的证据：

1. **`ModelSelect` 没有搜索**（`components/ModelSelect.tsx:148`）。它是 provider 分组的**全量模型列表**，`opencode models` 一次可返回上百个条目，用户只能滚动找。这是全平台最痛的一个下拉。
2. 128 个无搜索下拉里包含大量运行时动态列表：代理、工作流、仓库、数字员工、策略、Adapter、事件规则等，条目数随用户数据增长，**今天短不代表明天短**。
3. 已有作者手写阈值的先例：`components/canvas/inspector/CodeHostCallEdit.tsx:906` 写着 `searchable={selectOptions.length > 8}`——说明"按条目数决定要不要搜索"这条产品判断在仓内已自发出现，只是**没有被收进共享原语**，于是 152 个别的调用点各凭作者记性。

同时，三处已有搜索的控件**匹配语义各不相同**：`Select` 只匹配 `label + value`（`Select.tsx:162-168`）、`MultiSelect` 匹配 `label + value + description`（`MultiSelect.tsx:117-125`）、`RuntimeParameterPicker` 匹配 label/description/token/路径/别名并做 NFKC 归一（`runtime-parameters/catalog.ts:257-282`）、`lib/user-permissions.ts:41-55` 又有第四份 NFKC 归一实现。同一个平台里"搜索"这个词对用户意味着四件不同的事。

## 2. 目标

- **G1** 平台上**任何一个条目数够多的下拉框，打开即可直接打字搜索**，用户不需要记得"这个下拉支不支持搜索"。
- **G2** 触发是**共享原语的默认行为**，不是调用点的自觉：新写一个 `<Select>` 自动获得搜索，无需作者做任何事、也不需要 code review 逐个盯。
- **G3** 搜索**匹配面统一**：主标题、值、描述、分组名都能搜到；中英文、全角/半角、大小写差异不影响命中。
- **G4** 键盘操作全程连贯：打开即可打字，↑↓/Home/End/Enter 全程可用，Esc 一次清词、再一次关闭。
- **G5** 条目数少的小枚举（是/否、升序/降序）**保持现状**，不多顶一个搜索框、不丢失首字母跳转与空格选中。

## 3. 非目标

- **N1** 不改命令菜单类弹层（`UserMenu` 用户菜单、`canvas/ContextMenu` 画布右键菜单、`code/SymbolMenu`）。它们是命令菜单不是值选择器，加搜索会改变其交互定位。（用户 2026-08-25 明确划界：只覆盖选择器类控件。）
- **N2** 不引入服务端搜索。`Select` 的选项已经是前端内存数组，客户端过滤足够；`UserPicker` 的服务端搜索保持原样。
- **N3** 不做长列表虚拟化。仓内已有 `components/VirtualList.tsx`，但把它接进 portaled listbox 是独立的性能议题，另立 RFC。
- **N4** 不新增 `searchThreshold` 之类的每调用点旋钮。共享原语只保留一个二值逃生舱（显式 `searchable`），避免旋钮泛滥后又回到"各凭作者记性"。
- **N5** 不改 `Select` 的视觉样式。`.select__search` / `.select__search-input` 样式（`styles.css:21762-21784`）已存在且已在 25 处线上使用，本 RFC 只改"何时出现"。

## 4. 用户故事

- **US1** 管理员在设置页配置蒸馏模型。模型列表有 80+ 个条目分属 6 个 provider。他打开下拉、直接敲 `sonnet`，列表立刻收敛到 3 行。（今天：只能滚。）
- **US2** 工作流作者在画布 inspector 里给节点挑代理。团队有 40 个代理。他敲 `audit` 找到审计代理。
- **US3** 用户在"排序方向"下拉里选"降序"。这个下拉只有 2 项，**打开后和今天一模一样**——没有搜索框，敲 `j` 仍然跳到 `降序`，空格仍然选中。
- **US4** 中文用户在数字员工岗位下拉里敲输入法打"财务"，候选窗正常工作，列表按中文标题收敛。
- **US5** 用户在模型下拉里敲了 `claude` 后想看全量列表：按一次 Esc 清空搜索词、列表复原；再按一次 Esc 关闭下拉；**外层 Dialog 不会被一起关掉**。
- **US6** 用户记不住模型 id 但记得它属于 `anthropic`：敲 `anthropic` 能按**分组名**命中该组下所有模型。（今天分组名搜不到。）

## 5. 行为影响清单（breaking change 逐项呈确认）

本 RFC **不关闭任何既有能力**，因此不适用 CLAUDE.md §RFC workflow 第 7 条的"能力收缩型"附加门槛。但它把一个 opt-in 默认值翻成了条件默认，**128 个下拉的可见行为会变**，按同等标准逐项列出请用户确认：

| 编号   | 变化                                                                                                                         | 影响面                                     | 判断                                                                                                                                                                                                                                                           |
| ------ | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **C1** | 选项数 ≥ 8 的 `Select` 打开后**多出一个搜索输入框**，占据 listbox 顶部约 34px                                                | 128 处中条目数达标的那部分                 | 目标行为本身                                                                                                                                                                                                                                                   |
| **C2** | 搜索开启时**空格不再选中**当前高亮项（改为输入空格）                                                                         | 同上                                       | 用户 2026-08-25 已在四选一中明确拒绝"保留空格选中"（该选项会让搜索词不能含空格）                                                                                                                                                                               |
| **C3** | 搜索开启时**首字母 typeahead 失效**，由搜索取代                                                                              | 同上                                       | 二者语义重叠，保留两套会出现"敲 a 跳转 vs 敲 a 过滤"的分裂                                                                                                                                                                                                     |
| **C4** | 搜索开启时 DOM 焦点落在搜索输入框（而非 listbox）                                                                            | 同上                                       | **中文输入法的硬约束**：IME 只能向获得焦点的可编辑元素合成文本。视觉上仍是"列表里有一行高亮、↑↓ 移动它"，`aria-activedescendant` 保证屏幕阅读器播报的仍是当前选项；这也是 WAI-ARIA 1.2 combobox+listbox 的标准形态，且与已上线的 25 处 searchable 行为完全一致 |
| **C5** | Esc 语义变为两段（有词→清词、无词→关闭）                                                                                     | 全部 searchable 下拉，**含已上线的 25 处** | 新增能力，不减少能力；无词时与今天逐字相同                                                                                                                                                                                                                     |
| **C6** | 选项数在 8 附近浮动的下拉，搜索框会随数据出现/消失                                                                           | 少数动态列表                               | 阈值方案的固有代价。替代方案（全部常显）已被用户否决，因为它会让 2 项的下拉也顶一个搜索框                                                                                                                                                                      |
| **C7** | `Select` 匹配面从 `label+value` 扩到 `+description +group`；`MultiSelect` 从 `label+value+description` 加上 NFKC/locale 归一 | 已上线的 25 处 + 17 处 MultiSelect         | 只会**多命中**、不会少命中；US6 依赖它                                                                                                                                                                                                                         |

**不变的**：`Select` 的 props 签名向后兼容（`searchable?: boolean` 语义不变，只是省略时的默认值变了）；三态空行（无可用选项 / 无匹配 / 全部不可用，RFC-250）契约不变；禁用项键盘契约不变；分组表头渲染不变；`renderOption` / `renderValue` / `renderUnknownValue` 不变。

## 6. 验收标准

- **A1** 一个 8 项的 `Select` 打开后渲染搜索框；一个 7 项的不渲染。阈值常量从 `Select.tsx` 导出，且有测试钉死它等于 8。
- **A2** 显式 `searchable={false}` 在 20 项上仍不渲染搜索框；显式 `searchable` 在 3 项上渲染。逃生舱双向有效。
- **A3** 搜索命中 `description`；搜索命中 `group`（分组名）。
- **A4** 归一化生效：`ＡＢＣ`（全角）能被 `abc` 命中；大小写不敏感；中文标题能被中文子串命中。
- **A5** 搜索开启时敲 Esc：有词 → 词被清空、下拉**仍开着**、列表复原全量；无词 → 下拉关闭、焦点回到 trigger；两种情况都**不会**把外层 Dialog 一起关掉。
- **A6** 7 项的下拉上，首字母 typeahead 与空格选中**照旧工作**（锁 G5 不被误伤）。
- **A7** `Select` 与 `MultiSelect` 走**同一个**匹配纯函数；全仓不再存在手写 `searchable={...length > N}` 形态（源码棘轮断言）。
- **A8** `ModelSelect` 在 8 个以上模型时自动获得搜索（US1 端到端）。
- **A9** CI 全绿。已抽查的四个高相关锁测（`select-searchable.test.tsx` 用 3–4 项、`select-groups.test.tsx` 用 5 项、`kind-select.test.tsx` 的 `OUTPUT_KIND_UI` 只有 4 个条目、`model-select.test.tsx` 最多 4 个模型 + 2 个哨兵行）选项数**都在阈值以下**，预期零改动通过——这也是阈值取 8 而非更小值的直接理由之一。若实现期发现个别用例因选项数达标而必须调整，**须在 `plan.md` §变更记录里逐条写明是哪条、为什么，不得静默改测试**。
