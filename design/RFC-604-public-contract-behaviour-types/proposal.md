## 1. 背景

S9 的类型污染检测器（`rfc294-architecture-preflight` 的 `PUBLIC_SURFACE_DEBT`）在 HEAD 上余 27 条。其中 8 条是行为类型，检测器把它们一律记为债：

- **平台日志器（4 条）**：runtime-management 的材料编译与材料证据、source-control 的隔离工作区、task-execution 的系统代理运行，四个合同带着调用方的
  `Logger`。检测器禁止 public 合同引用 `@/platform/*` 的任何类型。
- **函数类型（4 条）**：
  - 方法参数位置的回调与借出式参数：隔离工作区的写窗口、合并时的子冲突解析、丢弃进度，仓库 Git 工作区的预览索引，工作区维护效果的“任务是否在物化”判定。
  - 输入对象里函数类型的成员：准备 / 草稿工作区效果的 `assertCurrent` 与 `checkpoint`、冲突解析的 `runAgent`、实时采集的 `getRootSessionId` 与
    `onInsert`。

前一类是检测规则过宽：平台日志器是纯行为接口，不暴露存储或传输机制；方法参数里带类型的回调本来就是方法签名的一部分。后一类与 RFC-569 收掉的五条同形：
函数类型的成员改写成方法签名，就是检测器认可的闭合形态。

## 2. 目标

- **G1（规则一）**：`@/platform/logging/logger` 的 `Logger` 是指定的平台合同接口，public 合同可以引用，检测器不记债、也不展开它的声明。其他平台类型照旧禁止。
- **G2（规则二）**：方法、调用签名、构造签名或函数声明的参数，其类型是函数类型时算闭合：检测器不记债，但照旧检查这个回调的参数与返回类型。其他位置的函数
  类型照旧记债：属性、返回值、联合成员、类型实参等。命令的输入是 DTO，其中的回调是属性，所以“命令不收回调”（design §3.3）不变。
- **G3（统一收法）**：输入对象里函数类型的成员改写为方法签名（RFC-569 的做法）。调用方传的对象字面量不变，没有行为变化。
- **G4**：上述 8 条离开 `PUBLIC_SURFACE_DEBT`（27 → 19），`counts.json` 的 `public-surface-deviations` 同一提交降到 19；其余计数不升。
- **G5**：两条规则各有正反用例。

## 3. 非目标

- 余下的 19 条：
  - 不透明身份引用 `object`、`CommittedEventRef`、有限键的映射类型与 `unknown` DTO，另立。
  - 能力 / 凭据 / 身份一族，等 RFC-546。
- 不改任何日志内容、回调时机或调用方的行为。

## 4. 能力影响清单

无。只改检测规则与类型的写法。

## 5. 用户可见变化

无。

## 6. 验收标准

- **AC-1**：检测器对 `Logger` 与方法参数位置的函数类型不再记债；对其他平台类型、属性 / 返回值位置的函数类型、回调参数里的开放类型照旧记债（正反用例）。
- **AC-2**：7 处函数类型成员改为方法签名，`tsc` 通过，调用方不改。
- **AC-3**：`PUBLIC_SURFACE_DEBT` 去掉这 8 条，与检测结果逐条相等；`counts.json` 同步降到 19。
- **AC-4**：受影响用例全部通过；推送后 exact SHA 的 GitHub Actions 全绿（环境性红格逐格归因、如实记录）。
