## 2. 数据契约

### 2.1 决定状态

`packages/shared/src/schemas/clarifyDecision.ts` 的 `status` 由 `'decided' | 'provisional'` 扩为：

```ts
status?: 'decided' | 'provisional' | 'deferred' | 'not-applicable'
```

- `deferred`：暂不决定。`not-applicable`：不适用。两者合称「跳过状态」，导出判定函数 `isClarifySkipStatus(status)`。
- 状态轴的含义是「这项决定现在处于什么状态」，四个取值互斥：已定、暂定、有意留空、不需要决定。不另设字段，避免出现「已决定且不适用」这类矛盾组合。
- 说明文字复用 `rationale`。界面按状态换标签（「我的依据」/「为什么不适用」/「还缺什么才能决定」）。

`decision` 对象已贯通全部答案复制点（HTTP 草稿与提交、MCP `save_clarify_draft`、轮次 DTO、封存、归属比较、追问上下文、最终提示词、图驱动研发的 clarify 来源），因此只改这一处枚举即可贯通；不需要逐处加字段。

图驱动研发（RFC-396）对 `decision` 的运行时处理只有透传与展示（`executionConsumption.ts:57-74`、`implementationBasis.ts:98-103`），不按状态分支；`DecisionReadback` 新增两条文案即可显示。跳过的回答作为人的来源导入时没有选项也没有自定义文本，状态就是它的全部内容，因此图文档的校验（`graphDesign.ts:47`、`:85`）随枚举一起放宽。

但有一处文本受枚举牵连，必须单独处理（实现阶段发现，初稿此处写的「无行为影响」是错的）：内置的图设计代理与图澄清代理把设计输出的 JSON schema 原样印在提示词里（`builtinResources.ts:25-29`、`:51`、`:62`），而内置代理一经发布即不可变，启动时逐字节比对已安装副本，不一致就抛 `graph-builtin-agent-content-conflict` 并中止启动（`builtinCatalog.ts:79-87`）。枚举变宽会改写这两段提示词，已安装过 v0.19.3 的实例升级后将无法启动。处理：

- 印进内置提示词的 schema 文本保持发布时的两个取值（`graphOutputInstructions` 在输出前把决定状态枚举收回到已发布的取值）；校验用的 schema 接受四个取值。两者只差这一处枚举。
- 这两个代理从不自己写人的决定，只把平台导入的来源原样带过，因此提示词不列新取值不影响功能。
- 按请求现拼的辅助提示词（`viewPlanning.ts:45-57`）不是已发布文本，随校验一起列出四个取值。
- 回归用例锁定四个内置代理提示词的逐字节摘要（取自 v0.19.3 的干净导出），今后任何 schema 变更若渗进已发布提示词，CI 会先于用户的启动发现。

### 2.2 规范形式：真实回答优先

一条回答同时带有跳过状态和真实回答（任一选项，或非空的自定义文本）时，**真实回答生效，跳过状态作废**。这是全系统唯一的裁决，由 shared 的一个函数表达：

```ts
withoutStaleClarifySkip(answer)   // 带真实回答时去掉跳过状态，其余原样返回（同一引用）
clarifySkipStatus(answer)         // 没有真实回答且状态为跳过时返回该状态，否则 undefined
```

去掉的只有 `status`；`rationale` 等用户写下的文字保留。

规范形式在以下位置生效，覆盖全部写入口：

| 位置 | 做法 |
| --- | --- |
| `clarifyAnswerBasis`（`clarifyMindmap.ts:46-54`） | 对规范形式求确认依据，因此客户端是否先归一不影响确认是否成立；没有 `decision` 的历史答案哈希逐字节不变 |
| `isClarifyAnswerValid`（`clarifyMindmap.ts:65-77`） | 跳过状态生效（`clarifySkipStatus` 有值）时有效；否则按原判定。「跳过状态 + 选项」按普通回答判定 |
| 服务端草稿保存 `saveClarifyDraft`（`clarifyRounds.ts:527-531`，HTTP 与 MCP 草稿的共同入口） | 落库前归一 |
| 服务端封存 `sealAnswersServerSide`（`clarify/service.ts:759-796`，整轮提交、逐题封存、改答的共同入口） | 落库前归一 |
| 前端两个写入口：`clarify.detail.tsx:432` 与 `CentralizedAnswerDialog.tsx` 的 `updateAnswer` | 写入本地状态前归一，界面即时一致 |

因此库里不会出现矛盾组合，读取方（最终提示词、看板、图驱动研发、只读摘要）不需要各自处理。

服务端整轮提交的校验（`clarify/seal.ts:269-285`）调用同一个 `isClarifyAnswerConfirmed`，随 shared 生效：已确认的跳过回答可以提交，未确认的照旧拒绝。

### 2.3 最终提示词

`packages/shared/src/clarify.ts` 的 `summariseClarifyChoice` 在「无选项且无自定义文本」分支之前增加两种文案：

- `User marked this question as not applicable.`
- `User deliberately left this question undecided for now.`

原「User did not answer this question.」只用于真正未回答。`summariseClarifyDecision` 不改，状态与说明照常输出。

提示词预算很紧（`packages/shared/tests/rfc378-decision.test.ts:55-95` 与 `:339`：提问指导加示例的预算 3350，实测 3264；停止提示的增量预算 2500，实测 1570），因此：

- 不改 `CLARIFY_MINDMAP_QUESTION_GUIDANCE` 与格式示例。
- `buildClarifyStructuralRules(true)` 末句追加一句（仅脑图分支）：不适用的题不再重问，暂不决定的题保持开放。
- `CLARIFY_DECISION_OUTPUT_GUIDANCE` 追加一句：不适用的题不在范围内；暂不决定的题列为未决事项；两者都不是选择，不得替用户选定。
- 追问提示词（`clarifyFollowup.ts:101-103`）首段追加一句：不要重问标为不适用的题。

### 2.4 题目来源

`ClarifyQuestionMindmapSchema`（`packages/shared/src/schemas/clarifyMindmap.ts:40-46`）增加两个可选字段：

```ts
requestTarget: z.enum(['question', 'category', 'root']).optional()
requestInstruction: z.string().check(utf16MaxLength(2000)).optional()
```

`clarifyFollowup.ts` 的 `generate()` 写入追加题时：`requestTarget` 一律写入（按请求的目标：题、非空分类路径、空路径）；`requestInstruction` 仅在请求的指引非空时写入，保存的是请求里的原始指引（可能带「引用」包装，前端用既有 `restoreMindmapFollowup` 拆开显示）。

这两个字段随题目进入问题集合摘要与追问上下文；两端都从同一份已保存问题计算，判定不受影响。旧题没有这两个字段：有父题的只显示父题与回答，没有父题的不显示来源卡。

### 2.5 任务看板摘要

任务问题看板的回答摘要（`taskQuestions.ts:456-469`）对「无选项且无自定义文本」返回空，跳过并封存的题在看板上会什么都不显示（`TaskQuestionList.tsx:487-489`）。看板条目增加可选字段 `answerSkip: 'deferred' | 'not-applicable'`（由 `clarifySkipStatus` 得出），`answerSummary` 此时取用户写的说明（没有则为空）；前端显示本地化的「不适用」「暂不决定」加说明。字段只进看板 DTO，不进任何提示词。

## 3. 后端：空分类补题

`clarifyFollowupStore.ts:62-67` 现在把「目标分类下没有任何问题」视为不存在。改为：

- 目标是非空分类路径、该路径下没有问题、它是冻结配置中某条预设路径的前缀（含相等）、且本轮是首轮（`round.iteration === 0`）时，视为有效的空分类目标。
- `canAppend` 对空分类目标要求轮次仍在等待、任务未结束，且本轮还有未封存的问题。空分类自己没有可封存的题，因此随整张图：与「对整体补充」在全部问题封存后关闭的既有规则一致，前端同样处理。
- 其余目标的判定不变；不在配置里的空路径、以及非首轮的空路径仍返回 `clarify-question-not-found`。

限定首轮的原因：每一轮是独立的一张图（proposal 非目标），后续轮次里「本轮没有题」的分类可能早在前面的轮次问过，把它当缺口会误导；追问上下文也不带前面轮次的问答。前端同样只在首轮显示空分类与对应建议（§6.4、§6.5）。轮次序号按（中间节点、循环迭代）计：循环包装内每次迭代重新开始一场澄清，其第一轮同样算首轮。

空分类的追问上下文为空数组，两端的依据摘要一致。新题的分类路径取请求路径（`clarifyFollowup.ts:169-173` 既有分支）。追问提示词仍带原任务背景与预设分类；为避免与其他分类的题重复，请求 JSON 增加 `existingQuestionTitles`（本轮全部题目标题），仅用于空分类目标，不进入依据摘要。

## 4. 前端信息架构

### 4.1 工作区

`MindmapWorkspace` 的状态不变（视图、选中、相机、折叠、搜索、追问草稿），变化如下：

- 删除全景用的 `Dialog`。舞台内部改为一个容器 `.mindmap-workspace__panes`，放画布和面板两个子项。全景且面板打开时为两列网格：画布 `minmax(0, 1fr)`，面板 `clamp(420px, 46%, 620px)`。聚焦视图沿用同一个面板元素、占满舞台。
- 并排还是占满由工作区量得的舞台宽度决定（同一个量取值也用于列数，§5.1），写成容器上的 `data-split="side" | "full"`，样式只认这个属性：舞台宽度大于 760 为并排，否则面板占满、画布隐藏。量不到宽度（未挂载、舞台为 `display: none`）时保持上一次的结果；从未量到时按并排处理。
- 面板是工作区内的常驻区域（`<section>`，带可访问名称），不是弹层：没有遮罩、不锁滚动、不设焦点陷阱，因此不走 `Dialog`，也不新增弹层外壳样式。
- 移动端三页签不变：点节点切到「回答与确认」页签。

焦点与 Esc：

- 由指针点击画布节点或点「下一个待处理」打开的题，焦点交给答题区（数字键可用）。
- 目录行无论用指针还是用回车 / 空格激活，都只选中并打开面板，焦点留在目录行（方向键可继续浏览）。
- 面板打开且处于全景视图时，焦点在工作区内任何位置按 Esc 都关闭面板；子控件已处理的 Esc（追问表单、选区追问、下拉、搜索框）不再触发。关闭时若焦点在面板内，回到打开它的元素（目录行或画布）；该元素此刻不可见时（例如手机上已切走的目录页签）依次退到画布、工作区。焦点本来就在面板外则不动。焦点在面板收起之后才交还：面板占满舞台时画布未渲染，无法提前接收焦点。

### 4.2 面板开合与视口

面板在画布右侧并排出现，画布因此变窄。相机规则（纯函数 `panelResizeCamera`，`lib/clarify/mindmap/geometry.ts`；由画布在尺寸变化回调里调用，`MindmapCanvas.tsx:122-133`）：

- 由面板开合引起的宽度变化不移动相机（画布左边缘不动，内容不跳）。其他原因的尺寸变化沿用现有的居中保持（`resizeMindmapCamera`）。
- 打开时，若被选中节点的卡片原本与可视区有交集、而变窄后右边缘超出可视区（留 16 边距），相机向左平移刚好让它露出，且不把卡片左边缘推出可视区。记下这次平移。
- 关闭时，若用户期间没有自己平移或缩放过画布，相机回到面板打开时的位置（打开时的那次平移随之撤销）；用户自己动过则保持用户当前的位置。
- 面板打开期间发生过定位（搜索、下一个待处理、确认并下一题）的，关闭时在回到原位置的基础上按全宽再定位一次被选中的节点：它在原视口里看得见就不动，看不见才移过去。这与没有面板时定位的效果相同，避免地图停在为窄画布居中的偏左位置。
- 面板占满（画布隐藏）时画布尺寸回调为零宽、被忽略，相机不变。

因此：打开面板不改变缩放；多数情况下不改变相机；关闭后画布尺寸复原，相机复原（除非用户期间自己移动过，或期间定位到了原视口之外的节点）。选中节点本身仍不平移画布，面板打开期间点别的节点也不平移。显式定位（搜索、下一个待处理）沿用现有 `revealMindmapPoint`，尺寸回调同步更新可视区引用，保证定位按变窄后的宽度计算。

这是对 RFC-372「弹窗开关不改变画布尺寸与相机」的替换，列为 proposal §4 的 C11。

小地图的窄屏规则（`mindmap.css:515-537`）以容器 `mindmap-stage` 为准。该容器声明从舞台（`mindmap.css:247-252`）移到画布所在的格子上，规则因此按画布的实际宽度生效；规则文本不变。

### 4.3 面板

`MindmapQuestionPane` 自上而下：

1. 工具栏：返回脑图、转到聚焦作答（仅并排时）、折叠子项。
2. 分类面包屑。
3. 来源卡（§6.6）。
4. 题号、状态、子题待处理数、生成中提示。
5. 标题。
6. 原 `QuestionForm`。
7. 跳过行（见 §6.2），其下是其余补充字段的折叠区（见 §6.1）。
8. 追问出的问题：直接子题列表，带状态，可跳转（仅题目节点）。
9. 追问行与追问表单（见 §6.3）。
10. 操作栏（固定在面板底部，不随内容滚动）：面板有余量时先是「我的依据」与决定成熟度（跳过后改为跳过说明），再是确认并下一题、确认这个回答、下一个待处理。有余量指舞台高度不小于 560 且面板宽度不小于 460（依据与成熟度能排成一行）。没有余量时（手机、1024×768、1440×900 下 420 宽的并排面板等）操作栏只留按钮，依据、成熟度与跳过说明回到第 7 项的位置随内容滚动，把高度让给选项。

分类与根节点：任务输入（仅根，默认折叠）、计数、下一步建议（仅根）、补充提问方向、子项列表。

主操作与回车：

- 「确认并下一题」确认本题并打开下一道待处理的题；没有下一道时只确认。「确认这个回答」只确认、停留在本题。
- 回车等同主操作。它由面板在答题区与操作栏（表单、依据与成熟度）上统一处理：仅当焦点不在按钮、链接、下拉、多行输入框上，且不处于输入法组合中时生效；回答无效时不动作。`QuestionForm` 自身的回车与数字键逻辑不接入脑图（脑图模式下路由不传 `onAdvance`，数字键选中后不会自动前进），避免选中与确认在同一拍里用到旧值。
- 既有约束保持：脑图不显示普通问答的键盘提示条，回车不会绕过确认。

### 4.4 路由与周边

`clarify.detail.tsx` 新增三项只读数据并下传：

- 预设分类路径：冻结快照里本轮中间节点的 `mindmap.categories`，经 `clarifyCategoryPaths` 展开；非首轮传空数组。
- 任务输入：任务详情的 `inputs` 配上快照 `inputs[]` 的标签，显示在根节点面板。
- 脑图模式的两个精简开关：`ClarifyQuestionHandler` 在只有一个可选处理节点时不渲染下拉；`QuestionForm` 的自定义输入框在未选「其他」（单选）或未勾选补充说明（多选）时不渲染。普通问答不传这两个开关，行为不变。

`QuestionForm` 另加一个可选属性 `intentResetToken`：取值变为非空时清掉「已点其他但还没输入」的本地意图。路由在脑图模式下传当前回答的跳过状态，因此标为跳过后「其他」不会仍显示为选中；跳过被撤销（取值回到空）时不清，避免在「其他」里边输入边撤销跳过时输入框被收走。

已封存轮次的页脚：除「查看决定摘要」外增加「查看任务结果」，链接到任务详情页。

目录（`MindmapOutline`）：

- 首轮的空分类行显示「尚无问题」。
- 搜索范围由题目与分类名扩大到选项文字、推荐理由和我的回答（选中的选项、自定义文本、依据）。命中不在标题里时，行内显示一行命中片段（截取命中处前后文）。

## 5. 布局与绘制

### 5.1 列数

`mindmapColumns(stageWidth)`（纯函数，`lib/clarify/mindmap/layout.ts`）：

```
列数 = clamp(1, 5, floor((stageWidth / 0.85 - 48 - 40 + 32) / (236 + 32)))
```

0.85 是可读比例，236 是卡宽，32 是列间距，48 是两侧留白，40 是为两层换行竖线预留的宽度（§5.2）。舞台 830 得 3 列，1150 得 4 列，458 与 358 得 1 列；5 列需要舞台不小于 1187。

列数由工作区量取舞台宽度得到（面板开合不改变舞台宽度，因此不触发重新布局），随布局请求传给 Worker，并进入布局键；列数变化时重新布局，沿用 `preserveMindmapAnchor` 保持选中节点的屏幕位置。

首次量取：工作区在首次绘制前同步量一次舞台宽度，量到之前不挂载画布，避免先按错误列数布局一遍。量不到（舞台为 `display: none`，例如移动端初始不在脑图页签；或环境没有布局）时用窗口宽度代入同一公式估算；之后量到非零宽度再更新，零宽度的回调一律忽略。

### 5.2 换行规则与宽度预算

每个节点有一个可用宽度。根节点的可用宽度为 `列数 × 236 + (列数 - 1) × 32 + 40`；有两个及以上子项的节点，其子项的可用宽度为自身可用宽度减 20（不小于 236）；只有一个子项时原样下传。

对每个节点的子项按顺序排行：

- 全部子项（各取其子树宽度，加间距）不超过节点的可用宽度：排成一行，在父节点下方居中横排，贝塞尔连线，与现状相同。
- 否则换行：行宽上限为可用宽度减 20；加入下一个子项会超过上限且当前行非空时另起一行。各行左对齐；子块左侧留 20 宽放竖线；行与行之间留 28。父节点在整个子块上方居中。

子树宽度取节点自身与子块宽度的较大者；子树高度为节点高度加 28 加子块高度。

由此，列数不小于 2 且可用宽度未触底（236）时，整张图的宽度不超过根的可用宽度，在可读比例下不需要横向平移即可看到每一行；布局关于根节点左右对称，与可读比例的初始相机（根节点水平居中）一致。列数为 1 或层级深到可用宽度触底时，每多一层换行多出 20 宽，需要时横向平移。

遍历仍是迭代式，不使用递归：一遍自顶向下确定次序与可用宽度，一遍自底向上排行，一遍自顶向下定位。

### 5.3 连线

多行子块的连线：每行一条横线，从左侧竖线到该行最后一个子项的中点；第一行的横线同时覆盖父节点中点下方，父节点底部中点向下接到这条横线；竖线连接各行横线；每个子项从横线向下一小段接到卡片顶部。横线与竖线用中性色，接到卡片的小段沿用子项状态色。

布局结果增加 `blocks`（每个多行父节点的竖线位置与各行横线位置、子项），由绘制读取。命中测试不变。

### 5.4 卡片

- 题卡 236×136：首行「题号 · 状态」，右侧是决定成熟度（首行放不下时让位给题号与状态）；标题两行；回答摘要两行；有待处理的子题时底行显示数量。跳过的题以「不适用」「暂不决定」作为回答摘要。
- 分类卡 236×64 不变；空分类用虚线边框，底行显示「尚无问题」，不带状态标记；悬停提示与「突出待处理」都不把它当作已完成。
- 缩略模式（缩放低于 0.6）的题目标签前加题号。
- 画布帮助文字加半透明底色，节点经过其下方时文字仍可读。

卡片高度保持固定常量，回答与确认只改内容、不改尺寸，因此不触发重新布局（RFC-372 L14）。

### 5.5 可观察量

画布外层元素带四个只读属性，供浏览器内断言布局与视口，不参与任何逻辑：`data-columns`（列数）、`data-world-width` 与 `data-world-height`（布局包围盒，取整）、`data-camera`（`x,y,zoom`，随绘制更新）。

## 6. 思考引导

### 6.1 就地决定

`DecisionDetails` 增加 `layout` 属性。`inline` 布局把「我的依据」单行输入和成熟度三选一放在折叠区之外，其余四个字段留在折叠区；选「暂定」或其余字段已有内容时折叠区默认展开。`inline` 布局可以分成两部分渲染：脑图面板有余量时（§4.3 第 10 项）把依据与成熟度放在操作栏上、紧挨确认按钮（真实浏览器验收发现放在选项下方时，选项稍长就要滚动才看得到，起不到「就地」的作用），折叠区留在选项下方；没有余量时两部分都留在选项下方（验收实测：固定在操作栏时，手机上可读区域不足一百像素，1440×900 的并排面板只剩约 295 像素）。默认布局不变，供普通问答与集中回答弹窗继续使用；默认布局遇到跳过状态时三选一按「未标注」显示。

### 6.2 跳过

题目下方一行两个小按钮：「这题不适用」「暂不决定」。点击后一次写入：清空选项与自定义文本、置状态、按新内容计算确认依据（跳过即确认）。此时隐藏成熟度三选一与折叠区，显示「已标为：不适用」、说明输入框与「恢复作答」。

- 跳过状态下编辑说明：每次写入同时重算确认依据，题目始终保持已确认，不会因为补一句说明而重新变成待确认。
- 恢复作答：取回跳过之前的回答原样（选项、自定义文本、成熟度与依据；工作区在本次页面会话内记住每题跳过前的回答），题目回到待确认。跳过期间写的说明是用户的文字，不会无故丢掉：跳过前没写依据时它保留为依据；跳过前已有依据时以原依据为准。刷新页面后没有可恢复的内容，恢复作答得到未回答的题，说明同样保留。
- 在跳过状态下直接选择选项或输入自定义文本：按 §2.2 自动撤销跳过。

### 6.3 追问

题目下方一行：`追问：` 加四个按钮。前三个把指引模板填入输入框并展开表单，第四个只展开表单。表单标题「追问 Qn」，提交按钮「生成追问」。分类与根节点的表单标题「补充提问方向」，提交按钮「生成问题」。操作栏不再有追问按钮。

### 6.4 空分类

`projectClarifyMindmap` 增加参数「预设分类路径」。对每条预设路径的每个前缀，若还没有对应分组就补一个；子树内没有任何问题的分组标记 `empty`。空分组不计入任何状态计数。目录行显示「尚无问题」；面板里显示补充提问方向表单（轮次可编辑时）。画布上的单链压缩规则不变。

预设路径进入画布的拓扑修订值（`topologyRevision`），否则冷加载时配置晚于问题到达会缺少空分类节点。非首轮不传预设路径，行为与现状一致。

### 6.5 下一步建议

纯函数 `suggestMindmapSteps`（`lib/clarify/mindmap/suggestions.ts`），输入问题、答案、已封存集合、预设路径，输出有序建议：

| 类型 | 条件 | 动作 |
| --- | --- | --- |
| `empty-category` | 预设分类下没有问题（只报最深的空路径；仅首轮） | 打开该分类面板 |
| `deferred` | 存在暂不决定的题（合并为一条，带数量） | 打开第一道 |
| `provisional-unplanned` | 暂定且缺验证负责人或复核时机 | 打开该题并展开补充字段 |
| `recommendation-unexamined` | 选了推荐项、没写依据、也没有子题 | 打开该题并填入「检查依据」指引 |
| `no-rationale` | 已回答（非跳过）但没写依据（合并为一条，带数量；已计入上一类的题不重复计） | 打开第一道 |

已封存的题不参与。界面最多显示 6 条，其余折叠成「另有 N 条」。建议只是提示，不阻塞提交。

### 6.6 来源卡

| 题目 | 显示 |
| --- | --- |
| 追问某题得到（`requestTarget = 'question'`，或旧数据里带父题） | 父题题号与标题、我对父题的回答摘要、保存的指引（有则显示）；「查看 Qn」跳转 |
| 在分类下补充得到（`'category'`） | 「来自你在〈分类路径〉下的补充提问」，加保存的指引（有则显示） |
| 对整体补充得到（`'root'`） | 「来自你对整体的补充提问」，加保存的指引（有则显示） |
| 模型原始提出且有父题 | 父题题号与标题、我对父题的回答摘要 |
| 其余 | 不显示 |

更深的祖先仍在可展开的路径里。

### 6.7 复核

纯函数 `reviewMindmapDecisions`（`lib/clarify/mindmap/review.ts`）输出汇总与分组：

- 汇总：题数、已确认、暂定、未标注（已回答但没标成熟度；未回答的不算）、不适用、暂不决定、没写依据。
- 分组：按题目所在分类路径（子题跟随其根父题），组内按树序，子题带深度。
- 「需要留意」：未确认、暂定、暂不决定、已回答但没写依据。

`DecisionReviewDialog` 用它渲染；提交选项区用 `position: sticky` 固定在滚动区底部。

## 8. 失败模式

- 空分类补题被拒（配置已变、轮次已结束或不是首轮）：沿用追问失败的展示与重试。
- 列数变化时布局 Worker 失败：沿用现有降级提示，聚焦视图可用。
- 旧页面提交带跳过状态的回答到旧服务端：不存在此组合（前后端同一二进制）。
- 协作者同时改同一题：沿用逐题最后写入生效；跳过状态与真实回答的裁决由 §2.2 在服务端落库前统一完成。
- 外部写入方（MCP）送来「跳过状态 + 选项」：按 §2.2 归一为普通回答，不报错。

## 10. 偏离与债

无偏离项。留下的事项：

- 真人试用观察未做（proposal §6）。
- 缩略模式下的标签宽度仍受卡片间距限制；本 RFC 通过换行和可读比例解决常见规模，不处理「一屏看完上百题全文」。
- 空分类提示与补题只在首轮提供；跨轮次的覆盖情况判断与带上前序问答的补题留待后续。
- 恢复作答只在本次页面会话内取回跳过前的回答。

真实浏览器验收（干净导出构建的二进制，录制的真实模型场景）另做了两处调整，均已补用例：

- 依据与成熟度原先放在选项下方，选项带说明和推荐理由时要滚动才看得到；面板有余量时改放到操作栏上、紧挨确认按钮，没有余量时仍在选项下方（§4.3、§6.1）。
- 面板打开期间用「确认并下一题」等定位过节点后关闭，地图会停在为窄画布居中的偏左位置；关闭规则改为回到打开时的位置，必要时按全宽再定位一次（§4.2）。
