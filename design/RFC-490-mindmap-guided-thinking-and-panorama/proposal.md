# RFC-490：脑图澄清的思考引导与全景交互重整

> 状态：In Progress（2026-11-12 落档）。
> 来由：用户 2026-11-12 要求审视脑图设计功能，审视结论与建议清单已在当次会话呈给用户；用户随后以目标指令「按你的建议完整实现所有修改」要求把审视建议全部落地。
> 批准依据：上述目标指令是在看过建议清单之后下达的实施指令，本 RFC 的范围即该清单（含清单里对 2026-10-13 两项既有决定以及 RFC-372 视口约定的替换，见 §4 的 C1、C2、C11），按该指令记为已批准，不另设批准等待。§4 能力影响清单在交付时逐项回报，任何一项用户不认可都可单独撤回。
> 审视建议分两类：单点缺陷直接修（不走 RFC，已提交 `0df2df21e`）；其余按本 RFC 落地。
> 前序合同：[RFC-372](../RFC-372-mindmap-clarify/proposal.md) 的轻量合同、[RFC-378](../RFC-378-mindmap-decision-review/proposal.md) 的决定补充与复核合同继续有效，本 RFC 只做下列增量。

## 1. 背景

2026-11-12 的审视在本机隔离实例上用真实模型录制的 9 题数据库设计场景走完了全程（作答、三种追问、失败重试、复核、提交、结果页，1440 / 1024 / 390 三种宽度），结论有三条：

1. 预期功能已完成、全程可用，另有几处与合同不符的单点缺陷（已另行修复）。
2. 能如实记录思考，但默认路径引导的是「逐题点选」，不是「逐步设计」。
3. 目录与聚焦作答顺手；全景脑图本身是最大短板，另有若干失效或藏起来的入口。

第 2、3 条的实测依据：

| 现象 | 实测 |
| --- | --- |
| 不写一个字就能产出一份设计 | 每题 3 次点击；前 3 题确认后界面即提示「可以复核决定」；「决定补充」默认折叠，排在选项和自定义输入框之下；复核弹窗不提示哪些决定没有写依据 |
| 不能跳过题，探索有代价 | 提交要求每道题都回答并确认，每次追问都会带来必须处理的新题 |
| 「逐步」要靠用户自己发起 | 首轮只问 2～3 题；预设分类没出题时不上图，看不出缺口；全部确认后只提示可以复核 |
| 思考时缺上下文 | 页面不显示原始需求；子题不显示父题的回答和触发它的追问指引；父题不列出追问出的子题 |
| 全景图装不下题 | 7 题时可读比例只看得到约 3 张题卡；9 题「适应全图」为 34.9%，标签只剩两三个字；1024×768 下画布只有 458×480，首屏几乎全是分类框 |
| 点任何节点都弹全屏弹窗 | 浏览地图变成反复开关弹窗，无法边看图边看题；「新增 N 题」的提示出现在弹窗背后 |
| 入口和叫法太多 | 同一个追问在界面上有五种说法 |
| 复核弹窗是扁平长列表 | 9 题内容高 2068px、可视 621px；不按分类分组；提交选项在最底部 |

## 2. 目标与非目标

### 目标

- **G1 就地写依据。** 选完答案后，直接给出一行「我的依据」和决定成熟度，不必展开折叠区；面板够高够宽时它紧挨确认按钮、不必滚动，否则（手机、小屏上的并排面板等）在选项下方。其余补充字段保留在折叠区。
- **G2 可以跳过。** 每道题可一键标为「不适用」或「暂不决定」，可附一句说明；跳过的题算已处理，不再阻塞提交；最终结果如实保留这两种状态；任务问题看板同样显示。
- **G3 上下文跟着题走。** 子题显示父题、我对父题的回答以及当时的追问指引；父题列出它追问出的子题；工作区可查看原始任务输入。
- **G4 看得见缺口。** 首轮里，预设分类即使还没有问题也显示在目录和画布上，并可直接让 AI 在该方向出题。后续轮次不提示（每轮是独立的一张图，本轮没有题的分类可能早已问过）。
- **G5 给出下一步。** 全部现有题处理完后，界面列出值得再想的地方（空分类、暂不决定的题、缺验证安排的暂定项、直接采用推荐而未写依据的题、没写依据的决定），每条可一键到位。
- **G6 复核看得出重点。** 复核弹窗顶部汇总各类数量，可只看需要留意的项，按分类分组，提交选项始终可见。
- **P1 全景装得下。** 题卡改紧凑；同级过多时换行；按画布宽度自适应列数；窄屏退化为单列。
- **P2 点击不再弹全屏弹窗。** 全景点击节点改为选中并在右侧面板显示，画布保持可操作；宽度不足时面板占满工作区。面板开合不改变缩放，关闭后视口复原。
- **P3 一个概念一个说法。** 追问只有「追问」一个名字；补充「确认并下一题」与回车确认。
- **P4 去掉题内杂项。** 只有一个可选处理节点时不显示处理节点下拉；未选「其他」时不显示自定义输入框。
- **P5 搜得到答案。** 目录搜索同时匹配选项文字和我的回答。
- **P6 找得到结果。** 已封存的轮次提供「查看任务结果」入口。

### 非目标

- 不让 AI 回答问题或解释选项。追问仍只生成选择题（RFC-378 既有边界）。
- 不提供自由添加节点、删题、合并、拖拽重排。
- 不把多轮澄清合并成同一张图；每轮仍是独立的一张图。
- 不改变提交、封存、派发与任务续跑的机制，不新增数据表与迁移，不新增模型调用。
- 不改普通问答模式的界面与行为（两处共用组件的行为变化见 §4）。

## 3. 用户流程

### 3.1 作答

打开一道题，焦点落在答题区。选择选项后出现「我的依据（选填）」单行输入和「未标注 / 已决定 / 暂定」三选一：面板够高够宽时在底部操作栏上、紧挨确认按钮、不随选项滚动；否则（手机、小屏上的并排面板等）在选项下方。选「暂定」时自动展开选项下方的其余补充字段。主按钮为「确认并下一题」，另有「确认这个回答」停留在本题。回车等同主按钮。

不好回答时，点「这题不适用」或「暂不决定」：本题清空选择、记为已处理并立即确认，依据输入框改为「说明（选填）」，补写说明不会让它变回待确认。点「恢复作答」取回跳过前的选择（本次页面会话内）；直接重新选择选项也会撤销跳过。

### 3.2 追问

题目下方固定一行「追问：检查依据 / 考虑代价 / 比较其他做法 / 自己写…」。前三项把指引填入输入框，由用户改写后点「生成追问」。选中文字后的「针对这段追问」保持不变。生成完成后，新题出现在本题下方的「追问出的问题」列表里，可直接点进去。

子题顶部显示：追问自哪一题、我对那一题的回答、当时的追问指引。分类下补出来的题显示它来自哪个分类的补充方向。

### 3.3 全景

画布按画布宽度决定每行最多放几张卡（1～5）。一个节点的子项一行放得下时横排，放不下时换行，各行左对齐，用左侧竖线和每行横线表示归属。题卡显示题号、状态、两行标题、两行回答摘要和决定成熟度。预设但还没有问题的分类以虚线框显示「尚无问题」。

点击节点只选中，并在画布右侧打开面板显示该题（或分类）；再点别的节点直接切换；点「返回脑图」或按 Esc 关闭。工作区宽度不足以并排时，面板占满工作区。

面板打开时画布变窄但内容不跳动；只有被点的节点会被面板挤出可视区时，画布才平移刚好让它露出。关闭面板后画布恢复原来的大小和位置（期间自己移动过画布的，保持移动后的位置）。

### 3.4 下一步

进度行在全部现有题处理完后显示「还有 N 处可以再想想」，点击打开根节点面板。根节点面板依次显示：任务输入、整体进度、下一步建议、补充提问方向、分类列表。每条建议带一个动作按钮。

### 3.5 复核

复核弹窗顶部一行汇总：已确认、暂定、未标注、不适用、暂不决定、没写依据。可切换「全部 / 需要留意」。题目按分类分组，子题缩进在父题之下。提交选项与说明固定在弹窗底部。

## 4. 能力影响清单

本 RFC 不关闭任何既有能力。以下是用户可见的替换与调整，请逐项确认：

| 编号 | 既有行为 | 改为 | 说明 |
| --- | --- | --- | --- |
| C1 | 全景点击节点打开居中大弹窗（2026-10-13 用户决定） | 选中并在右侧面板显示；宽度不足时面板占满工作区 | 弹窗内的全部操作都在面板里保留。面板最小 420px，不回到 2026-10-13 之前 280px 的窄栏 |
| C2 | 同父节点一律横排（2026-10-13 用户决定） | 一行放得下时横排，放不下时换行 | 小图外观不变 |
| C3 | 题卡 236×190，回答摘要两行、成熟度单独一行 | 题卡 236×136，成熟度并入首行 | 标题由三行改为两行，完整标题仍在面板、目录与悬停提示 |
| C4 | 提交要求每题都有选项或自定义回答 | 标为「不适用」或「暂不决定」也算已回答 | 仍要求每题已确认；跳过动作同时完成确认 |
| C5 | 「深入这个问题」按钮与「我想追问」并存 | 只保留题目下方的追问行 | 英文与中文文案同步改名，见 design §7 |
| C6 | 复核弹窗按题号平铺 | 按分类分组，带汇总与筛选 | 「定位查看 / 修改」保留 |
| C7 | 脑图里每题都显示「处理节点」下拉 | 只有一个可选节点时不显示 | 仅脑图模式；普通问答不变 |
| C8 | 脑图里自定义输入框常驻（禁用态） | 选了「其他」才显示 | 仅脑图模式；普通问答不变 |
| C9 | 决定状态取值为已决定、暂定 | 增加暂不决定、不适用 | 经 MCP 写入的回答同样可用这两个值；普通问答不显示入口，但若带有这两个值，最终提示词按同一文案呈现。图驱动研发的设计文档接受带这两个值的回答来源；已发布的内置图研发代理提示词文本不变（升级不受影响） |
| C10 | 数字键在焦点位于选项的单选框时不响应 | 响应 | 已随单点缺陷修复提交；普通问答同样受益 |
| C11 | 打开节点详情不改变画布尺寸与相机，关闭回到原视口（RFC-372） | 面板并排时画布变窄；缩放不变；仅当被选中的节点会被挤出可视区时平移刚好让它露出；关闭后画布尺寸复原，相机回到打开时的位置 | 期间用户自己移动或缩放过画布的，关闭后保持用户的位置；期间定位到原视口之外的节点的，关闭后该节点保持可见。选中节点本身仍不平移画布 |
| C12 | 脑图里只有「确认这个回答」，回车无动作 | 主按钮改为「确认并下一题」，回车等同主按钮；「确认这个回答」保留为次按钮 | 回车与主按钮都先确认再前进，不会绕过确认；数字键选中选项后仍不自动前进 |
| C13 | 依据与成熟度在默认折叠的「决定补充」里 | 两者有回答后常驻显示，不在折叠区里：面板够高够宽时在底部操作栏、紧挨确认按钮，否则在选项下方；代价、未验证事项、验证负责人、复核时机仍在选项下方的折叠区 | 仅脑图模式；普通问答与集中回答弹窗不变 |

## 5. 验收标准

| 编号 | 可观察结果 |
| --- | --- |
| AC01 | 选完答案后，不展开任何折叠区即可填写依据并标注成熟度（面板够高够宽时也不必滚动）；修改依据使确认失效；选「暂定」自动展开其余字段 |
| AC02 | 「不适用」「暂不决定」各一次点击完成并确认；补写说明后仍为已确认；「恢复作答」取回跳过前的回答；重新选择选项自动撤销；全部题为已确认或已跳过时可以提交 |
| AC03 | 跳过状态经草稿、刷新、协作更新、封存、最终提示词不丢失；最终提示词区分「不适用」「暂不决定」「未回答」，并要求模型不替用户做选择；任何写入口送来「跳过状态加选项」都按真实回答保存；任务问题看板显示跳过的题 |
| AC04 | 子题显示父题标题、父题回答摘要与追问指引；分类或整体补充出来的题显示它的来源；父题列出子题并可跳转；旧数据（没有保存来源的题）只显示父题与回答 |
| AC05 | 首轮里预设分类没有问题时仍出现在目录和画布，可对它发起补题，新题落在该分类下；已封存的轮次只显示不可操作；后续轮次不显示空分类 |
| AC06 | 全部现有题处理完后显示下一步建议数量；五类建议各自可达且动作正确；已封存轮次不显示建议 |
| AC07 | 复核弹窗的汇总数与题目状态一致；「需要留意」只留下暂定、暂不决定、未确认、没写依据的题；分组与目录的分类一致；提交选项不随列表滚动消失 |
| AC08 | 9 题录制场景在 1440 宽、目录展开、可读比例下，画布不需要横向平移即可看到每一行的全部题卡（布局总宽乘可读比例不超过画布宽度）；390 宽下为单列 |
| AC09 | 5000 节点、300 同级、100 层深度仍可布局、不重叠、可命中；回答与确认不触发重新布局 |
| AC10 | 全景点击节点后画布仍可平移、缩放、点击其他节点；面板可用 Esc 关闭并把焦点还给触发元素；原本可见的被点节点不被面板挤出可视区；关闭面板后画布尺寸与视口复原 |
| AC11 | 界面上「追问」只有一个说法；「确认并下一题」一次点击完成确认并前进；回车等同主按钮，且不在按钮、多行输入框上触发；数字键选中选项后不自动前进 |
| AC12 | 目录搜索能按选项文字、推荐理由和我的回答（含依据）找到题目，并显示命中的片段 |
| AC13 | 已封存轮次的页脚提供决定摘要和任务结果入口 |
| AC14 | 普通问答模式的界面、提示词与提交行为保持不变（既有用例不改而通过） |
| AC15 | RFC-372 与 RFC-378 的端到端旅程在新交互下通过，并新增一条包含跳过、空分类补题、面板内连续作答的旅程 |

## 6. 完成口径

先完成全部生产实现与测试用例，再集中验证。质量门以确切提交的 GitHub Actions 为准。设计门与实现门只审功能。本 RFC 不做真人试用研究；「是否更能激发思考」仍需真实使用者观察，不以字段填写量或分支数量记为成功。
