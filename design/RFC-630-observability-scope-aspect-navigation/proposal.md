- 配套：[技术设计](./design.md) · [交付计划](./plan.md) · [页面原型](./prototype/index.html)（示例数据，可点击）
- 来由：用户 2026-11-27「现在在使用运行观测的时候，整体逻辑性不好，没有从可观测领域领域建模的方式进行引导使用，基本都是能力平铺，导致每个页面都比较乱，想看一个东西也不知道应该在哪找」。
- 本文的结构与口径经两轮澄清确认，决定清单见 §14。

## 1. 摘要

“运行观测与统计”现在是五个平级页签：前四个按对象切用量（总览、任务、Agent 与模型、系统执行），第五个是自成一套的过程度量。同一个任务在三处各有一份互不相通的视图，同一个量有几种叫法和几种算法。

本 RFC 把它改成一页三行固定控件：

1. **范围**：在看什么。全部 › 能力类型 › 能力 › 任务或交办，另外可以“只看”一个切面（环节、Agent、模型、执行原因、系统工作、来源、发起人、版本）。
2. **时间**：四个快捷项或自定义的起止时间，可以对比上一期或按版本分界对比。
3. **关注面**：关心什么。任何范围下都是同一组七个：概况、成本、效率、质量、人工介入、稳定性、明细。

每个面的排法相同：指标卡，一张构成图和一张变化图，一张“按…看”的表。表里点一行，范围就收窄到它。对象和维度只是这套统计的索引与筛选；范围选“全部”时，“按…看”就是全局的维度统计。

同时做四件事：统一叫法，统一算法，补全下钻与跳转，补上缺的视图（按能力看成本、Agent 与模型的全貌、现在在等谁、全局告警、一个任务的全过程、单代理任务的过程指标）。

不新增采集，不新增表，不改变任何执行行为。现有的每一块内容和每一个指标都保留，位置见 §10。

## 2. 背景与问题

现状（2026-11-27 按源码清点，细节见[技术设计](./design.md) §2）：

| 问题 | 事实 |
| --- | --- |
| 页签不是同一种东西 | 前四个页签是“用量按不同对象切”，第五个“过程度量”自带能力列表 → 能力详情 → 五到六个子页签 → 可展开的环节行，最深要点五次。两半的统计口径和刷新方式都不同 |
| 一个任务有三份视图 | 观测页的任务下钻（按调用）、过程度量的任务明细（按环节）、任务详情页（节点统计与节点运行）。只有过程度量明细能跳到任务详情页，其余互不相通 |
| 很多行点不动 | Agent 表、系统调用列表的行不能点；任务详情页、交办页、Agent 页都没有进观测页的入口 |
| 同一个量几种叫法 | Token（期间 Token、Token 合计、每任务 Token、总 tokens）、成本（人民币估值、人民币、成本）、缓存写入与缓存创建、失败重试与自动重试；同一类系统工作有三套名字 |
| 同一个量几种算法 | 时长有六种定义；任务状态一处分六类、一处分四类；一处取 P95、一处取 P90 |
| 两半数字不是同一批 | 总览里消耗按调用发生的时间算，任务按开始时间算；页面只靠一行小字说明 |
| 内容平铺 | 约 44 块内容、约 190 个指标位排在各页签里，没有“先看什么、再去哪”的引导 |
| 有覆盖缺口 | 过程度量不覆盖单代理任务；按能力看不到成本合计；没有全局的告警列表；看不到“现在在等谁” |

用户最想回答的四个问题（2026-11-27 确认）：某个能力整体怎么样；某个任务怎么回事；钱花在哪；人卡在哪。

## 3. 目标与非目标

### 3.1 目标

1. **一个模型贯穿全页**：对象（能力、任务或交办、环节、调用）、维度（Agent、模型、来源、发起人……）、关注面（七个）三样东西各归其位，页面按这个模型引导。
2. **找得到**：任何一个数字都能说出它在哪个范围、哪个面；从任何一行都能往下钻，从任何一个对象都能跳到它自己的页面，反过来也能跳回来。
3. **对得上**：同一范围、同一时间口径下，各种拆分相加等于合计；从“全部”钻到能力、任务、环节、调用，数字逐层对得上。
4. **叫法与算法各一套**：同一个量只有一个名字、一个定义，全页通用；任务详情页、交办页、节点抽屉上的同一个量用同一个名字。
5. **四个问题各有直达的位置**：
   - 某个能力整体怎么样：范围选到它，看概况。
   - 某个任务怎么回事：范围选到它，看全过程。
   - 钱花在哪：成本，按能力、任务、环节、Agent、模型、执行原因、系统工作看。
   - 人卡在哪：人工介入，先看“现在在等谁”，再看各类人工门的等待。

### 3.2 非目标

- 不新增采集，不新增表与列，不回填历史。
- 不改变任何执行行为，不改告警规则，不改任务生命周期。
- 不做多个“只看”条件的组合、阈值告警、导出、预算提醒。
- 不为单代理提供文本主题分析：这项分析现在只支持工作流、工作组、数字员工。
- 不改任务详情页和交办页的内容，只统一叫法并增加入口（§7、§9）。任务列表不在本次范围内。
- 不建派生表、缓存或后台汇总（沿用 RFC-371 v2 与 RFC-616 的原则：按需计算，结果有界）。
- 不为已停用的任务类型（旧版 Mission 流水线的代码检视任务等）提供观测：它们不能再创建，不属于任何能力类型，只在期间实际消耗里和已删除的任务合成一行（沿用 RFC-616 的决定）。
- 不统一“评审、审核、复核”这类功能名在全站的叫法；本 RFC 只管观测页上出现的量与对象。

## 4. 观测的领域模型

### 4.1 对象

对象之间是一棵树，页面的“范围”就是在这棵树上选一个位置。

| 对象 | 含义 |
| --- | --- |
| 能力类型 | 工作流、工作组、数字员工、单代理、任务之外的平台调用 |
| 能力 | 一个具体的工作流、工作组、数字员工，或一个被单独运行的 Agent；平台调用下是一类系统工作 |
| 任务或交办 | 能力的一次运行。工作流、工作组、单代理的一次运行叫任务；数字员工的一次运行叫交办 |
| 环节 | 运行里的一步。工作流是节点（含循环、扇出、Git 这类包装器），工作组是 Leader 与各成员，数字员工是工作项 |
| 执行 | 环节的一次执行，带执行原因（首次执行、评审返工、反问后续跑、失败重试、其它重跑、系统工作） |
| 调用 | 一个运行时进程，带 Agent、运行时与模型、四类 Token 和成本 |
| 人工门的一轮 | 一次等人处理：评审、反问、完成确认、人类成员交付、方案确认、外部审批、阻塞 |
| 人的操作 | 续跑、修复、同步工作流、取消、人工重试等 |
| 告警 | 任务页上的卡住与不一致告警 |

说明：

- “单代理”和“任务之外的平台调用”是这次补上的两类。前者现在不在过程度量里；后者现在只在“系统执行”页签里。类型的名字与任务列表一致（工作流、工作组、单代理）。
- 能力这一级还有两种特殊项，沿用现在的做法：没有来源的（没有来源工作流的任务、没有来源工作组的任务、没有归属员工的交办），以及已删除的能力（仍按 ID 汇总，名称显示为“已删除的…”）。
- 平台调用下没有任务这一级：一类系统工作下面直接是调用。

### 4.2 关注面

七个，固定不变。

| 关注面 | 回答的问题 |
| --- | --- |
| 概况 | 整体怎么样，值得先看哪里 |
| 成本 | 花了多少 Token 和钱，花在哪 |
| 效率 | 用了多久，时间花在哪 |
| 质量 | 成功了多少，一次做对的有多少，哪里被打回 |
| 人工介入 | 人参与了多少，等人等了多久，现在在等谁 |
| 稳定性 | 失败、重试、中断、告警 |
| 明细 | 这个范围里的每一个任务或交办，或者每一次调用 |

### 4.3 范围、“只看”与“按…看”

范围由两部分组成：

1. **在树上的位置**：全部 › 能力类型 › 能力 › 任务或交办。
2. **只看**（可选，一次一个）：
   - 运行的属性：来源、发起人、版本。它们筛的是“哪些任务或交办”。
   - 运行内部的切面：环节、Agent、模型、执行原因、系统工作。它们筛的是“任务或交办里的哪一部分”。

“只看”和“按…看”是同一件事的两头：在“按 Agent 看”的表里点一行，就是“只看这个 Agent”。

| 维度 | 可以“按它看” | 可以“只看”它 | 在哪些位置可用 |
| --- | --- | --- | --- |
| 能力类型 | 是 | 点一行进入这一类型 | 全部 |
| 能力 | 是 | 点一行进入这个能力 | 全部、能力类型 |
| 任务与交办 | 是（只在成本面，列出最高的 50 个） | 点一行进入这个任务或交办 | 全部、能力类型、能力 |
| 环节 | 是 | 是 | 单个能力、单个任务或交办；单代理（只有一个环节）与平台调用除外 |
| Agent | 是 | 是 | 任何位置 |
| 模型（运行时 × 模型） | 是 | 是 | 任何位置 |
| 执行原因 | 是 | 是 | 任何位置；平台调用除外 |
| 系统工作 | 是（只在成本面） | 是 | 任何位置；平台调用下它就是能力 |
| 来源 | 是 | 是 | 全部、能力类型、能力；平台调用除外 |
| 发起人 | 是 | 是 | 全部、能力类型、能力；平台调用除外；只对能查看全部任务的账号提供 |
| 版本 | 是 | 是 | 单个工作流、单个数字员工 |
| 人工门的种类 | 是（只在人工介入面） | 否 | 任何位置；平台调用除外 |
| 处理人 | 是（只在人工介入面） | 否 | 同上；只对能查看全部任务的账号提供 |

按版本分界对比时不能再“只看”某个版本。

点一行的规则：

- 能力类型、能力、任务与交办这三种是换位置，已选的“只看”保留。
- 其它维度：没有“只看”时，点一行就把它设为“只看”。已经有“只看”时，表里显示的是两个条件同时成立的数字，这些行不能点；表头注明先取消当前的“只看”。
- 人工门的种类与处理人的行不能点。

### 4.4 两种粒度

- **整次运行**：没有“只看”运行内部的切面时，数字说的是任务或交办：多少个、成功率、总历时、每个的成本、一次通过率。
- **运行里的一部分**：只看某个环节、Agent、模型、执行原因或系统工作时，数字说的是这部分：涉及多少个任务或交办、次数、时长、失败率、返工与重试的占比、相关人工门的等待。
  - 只看环节、执行原因时，次数是**执行**次数（节点执行一次算一次）。
  - 只看 Agent、模型、系统工作时，次数是**调用**次数（运行时进程启动一次算一次；一次执行通常是一次调用，带子 Agent 或换模型时会多出几次）。

七个面在两种粒度下都在，只是卡片和列换成对应粒度的指标。某个面在某个范围下没有内容时（例如平台调用没有评审），页面说明“不适用”，不留空白。

## 5. 页面

入口不变：运行与仓库 › 运行观测与统计，路径 `/observability`。

### 5.1 固定的三行

1. **范围条**：面包屑形式。点前面的段回到上一层；当前段可以展开，换到同层的另一个；末尾的“选择…”进入下一层（任务与交办列出最近 50 个，更多的在明细里找）。右侧是“只看”，已选时显示为一个可取消的标签。当前段是能力、任务或交办时，旁边有通向它自己页面的链接。
2. **时间与对比**：四个快捷项（近 24 小时、近 7 天、近 30 天、近 90 天，默认近 30 天）和“自定义”。自定义填起止时间，精确到分钟，最长 366 天；结束时间晚于现在时按现在算；结束不晚于开始或超过最长时给出提示，保留原来的范围。对比为不对比、对比上一期，单个工作流或数字员工还可以按版本分界对比。范围选到单个任务或交办时，这一行换成一句说明：它看的是全过程，没有时间范围。
3. **关注面页签**：七个。切换范围时保留当前的面，切换面时保留范围。

三行下面是一句统计口径（§6.1）和一处数据说明（§6.4），全页只有这一处。

范围、只看、面、时间（快捷项或起止时间）、对比、“按…看”的维度、所选的人工门种类、明细的搜索、筛选、排序、列集与页码都记在地址里，刷新页面或把地址发给别人，看到的是同一个视图。

### 5.2 每个面的排法

除明细外，每个面自上而下都是：

1. **指标卡**：不超过六张。开了对比时，每张卡带变化方向和好坏；数量类和系统工作占比只给方向，不分好坏。
2. **构成与变化**：左边一张构成图（这个面的量由什么组成），右边一张变化图（按时间分段，可换指标）。分段跟着时间范围的长短：不超过 12 小时每小时一段，不超过 4 天每 3 小时一段，不超过 14 天每天一段，更长每周一段（周从周一开始）。四个快捷项依次是每 3 小时、每天、每周、每周。
3. **环节一览**（只在单个工作流、工作组、数字员工下，并且没有“只看”运行内部的切面时；单代理只有一个环节，不显示）：工作流是画布，数字员工是职责图（保留区域与泳道分组），工作组是成员表。默认按这个面的主指标着色，可以换成这个面的其它指标。点一个环节就只看它。
4. **按…看**：一张表，可以切换维度（§4.3）。按环节、Agent、模型、执行原因、系统工作看时，表里用“运行里的一部分”的列（§5.3）。默认按这个面的主指标从高到低排，按环节看时按定义的顺序；点表头可以换排序。点一行的规则见 §4.3。最多 200 行，超出时按成本从高到低保留，其余合并成一行“其余”，所以各行相加仍等于合计；按任务与交办看只列成本最高的 50 个，并指向明细。开了对比时，按环节看的时长与 Token 列带基线值。
5. **这个面特有的卡**（§5.3）。

#### 整次运行粒度

下表里的“次数”“时长”“失败率”按 §4.4 分别指执行或调用。

- 时长：一个任务或交办里这部分各次执行（或调用）的时长之和，统计给中位数与 P90，另给合计。
- 失败率：按执行统计时是失败的执行 ÷ 已结束的执行；按调用统计时是失败或中断的调用 ÷ 已结束的调用（§8.2）。
- 主要失败码：这些执行的失败码；按 Agent、模型看时取这些调用所在的执行的；按系统工作看时没有。
- 按模型看时，Token 与成本按模型精确拆分，各行相加等于合计。一次调用用到不止一个模型时，它在每个模型下各算一次，所以次数、时长、失败不能相加，表里注明。
- “相关人工门”：只看某个环节时，是这个环节自己的人工门和评审它产出的评审；只看某个 Agent 时，是评审它所在环节产出的评审和它提出的反问。只看模型、执行原因、系统工作时没有对应的人工门，这一面说明“不适用”。
- 仓库准备、动态编排这类平台自己的环节不发起调用，它们出现在按环节看里，不出现在按系统工作看里。

**全过程**是一张时间轴：每个环节一行；色块是一次执行，按执行原因着色，失败的执行有不靠颜色的标记，还在运行的右端开口；斜纹是在等人。刻度是实际的日期与时间。把指针或焦点移到一段上，显示原因、起止、Agent 与模型、Token 与成本，或人工门的种类、轮次与结果。调用节点那一行代表它调起的子任务，带一个“看子任务”的链接，通向子任务自己的范围。

**调用表**：每个运行时进程一行，显示完整数字（不缩写）。列：开始、环节、第几次执行、执行原因、Agent、运行时、模型、状态、调用时长、用量状态、输入、缓存读取、缓存写入、输出、成本；系统工作的调用带类别名。“第几次执行”取自节点执行的记录。表尾有合计。最多显示 2,000 条，超出时注明。只列它自己的调用；子任务的调用在子任务的范围里。

单个任务或交办下也可以“只看”环节、Agent、模型、执行原因或系统工作：七个面换成“运行里的一部分”的内容（只算这一个），全过程只保留相关的行，调用表只留相关的调用。

一个任务或交办的成本、Token、执行、人工门都只算它自己的；它调起的任务各有自己的范围（§6.2）。成本面另有一行“它调起的任务另花了 ¥x”，不计入上面的合计。总历时与时间拆分是它自己的墙钟，其中等人包含它调起的任务里的评审与反问等待。

单个任务或交办下也可以按环节、Agent、模型、执行原因、系统工作看，表与汇总里的相同。

右上角是“打开任务页”或“打开交办页”。这是一个任务唯一的观测视图：任务详情页、交办页、节点抽屉都通到这里（§9），现有的任务下钻和过程度量里的明细展开行并入它。

### 5.5 当前

三处内容不受时间范围影响，说的是此刻；它们共用一次查询，页面可见时每 30 秒刷新。

1. **“当前”条**（概况顶部）：这个范围里运行中、等人处理（并注明最久等了多久）、已中断、未解决告警各有多少。每个还没结束的任务与交办各算一个：有还没处理的人工门的算等人处理，其余的算运行中（含排队）；已中断单独计数。运行中与等人处理最多统计最近的 500 个未结束的，超出时注明。每项可点：运行中通向明细的“运行中”，等人处理通向人工介入，已中断通向明细的“已中断”，未解决告警通向稳定性。
2. **现在在等谁**（人工介入顶部）：还没处理的人工门，等得最久的在前。列：任务或交办、能力、环节、种类、已等待、等谁处理。点一行进入那个任务或交办的人工介入面。
3. **告警**（稳定性）：未解决的告警不受时间范围影响，给出总数并列出最近的 50 条；其后是这段时间开始的任务与交办上已解决的告警。列：规则、级别、任务或交办、发现时间、状态。点一行进入那个任务或交办的稳定性面。

“等谁处理”：人类成员交付显示被指派的成员；其余的人工门任何任务成员都可以处理，显示发起人。这一列只对能查看全部任务的账号显示人名，其余账号显示“任务成员”。

“按…看”的表都是按时间范围统计的，所以表里不放“现在等人”这类此刻的数字。“只看”运行内部的切面时，“当前”条与现在在等谁也不显示。

## 6. 统计规则

### 6.1 时间口径

全页一句话：**统计所选时间范围内开始的任务与交办，以及它们到现在为止的消耗、时长和人工介入。**

- 一个任务在 9 天前开始、昨天才结束：选近 7 天时它不在统计里；选近 30 天时它完整地在里面。
- 更早开始、现在还没结束的任务与交办，在“当前”条和明细的“运行中”“等人处理”“已中断”里。
- 任务之外的平台调用没有所属任务，按调用自己开始的时间算。
- 范围是单个任务或交办时没有时间范围。

**期间实际消耗**（成本面里的一张卡，用户 2026-11-27 决定增加）：另一种口径，按调用发生的时间算。它显示：

- 这段时间里实际发生的调用的成本、Token、调用次数，其中失败或中断的调用有几次；
- 其中来自更早开始的任务与交办的部分；
- 按时间分段的实际消耗柱图（不超过 12 小时每小时一段，不超过 4 天每 3 小时一段，不超过 62 天每天一段，更长每周一段）；
- 范围是全部时，另有一行已删除或已停用类型的任务的消耗，它计入这张卡的合计；
- 一句话说明它和上面“成本”的关系。

这是页面上唯一按调用时间统计的地方，遵守当前的范围与“只看”。只看环节或执行原因时不显示这张卡：这两种切面要先把调用对到执行上，只在按开始时间统计的那套数字里提供。

### 6.2 归属

每个调用、每次执行、每轮人工门只属于一个任务或交办，在任何范围里都只算一次。

1. **每个任务只算在它自己的能力里。** 一个任务被另一个任务通过调用节点调起，或被数字员工当作工具调起时，它仍然是它自己那个能力的一次运行（来源标为“子任务”或“数字员工调用”）。它的调用、执行、人工门都算在它自己名下，不算进发起方。所以全部等于各类型之和，类型等于各能力之和，能力等于各任务与交办之和，每一层、每个量都对得上。
2. **发起方看得到它调起了什么。** 单个能力、单个任务或交办的成本面有一行“它调起的任务另花了 ¥x”，不计入合计；全过程里调用节点那一行通向子任务自己的范围。
3. **总历时与时间拆分是每个任务自己的墙钟。** 发起方等子任务跑完的时间在它自己的总历时里；其中等人的部分包含它调起的任务里的评审与反问等待（与现在的过程度量相同）。被调起的工作组任务里的完成确认与人类成员交付等待，只在那个工作组任务自己的时间拆分里算等人。人工门的轮次、等待合计、打回率这些统计只算每个任务自己的，不重复。
4. **数字员工**：一次交办是一个单元。它各轮在内部执行的任务属于这次交办，不单独出现，各轮的消耗、评审与反问都算在交办名下（与现在相同）。交办把某个工作流当作工具执行时，那个任务是这个工作流的一次运行，按第 1 条算在工作流名下。
5. **系统工作**：平台替一个任务做的系统工作（提交推送、合并冲突解决、变更导读、记忆提取等）算在这个任务名下，在“按执行原因看”里单列，占比在成本面有一张卡。
6. **任务之外的平台调用**：没有所属任务的调用（运行时探测、MCP 测试、任务之外的记忆提取与文本主题分析等）归到“任务之外的平台调用”这一类型，按系统工作的类别分能力。范围是全部时，成本、Token 与按 Agent、模型、执行原因、系统工作看的各行都包含它们（执行原因归系统工作）；按来源、发起人看时它们合成单独的一行。

### 6.3 样本

沿用 RFC-616 的规则，全页统一：

| 统计 | 样本 |
| --- | --- |
| 数量、结局分布 | 这段时间开始的全部任务与交办 |
| 成功率 | 已结束的（成功、失败、已取消） |
| 总历时、时间花在哪里、流动效率、等人占比、一次通过率 | 成功的；没有运行时长记录的不进时间拆分，页面注明个数 |
| 成本与 Token 的合计 | 全部，进行中的算到现在为止 |
| 每个的成本、每个的 Token、每个的人工介入 | 已结束的；开始于最早一条调用记录之前、自己也没有调用记录的不进 Token 统计，页面注明个数 |
| 执行失败率、失败重试率、失败码、中断的执行 | 全部执行，含进行中的任务与交办里已经发生的 |
| 人工门的等待、轮次、决定 | 已处理完的有效轮次；作废的轮次只计入等人时间 |

成本合计从“只算已结束的”改为“全部、进行中的算到现在为止”，是相对 RFC-616 的一处变化（§8.3）。

### 6.4 可见范围、上限与数据说明

- 门与现在相同：`tasks:read`。能查看全部任务的账号统计全部；其余账号只统计自己发起或参与的任务与交办，以及自己发起的平台调用。按人拆分的内容（发起人、处理人）只对前者提供。
- 上限：一次统计最多 2,000 个任务与交办，超出时只统计最近的 2,000 个；“当前”最多 500 个未结束的；未解决的告警列出最近 50 条；一个任务或交办的调用表最多 2,000 条，其它调用表最多 5,000 条；“按…看”最多 200 行，其余合并。
- 页面顶部的一处数据说明，只在对应情况出现时显示：
  - 你只能看到自己发起或参与的任务与交办；
  - 超出上限，统计只包含最近的 N 个，建议缩小时间范围或范围；
  - 部分调用的用量不完整，Token 合计是下界；
  - 部分调用没有定价，成本是下界（显示为“¥x 起”，全部未定价时显示“未定价”）；
  - 有 N 个开始于最早一条调用记录之前，不进 Token 统计；
  - 有 N 个没有运行时长记录，不进时间拆分；
  - 有 N 次执行没有记录原因，按首次执行计。

- 页面名“运行观测与统计”；卡片名“提升点”；提示的严重程度（优先处理、值得关注、供参考）。

- “等待用量”“等待中”这类不是等人的“等待”。

数字格式：指标卡与汇总表里 Token 缩写为 K、M；调用表显示完整数字。时长统一用“3 分”“1 小时 20 分”“2 天 4 小时”的形式。没有样本的显示“—”，不显示 0。

## 8. 统一算法

### 8.1 状态

汇总计数用五类，全页一致：

| 类别 | 含义 |
| --- | --- |
| 成功 | 任务已完成；交办以成功类结局结束 |
| 失败 | 任务失败；交办以失败类结局结束 |
| 已取消 | 任务已取消；交办被取消 |
| 已中断 | 任务已中断，等人决定恢复还是取消 |
| 进行中 | 其余：排队、运行中、等人处理 |

成功率 = 成功 ÷（成功 + 失败 + 已取消）。已中断与进行中都不进分母。

单个任务或交办显示状态时（明细的行、它自己的范围、现在在等谁），用它自己的状态标签，与任务页、交办页相同。

### 8.2 时长

| 名称 | 定义 |
| --- | --- |
| 总历时 | 结束时间减开始时间；没结束的算到现在。统计取成功的，给中位数与 P90 |
| 自动执行 | 处于运行状态的累计时长，减去调用节点等待子任务里的人处理的时间；数字员工取各轮执行的计量时长之和 |
| 等人 | 人工门各轮区间的并集长度，限制在起止之内；按人工门的种类拆分 |
| 排队与中断 | 总历时减去上面两项 |
| 流动效率 | 自动执行 ÷ 总历时 |
| 执行时长 | 一次执行从开始到结束。按环节、执行原因统计时，取一个任务或交办里各次执行之和的中位数与 P90 |
| 调用时长 | 一个运行时进程从开始到结束。按 Agent、模型、系统工作统计时，同上 |

分位数统一为中位数与 P90，最近秩法。

失败率有两种，名字分开：

| 名称 | 定义 |
| --- | --- |
| 执行失败率 | 失败的执行 ÷ 已结束的执行。被评审取代而作废的执行不算失败，中断的执行不算失败（另有“中断的执行”计数） |
| 调用失败率 | 失败或中断的调用 ÷ 已结束的调用。按 Agent、模型、系统工作统计时用它 |

### 8.3 数字会变的地方

下面是相对现在页面的口径变化，批准本 RFC 即确认这些变化。

| 现在 | 改为 | 影响 |
| --- | --- | --- |
| 总览的“期间 Token”“人民币估值”按调用发生的时间统计，是首屏的主数字 | 首屏的成本与 Token 是这段时间开始的任务与交办的全部消耗；按调用时间的合计移到成本面的“期间实际消耗”卡 | 两个合计在长任务多的时间范围里不相等 |
| 总览的“已结束任务时长”取已结束的任务（成功、失败、已取消），给 P50、P95、最长 | 总历时取成功的，给中位数与 P90；不再给“最长”，明细按总历时排序可以看到 | 数值变化；失败与取消的任务不再影响时长 |
| 总览的任务完成情况分六类（完成、失败、已取消、进行中、等待、已中断） | 五类；“等待”并入进行中，细分在“当前”条和明细的筛选里看 | 分类变化 |
| 过程度量把已中断的任务算作进行中 | 已中断单列 | 进行中的数量减少 |
| 过程度量的 Token 与成本只算已结束的单元 | 合计算全部，进行中的算到现在为止；每个的成本仍只算已结束的 | 合计变大 |
| 过程度量里一个任务的 Token 与成本包含它调起的子任务；用量页签的任务表只算它自己的 | 统一为只算它自己的；它调起的任务另列一行（§6.2） | 有调用节点的任务，相对原过程度量成本变小；各层相加不再重复 |
| 过程度量里每个任务的人工介入次数包含子任务的评审与反问轮次 | 只算它自己的 | 有调用节点的任务数值变小 |
| Agent 表的“任务数”是出现过这个 Agent 调用的任务个数，数字员工各轮的内部任务各算一个 | 涉及的任务与交办数：数字员工各轮的内部任务合成一次交办 | 数字员工用得多的 Agent 数值变小 |
| Agent 表最多 200 行、模型表最多 500 行 | 都是最多 200 行，其余合并成一行 | 模型很多时尾部合并 |
| 任务下钻的“运行态时长”是累计处于运行状态的时长 | 自动执行：再扣掉调用节点等子任务里的人处理的时间；还在运行的加上当前这一段 | 有调用节点或还在运行的任务数值不同 |
| 任务页签的状态筛选是八个任务状态 | 七项（§5.7）：等待评审与等待人工合成“等人处理”，排队并入运行中；行里的状态标签仍然区分 | 不能再分别筛这几种 |
| Agent 表的“调用耗时”是时间范围内已结束调用的时长合计 | 调用时长按 §8.2 给中位数与 P90，另给合计；样本是这段时间开始的任务与交办的调用 | 合计的样本变化 |
| “Token 花在哪里”和环节表里的 Token，是每个任务的均值（只算已结束、有调用记录的） | 合计，包含进行中的；每个的成本与每个的 Token 仍在成本面的卡上 | 数值变化；各项相加等于成本卡 |
| 环节的“占全部 Token 的比例” | 成本占比；范围里有未定价的调用时按 Token 算，并注明 | 指标变化 |
| 已删除任务的调用计入总览的消耗，显示为“已删除任务” | 不进按任务统计的成本；在范围是全部时的期间实际消耗卡里单列一行 | 首屏成本不含已删除任务 |
| 单代理任务不在过程度量里 | 作为一类能力，七个面都有 | 新增覆盖 |
| 变化图：用量按天，过程度量按周 | 按 §5.2 的分段，随时间范围的长短变化 | 分段变化 |
| 时间范围只有四个固定项；默认是页面近 7 天、“查看度量”入口近 30 天 | 四个快捷项加自定义起止时间；默认一律近 30 天 | 新增自定义；默认值变化 |
| 用量页签每 30 秒自动刷新 | 只有“当前”和未结束的单个任务或交办自动刷新（§5.9） | 汇总数字需要手动刷新 |

其余指标的定义不变：RFC-616 proposal §5.2 至 §5.9 的口径（一次通过、人工介入次数、评审、反问、脑图、工作组、数字员工、稳定性）与 §8 的提示规则继续有效，本 RFC 只改它们在页面上的位置（§10）。

## 11. 能力影响清单

本 RFC 以功能为由调整既有能力，逐项列出，请用户确认。

| 既有能力 | 处理 | 理由 |
| --- | --- | --- |
| 五个页签的结构 | 取消，改为范围 × 关注面 | 本 RFC 的主旨 |
| 旧的页面地址（`tab`、`task`、`kind`、`subject`、`view` 等参数） | 不再识别，落到全部 › 概况；站内入口全部改为新地址 | 不保留两套地址解析 |
| 首屏按调用时间统计的 Token 与成本 | 移到成本 › 期间实际消耗 | §6.1，用户决定 |
| 已结束任务时长的 P95 与“最长” | 改为成功任务的中位数与 P90 | §8.2 统一 |
| 任务状态的“等待”一类 | 并入进行中；“当前”条和明细的筛选里有“等人处理” | §8.1 统一 |
| 用量统计每 30 秒自动刷新 | 只有“当前”和未结束的单个任务或交办自动刷新 | 统计改由同一套按需计算提供，自动轮询会阻塞其它请求（RFC-616 design §13 的既有约束） |
| 任务下钻里的调用泳道（每个调用一行） | 换成全过程时间轴（每个环节一行，色块是执行）；每个调用的起止在调用表里 | 一个任务只保留一个视图 |
| 过程度量明细里就地展开各环节 | 改为进入这个任务或交办 | 同上 |
| 阶段分析里“所选节点”的卡片 | 改为点环节后只看它 | 同一套七个面代替单独的卡片 |
| 阶段分析里画布与表格二选一 | 环节一览与按环节看同时显示 | 排法统一 |
| 能力列表一次铺开各类型的全部列 | “按能力看”的列随所在的面变化 | 列随面走 |
| 提升点单独一个页签，列表页只列前几条 | 概况里的一张卡；单个能力下列出全部 | 引导放在最前面 |
| 任务页签按八个任务状态筛选 | 七项，等待评审与等待人工合成“等人处理” | §8.3 |
| 过程度量里任务的成本包含它调起的子任务 | 只算它自己的，调起的另列 | §6.2，各层对得上 |
| §8.3 列出的其余口径变化 | 见 §8.3 | 统一算法 |

没有被移除的指标：RFC-616 proposal §5 的指标目录与现有用量页签的每一列都保留，位置见 §5.3 与 §10。

## 12. 用户故事

下面的数字只是举例。

1. **某个能力整体怎么样。** 我是“需求开发”工作流的维护者。从工作流编辑页点“查看观测”，落到这个工作流的概况：近 30 天 30 个任务，成功率 93%，总历时中位数 5 小时，其中等人占 89%。“提升点”提示“大部分时间在等人”，我点“看人工介入”，看到等待主要在方案评审这一步，P90 接近一天。
2. **某个任务怎么回事。** 一个任务跑了八个多小时。我在任务详情页点“查看观测”，看到全过程：方案评审等了两轮共六个小时，中间方案设计返工了一次；编码只用了半小时。切到成本，返工占了这次任务 Token 的 12%。
3. **钱花在哪。** 我打开观测页，范围是全部，进成本：近 30 天 ¥1,831。按能力类型看，工作流占 74%；点进去按能力看，再点“需求开发”，按环节看，代码审计占 42%。换成按模型看，大头在一个模型上。每一层表尾的合计都等于上面的成本卡。
4. **人卡在哪。** 我进人工介入：现在有 6 个在等人处理，最久的等了 3 天，是“发布说明”的发布评审。下面按人工门的种类看，评审的等待中位数 37 分钟，但 P90 是 6 个多小时。
5. **某个 Agent 表现如何。** 我在 Agent 页点“查看观测”，落到全部、只看这个 Agent：它参与了多少任务、调用的失败率、产出被打回的比例、花了多少钱，分布在哪些能力和环节上。
6. **改动有没有效果。** 我给工作流发了新版本，在它的范围里把对比切到“按版本分界”，各张卡给出新旧两组的变化。
7. **普通成员。** 我只能看到自己发起或参与的任务与交办，页面顶部说明了这一点，按发起人、按处理人的拆分不出现。

## 13. 验收标准

- AC-1：页面只有范围条、时间与对比、七个关注面三行固定控件；切换范围时保留当前的面，切换面时保留范围；§5.1 列出的状态都在地址里，刷新页面后不变。
- AC-2：范围能逐级到达全部、五种能力类型、每个能力（含“没有来源的”与“已删除的”）、每个任务或交办；每一级的当前段能换到同层的另一个。
- AC-3：“只看”与“按…看”的维度、可用位置、点一行的规则与 §4.3 一致；在“按…看”的表里点一行与从“只看”里选同一个值，结果相同；已有“只看”时，非位置类维度的行不可点。
- AC-4：七个面在 §5.3 的两种粒度下的指标卡、构成、变化、列与表一致；类型特有的内容出现在表里指定的位置；不适用的面显示说明。
- AC-5：范围是单个任务或交办时，七个面的内容与 §5.4 一致；全过程时间轴按环节分行，执行按原因着色，等人与执行可区分，失败的执行有不靠颜色的标记；调用节点通向子任务。
- AC-6：同一范围与时间下，成本面“按…看”的表尾合计等于成本卡；按能力类型、能力、环节、Agent、模型、执行原因看，Token 与成本各行相加都等于合计（行数超过上限时“其余”一行补齐）；“Token 花在哪里”各项相加等于成本卡；全部的合计等于各类型之和，类型等于各能力之和，能力等于各任务与交办之和。
- AC-7：被调起的任务只算在它自己的能力里，来源正确；任何范围里同一个调用、同一次执行、同一轮人工门只算一次；发起方的成本面显示它调起的任务另花了多少，不计入合计；调用节点通向子任务。
- AC-8：首屏的成本与 Token 按 §6.1 的口径；期间实际消耗卡按调用时间统计，给出来自更早开始的任务与交办的部分和失败或中断的调用数。
- AC-9：“当前”条、现在在等谁、未解决告警不随时间范围变化，每 30 秒刷新；每个未结束的任务与交办只算一次，等人处理的个数等于有未处理人工门的个数，每一轮只列一次；能查看全部任务的账号看到人名，其余账号看到“任务成员”。
- AC-10：单代理任务作为一类能力出现；任务之外的平台调用作为一类出现，质量与人工介入显示“不适用”。
- AC-11：§7 的叫法在观测页、节点抽屉、任务详情页的节点运行表和三个原有入口上一致；被替换的旧叫法不再出现在这些地方的文案里；§7 列为“不改的”保持原样。
- AC-12：§8 的状态与时长定义在全页一致；同一个任务在明细、它自己的范围、“按任务与交办看”里的总历时、成本、状态相同，状态标签与任务页相同。
- AC-13：§9 列出的每个入口都存在并落到指定的范围与面；观测页里的每个对象都能跳到它自己的页面；没有 `tasks:read` 时入口不显示。
- AC-14：提升点按 §5.6 的规则显示，每条通向指定的面；14 条规则的阈值、最小样本数与严重程度与 RFC-616 相同。
- AC-15：对比上一期与按版本分界可用；比率给百分点，其余给百分比，好坏方向正确。
- AC-16：只统计自己可见的任务与交办；按人拆分只对能查看全部任务的账号提供；§6.4 的每条数据说明在对应情况下出现。
- AC-17：§10 的每一行在新页面上都能找到对应内容；RFC-616 proposal §5 的每个指标仍然可见。
- AC-18：2,000 个任务与交办的范围，本机 SQLite 上一次汇总在 2 秒内返回；“当前”在 1 秒内返回。
- AC-19：手机宽度下页面不横向滚动，表格与图在各自的容器里滚动；亮色与暗色下都可读；全部控件可以用键盘操作。
- AC-20：旧地址里新页面不认识的参数被忽略，同名的参数按新规则校验，不报错；只带旧参数的地址落到全部 › 概况；地址里的对象找不到时显示提示与通向上一层的链接。
- AC-21：明细可以按名称或 ID 搜索，按 §5.7 的七项状态筛选，按四列排序，切换三种列集，用页码翻页；运行中、等人处理、已中断不受时间范围影响。
- AC-22：时间范围的终点在范围与面之间切换时不变；点“刷新”或换时间范围后更新，页面显示截至时间。
- AC-23：时间可以用四个快捷项或自定义起止时间（精确到分钟，最长 366 天）；自定义的范围记在地址里，刷新页面不变；变化图与期间实际消耗的分段随范围的长短按 §5.2、§6.1 变化；对比上一期在自定义范围下可用；结束不晚于开始或超过最长时给出提示并保留原来的范围。

## 15. 原型

[页面原型](./prototype/index.html)是一个单文件页面，数据由页面内的一个小引擎按固定种子生成，所以各层数字对得上。它演示了范围条、只看、七个面在两种粒度下的排法、单个任务的全过程、当前、提升点、对比上一期、期间实际消耗、自定义时间范围和两种查看身份。

原型与本文的差别，以本文为准：

- 环节一览在正式页面里是工作流画布、职责图和成员表，原型用一排环节卡片代替。
- 原型没有放：各类人工门的细项、类型特有的内容、文本主题分析、按版本分界对比、明细的列集与搜索、单个任务或交办下的“只看”、按处理人看。
- 原型的“按…看”的行数、已有“只看”时行是否可点与本文不完全相同；原型的示例数据里没有被调起的任务。
