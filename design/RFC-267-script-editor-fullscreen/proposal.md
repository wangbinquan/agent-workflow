# RFC-267 · 工作流脚本节点全屏编辑

> 状态：Done（2026-08-07，用户批准后实现并完成真实浏览器验收）
> 日期：2026-08-07
> 关联：RFC-253（脚本执行节点与公共 `<CodeEditor>`）、RFC-035（公共 `<Dialog>`）、RFC-250（前端交互完整性）

## 1. 背景

工作流脚本节点的正文编辑器当前只存在于右侧 Inspector：

- 桌面布局把 Inspector 固定在 `clamp(360px, 27vw, 420px)` / `clamp(360px, 30vw, 420px)`；
- Inspector 自身还有左右内边距，CodeMirror 的行号栏继续占用横向空间；
- 公共 `<CodeEditor>` 固定启用软换行。

因此，一段在常规代码编辑器里能保持单行的脚本，会在约 330–390px 的正文区被拆成多行。脚本越长，阅读上下文、对齐缩进和检查长表达式越困难。用户明确要求：**脚本正文支持全屏编辑**。

## 2. 目标

- **G1**：脚本正文旁提供清晰的「全屏编辑」入口，使用接近整个浏览器视口的代码编辑空间。
- **G2**：全屏与内嵌编辑使用同一个脚本值；全屏输入继续进入现有 workflow history 与 1 秒自动保存链路，不新增第二套草稿或 Save/Cancel 语义。
- **G3**：保留当前语言、高亮、缩进、只读权限和主题；全屏只是呈现面积变化，不改变脚本持久化格式或执行语义。
- **G4**：键盘与触屏完整：Esc / 关闭按钮退出，退出后焦点回到触发按钮；焦点被约束在全屏层内；窄屏不产生横向页面溢出。

## 3. 非目标

- **NG1**：不接浏览器 Fullscreen API，不隐藏浏览器自身工具栏；本 RFC 的「全屏」是平台内的视口级编辑层。
- **NG2**：不新增独立脚本资源、文件上传、多文件标签、搜索替换、格式化器、运行按钮或终端。
- **NG3**：不改变 CodeMirror 现有软换行策略，也不新增 word-wrap 设置；扩大可用宽度已直接解决本次问题。
- **NG4**：不顺带迁移 RFC-253 尚未完成的其它 JSON / YAML `<TextArea>`；只有脚本正文获得入口，生成的只读输入/信封样例不显示全屏按钮。
- **NG5**：不改 backend、shared schema、API、数据库或 workflow `$schema_version`。

## 4. 用户故事

- **US-1**：我在脚本正文右上方点击「全屏编辑」，立刻得到接近整屏宽高的 CodeMirror，长表达式不再因 360–420px Inspector 而密集折行。
- **US-2**：我在全屏里继续输入，关闭后内嵌正文立即显示相同内容，工作流照常自动保存，不需要再点一次「应用」。
- **US-3**：我按 Esc 退出全屏，焦点回到「全屏编辑」按钮，可以继续用键盘浏览 Inspector。
- **US-4**：没有 `scripts:author` 权限时，我仍可全屏查看，但编辑器保持只读，入口文案如实显示「全屏查看」。
- **US-5**：在 390px 手机宽度下，全屏层覆盖整个可用视口并尊重安全区，编辑器内部滚动，不把页面撑宽。

## 5. 产品决策

### D1 · 复用公共 Dialog

全屏层使用 `components/Dialog.tsx` 的 `size="full"`：复用 portal、遮罩、body scroll lock、focus trap、Esc、outside-click 与焦点恢复，不另造 overlay / panel chrome。

### D2 · 实时编辑，不设确认按钮

全屏 CodeEditor 直接调用当前 `ScriptEdit.update({script: next}, continuousNodeInspectorChange(...))`。关闭只改变 UI 开合状态，**不会回滚，也不会额外提交**；这与内嵌编辑器现有的即时 workflow history + autosave 语义完全一致。

### D3 · 只给正文入口

入口位于 `scriptInspector.body` 字段内、正文编辑器上方，并使用既有 `btn btn--xs btn--ghost`。RFC-253 T43 的只读样例不会出现入口，避免把「文档样例」误认为可编辑脚本。

### D4 · 全屏仍服从权限

有 `scripts:author` 时文案为「全屏编辑」且可写；无权限时文案为「全屏查看」且 `<CodeEditor readOnly>`。权限只决定编辑能力，不阻止扩大阅读面积。

## 6. 行为影响

- 仅新增一个可逆的前端呈现入口；关闭后定义字节与现有编辑链路一致。
- 无 wire breaking、无数据迁移、无能力收缩、无部署配置变化。
- 全屏内的更改与内嵌更改一样会触发自动保存；这不是临时预览层。

## 7. 验收标准

- **AC-1** 脚本正文显示一个本地化、可访问的全屏入口；输入/信封样例不显示该入口。
- **AC-2** 点击入口打开 `role="dialog"` 的 full-size 公共 Dialog；桌面占用除窄边距外的视口，≤720px 时覆盖完整 `100vw × 100dvh`。
- **AC-3** 全屏 CodeEditor 使用当前语言和当前正文，填满 Dialog 剩余高度；编辑器自己滚动，Dialog 页面不横向溢出。
- **AC-4** 全屏输入沿用 `continuousNodeInspectorChange`，关闭后内容保留并继续走现有自动保存。
- **AC-5** Esc、×、遮罩点击均可退出；退出后焦点返回原触发按钮。
- **AC-6** 无 `scripts:author` 权限时入口为「全屏查看」，两处 CodeEditor 均为只读。
- **AC-7** 深色/浅色、高亮、行号、Tab 缩进与软换行沿用公共 `<CodeEditor>`，不出现第二套主题。
- **AC-8** 单测覆盖打开/关闭、值与 language 接线、权限、修改回传、焦点恢复；真实浏览器覆盖 1536px 与 390px，并留截图核对。
