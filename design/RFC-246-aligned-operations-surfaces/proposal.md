# RFC-246 · 任务、定时任务与远程仓库运行表面统一

- 状态：Done（2026-08-01）
- 日期：2026-08-01
- 触发：用户要求「把定时任务和远程仓库界面也同步下 UX，和任务列表一样」
- 相关 RFC：RFC-024（远程仓库缓存）、RFC-159 / RFC-192（定时任务行内操作）、
  RFC-244（高密度任务运行中心）

## 1. 背景

RFC-244 已把 `/tasks` 收敛为一张高密度运行表面：标题、副标题、业务视图、搜索、筛选和列表位于
同一 surface，桌面行紧凑，移动端使用同一语义 DOM 重排且不产生页面级横向滚动。

`/scheduled` 与 `/repos` 仍是旧式宽表格：标题与结果分离、缺少业务视图与搜索，窄屏依赖横向滚动。
三个页面都是高频运维列表，却使用三套不同的信息层级和响应式策略，用户需要反复重新理解。

## 2. 目标

- **G1 一套运行语言**：三个页面共用 surface、标题区、业务视图、搜索/筛选工具条和密度 token。
- **G2 保留业务能力**：定时任务的启停、立即运行、详情跳转，以及仓库的刷新、删除、批量导入行为不变。
- **G3 业务视图优先**：先按用户要处理的工作分组，再提供精确筛选。
- **G4 响应式同构**：桌面为紧凑列网格；移动端同一 DOM 重排，无页面/列表级横向 overflow。
- **G5 公共实现**：抽取公共 `OperationsToolbar` 与通用 CSS chrome，不复制 RFC-244 的私有 SVG/CSS。

## 3. 已批准的产品决策

用户在 2026-08-01 直接要求按任务列表同步两个页面，构成本 RFC 的实施批准；以下是对该指令的
业务映射，不新增后端语义：

### 3.1 定时任务

- 业务视图：`全部 / 启用 / 需关注 / 已暂停`。
- 「需关注」包含修复态、最近启动失败、连续失败或存在 `lastError` 的日程；该集合可与「启用」重叠。
- 搜索覆盖名称、调度摘要、启动类型和 Owner。
- 高级筛选：启动类型（工作流 / 工作组 / Agent）与最近结果（从未 / 已启动 / 失败）。
- 行列：`日程 / 状态 / 下次运行 / Owner / 操作 / 详情提示`；普通内容以 56px 为密度目标。

### 3.2 远程仓库

- 业务视图：`全部 / 使用中 / 需关注 / 未使用`。
- 「需关注」只使用现有确定事实：仓库含 submodule 且最近 submodule 同步明确失败；不发明“多久算过期”。
- 搜索覆盖脱敏 URL、本地缓存路径与默认分支。
- 高级筛选：是否含 submodule、是否发生过后台自动刷新。
- 行列：`仓库 / 新鲜度 / 使用情况 / 操作`；仓库没有详情页，因此不伪造右侧 chevron 或整行跳转。

## 4. 非目标

- 不新增或修改 API、数据库、权限、缓存刷新与调度行为。
- 不做服务端分页：现有两个列表 API 已向当前页面返回完整授权集合，本 RFC 在客户端派生视图与筛选。
- 不把仓库 URL 从 `urlRedacted` 退回原始 URL，也不暴露新敏感字段。
- 不改变空列表的主 CTA：Scheduled 仍新建日程，Repos 仍批量导入。

## 5. 验收标准

- **A1**：`/tasks`、`/scheduled`、`/repos` 使用同一个公共工具条与通用 surface class。
- **A2**：Scheduled 四视图、搜索、两类高级筛选结果与计数正确；行内开关/立即运行/详情导航不回归。
- **A3**：Repos 四视图、搜索、两类高级筛选结果与计数正确；刷新/删除/强制删除/批量导入不回归。
- **A4**：桌面普通 Scheduled/Repos 行以 56px 为密度目标，必要正文允许自然增高，不裁切 Owner/路径。
- **A5**：1280px、1024px、390×844、390×568 下 document/main/list 均无横向 overflow。
- **A6**：移动端搜索与筛选同排，筛选触点不小于 42px；Scheduled 行仍可操作，Repos 操作不遮挡正文。
- **A7**：加载、错误、初始空态、筛选无结果均使用既有公共组件。
- **A8**：前端单测、typecheck/lint/format、目标 Playwright 与视觉回归全绿；上库后按 exact SHA 核验 CI。
