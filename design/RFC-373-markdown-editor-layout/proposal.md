# RFC-373：Markdown 编辑器可调整分栏

状态：Approved · 2026-10-13。用户已审阅本会话交互原型，并明确同意落地正式版本、提交并推送远端。采用原型推荐的「编辑 / 双栏 / 预览」三态控制。

## 背景与范围

Agent 新建、Agent 编辑的提示词页，以及 Skill 详情的正文编辑，共用 `packages/frontend/src/components/MarkdownEditor.tsx`。现有 `.md-editor` 使用 `1fr 1fr`，列与 pane 缺少可收缩宽度约束；外侧列表又占用部分空间，宽预览内容可能挤压编辑区域。现有 720px 整屏断点不能表达编辑容器的实际可用宽度。

已核对其他编辑入口：Skill 新建、Skill 文件树与记忆编辑使用单个 TextArea；工作流节点 PromptPreview 为上下排列，任务输出另开只读预览。它们没有共用的双栏病因，本次保持其现有功能。

## 用户体验

1. 编辑器右上角统一显示「编辑 / 双栏 / 预览」；任何时刻至少显示一个内容面板。
2. 双栏默认均分，中间分隔条支持鼠标、触控拖动；两侧最小宽度 320 CSS px。双击分隔条或点击「均分」恢复 50:50；键盘左右键微调，Home/End 到边界，Enter 收起编辑区到预览，视图按钮可恢复。
3. 按编辑容器实际宽度适配。不足以容纳两栏时自动显示最近使用的单栏（新用户可编辑资源默认编辑、只读资源默认预览）。双栏按钮保留但禁用，并显示原因。恢复空间后，原本选择双栏的用户自动恢复分栏；在窄屏主动选择单栏则继续尊重该选择。
4. 切换与拖动不改正文、不触发保存、不重建 textarea；草稿、光标和各面板滚动位置保留。既有保存、离开确认、Skill 聚合草稿与只读行为保持。
5. 同一浏览器记住模式、最近单栏及用户设定的比例；只记布局，不存正文。窗口临时变窄时夹取显示比例，不覆盖用户的宽屏比例。读取异常、损坏数据、存储不可用均不妨碍编辑。
6. 长代码、宽表格在预览内部滚动；工具栏可换行。短窗口保证编辑区的可用高度，必要时滚动工作区，不能再收缩成一行。

## 验收

- AC1：三个真实入口共用相同的三态与拖动行为。
- AC2：拖动/键盘到极限后，能容纳双栏的容器中两侧均不小于 320px，页面不被长内容撑宽。
- AC3：容器宽度在临界值上下变化、父页签隐藏后重现、320/390px 手机宽度及短窗口均可编辑并访问预览。
- AC4：模式切换前后正文、选区、滚动及 dirty 状态不因布局操作丢失；恢复双栏时草稿仍实时预览。
- AC5：刷新恢复布局，损坏或被拒绝的 localStorage 有默认回退；临时窄屏不污染宽屏偏好。
- AC6：只读内容可查看源文与渲染，不能输入；现有 GFM、代码高亮、数学和提示块仍由 Prose 提供。
- AC7：中文/英文与浅色/深色使用现有设计原语；分隔条具备名称、范围、当前位置与键盘操作。
