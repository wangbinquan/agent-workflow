# RFC-371 v2：运行观测精简重设计（2026-10-14）

> 状态：Done 候选。用户 2026-10-14 明令“按推荐完成 RFC-371 的整体重构，重点考虑存储与界面性能，授权完整重新设计和优化、不要有负担，现在没有现网存量环境”，并豁免 Codex 设计门 / 实现门。本文取代 [design.md](./design.md) §1–§22 及其后各补充文档中的**实现**设计；[proposal.md](./proposal.md) 的产品定位与统计口径（§1、§3、§5）继续有效，被收缩的能力见 §9。依据见 [审视记录](../rfc370-372-review-2026-10-14.md) §3。

## 1. 为什么重做

v1 的统计口径是对的，实现代价不成比例（本机实例实测，详见审视记录 §3.3）：

- 约 80 张表、330 个 SQLite 触发器、PG 220 个触发器；15 张是他域业务表（tasks、node_runs、node_run_events…），每次写入都要多写一行，已造成 node_runs 写事务互等。
- 四套派生数据并存（有界实时查询、完整报告、计算缓存、增量投影），派生表 23.0 GB，是原始事实的 194 倍；投影积压 32.7 小时，页面停在 4 小时前。
- platform 层约 3.3K 行观测业务代码按 SQL 读他域私有表，绕开模块边界；未接线的 CrewStation 代码与 `'crewstation'` 分支。
- 页面单页最高 51K px，文案偏实现术语，时长显示原始毫秒，系统执行与业务任务混排。

v2 的原则：**一次调用一行，原地更新；统计按需聚合，不建派生表；跨模块只走公开查询。**

## 2. 架构落位（RFC-294）

bounded context 仍是 `modules/run-observability`，代码按目标分层落位：

| 层 | 内容 |
| --- | --- |
| `domain/` | 用量快照合并、人民币计价（整数纳元）、价格选择规则、分位数与日桶 |
| `application/` | 调用记录（受理 / 用量 / 结束 / 开机修复）、统计查询、价格管理；只依赖自身 `ports/` |
| `ports/` | 调用存储、价格存储、任务事实、运行时目录 |
| `infrastructure/` | Drizzle 持久化（SQLite / PostgreSQL 同一份中立查询） |
| `inbound/http/` | HTTP 路由（审视记录 §3.2 低项：入站代码不再放 `infrastructure/http`） |
| `composition/` | 由装配根注入数据库、任务事实与运行时目录 |
| `public/` | `participants`（调用写入合同）、`queries`（统计查询合同） |

跨模块依赖只有三条，全部是对方的公开合同：

1. run-observability 声明所需端口 `ObservationTaskFactsPort`（`application/ports/taskFacts.ts`），由 task-execution 在 `composition/taskObservationFacts.ts` 提供实现、装配根绑定：任务可见性批量判定（复用 task-execution 唯一的可见性谓词）、任务展示摘要、按创建时间（任务的 `started_at`，即提交时刻）的可见任务分页、任务状态计数与完成时长、单任务尝试。只做批量（≤500）或分页查询，不暴露表；run-observability 从不 import task-execution。
2. runtime-management 的运行时目录（价格页列出运行时注册项与其配置模型）。
3. 任务执行侧（runner / 系统 Agent）通过 `run-observability/public/participants` 的 `CallObservations` 写调用。

platform 层不再含任何观测业务代码；不建触发器、不读他域私有表、不设后台投影 / 报告 worker。领域与界面不出现 CrewStation 字样；托管部署接入留给 RFC-370 阶段 B 另立。

## 3. 数据模型（三张表）

### 3.1 `observation_calls` — 每次运行时子进程一行

| 列 | 说明 |
| --- | --- |
| `id` | 调用 ID（ULID），spawn 前生成 |
| `purpose` | `task`（业务节点）/ `system`（平台自身的 Agent 工作：合并冲突处理、提交说明、记忆提取、分支追问、MCP 测试、运行时自检…） |
| `task_id` / `node_run_id` | 所属任务与节点尝试；系统调用可以不属于任务 |
| `system_kind` / `system_label` | 系统调用的类别与展示名 |
| `owner_user_id` | 不属于任务的系统调用的发起人（可见性用） |
| `agent_id` / `agent_name` | Agent 稳定 ID 与名称快照 |
| `runtime_id` / `runtime_name` / `protocol` | 运行时注册 ID、名称快照、`opencode` / `claude-code` |
| `status` | `running` / `done` / `failed` / `canceled` / `interrupted` |
| `started_at` / `ended_at` | epoch 毫秒 |
| `usage_state` | `pending`（运行中尚无用量）/ `partial`（下界）/ `complete` / `none`（结束且运行时未报告用量） |
| `input_tokens` `cache_read_tokens` `cache_write_tokens` `output_tokens` `reasoning_tokens` | 各模型合计；输出含推理，推理是输出的子集，不另加 |
| `cost_nano` / `cost_state` | 人民币纳元（10⁻⁹ 元）整数；`none`（无 Token）/ `priced` / `partial` / `unpriced` |
| `updated_at` | 最后一次原地更新 |

索引：`(started_at)`、`(task_id, started_at)`、`(status)`。**不加指向 tasks 的外键**：与记忆提取作业、恢复事件同规则，用量是账目事实，任务删除后保留（task 删除服务 `services/taskDelete.ts` 头注释的保留清单），统计里显示为“已删除任务”，只有 `tasks:read:all` 能看到。

### 3.2 `observation_call_models` — 调用内按实际模型拆分

主键 `(call_id, model)`，`call_id` 外键级联删除。`model` 为运行时报告的实际模型（OpenCode 为 `provider/model`，Claude Code 为模型名），空串表示未归属。五个 Token 列；`price_id` 为命中的价格版本，`cost_nano` 为 NULL 表示未定价。每次更新整组替换（同一事务先删后插），天然幂等。

### 3.3 `observation_prices` — 只追加的价格版本

`(runtime_id, model)` 一条价格线（没有运行时注册的调用——例如经旧 `*Model` 设置运行的系统 Agent——以 `builtin:<protocol>` 为键，见 [断代验证](./cutover-verification-20261014.md) §3），每次保存新增一行：四项费率（人民币微元 / 百万 Token 的整数，即“元/百万Token”×10⁶，最多 6 位小数；NULL 表示该桶未知、不是免费）、`effective_from`、`created_at`、`created_by`、`note`。

**价格选择规则**（无需快照表即可冻结）：调用 C 采用满足 `runtime_id = C.runtime_id`、`model = 模型`、`effective_from ≤ C.started_at` 且 `created_at ≤ C.started_at` 的版本中 `(effective_from, created_at)` 最大者。版本不可变、只追加，所以同一调用无论何时补到用量都命中同一版本；新价只影响之后受理的调用，回填生效时间也不改历史（proposal §4.4.1）。保存用 `expectedLatestId` 做 CAS，冲突 409、保留草稿。

### 3.4 计价

`cost_nano = round(tokens × rate_micro / 1000)`，按桶用 BigInt 计算后求和，最终整数落库。某桶有 Token 而费率未知 → 该模型部分定价；模型无价格线或模型未归属 → 未定价。展示最多 6 位小数，非零但小于 ¥0.000001 显示“< ¥0.000001”，未定价显示“未定价”而不是 ¥0。

## 4. 写入链路

```text
spawn 前   CallObservations.accept()           插入 running 行；失败则不启动进程
运行中     driver usageMeter.observe(event)     内存合并；变化后最多每 3 秒原地更新一次
结束后     meter.finish()                      OpenCode 读一次原生库做有界汇总；Claude 用 result
           CallObservations.finish()            终态 + 最终用量（替换），写入严格按序串行
开机       repairInterrupted(bootAt)            开机前仍为 running 的行改为 interrupted
```

用量合并属于运行时驱动（RuntimeDriver 自己解析协议，调用方不按协议名分支），输出统一的 `{ state, models[{ model, input, cacheRead, cacheWrite, output, reasoning }] }`：

- **OpenCode**：stdout 只有根会话的 `step_finish`（`packages/opencode/src/cli/cmd/run.ts:717` 跳过非根会话的 part），按 part id 去重累加；运行中模型取本次启动配置的模型，未配置则未归属；见到 `task` 工具调用（子 Agent）时状态为 partial。结束后在 spawn 环境定位原生库（`OPENCODE_DB` / XDG 数据目录，`:memory:` 不读），只读执行一条聚合：从根会话沿 `session.parent_id` 递归（深度 ≤ 8）取子树，统计 `time_created ≥ 调用开始` 的 `step-finish` part，按所属 assistant message 的 `providerID/modelID` 分组（表结构见 `packages/core/src/session/sql.ts:22-98`）。成功则替换为 complete 的按模型结果；读不到则保留 stdout 结果（有子 Agent 时为 partial）。时间下界天然排除恢复会话中上一次调用已有的步骤。OpenCode 原生输出不含推理，合入输出一次。
- **Claude Code**：`assistant` 事件按 message id 去重（同一消息拆成多条事件），按 `message.model` 累加输入 / 缓存；输出可能不是终值，运行中为 partial。非恢复调用收到 `result.modelUsage` 后替换为按模型的完整用量（含子 Agent）；`error_during_execution` 的全零不覆盖已知值。恢复调用的 `modelUsage` 可能含历史累计（protocol-evidence.md），保留 assistant 合计并标 partial，不猜差值。
- 未声明计量能力的驱动：状态 `none`。

写入失败不影响任务结果（受理失败除外）。系统 Agent（记忆提取、分支追问、MCP 测试、运行时自检、意图构建等）与节点内的系统工作（合并冲突处理、提交）走同一合同，`purpose='system'` 并带类别。

## 5. 读取：按需聚合，结果有界

所有统计在调用时对三张表做窗口过滤 + `GROUP BY`，走 `(started_at)` 或 `(task_id, started_at)` 索引；没有缓存、投影与水位，页面打开即为当前数据。

| 接口 | 口径与上限 |
| --- | --- |
| `GET /api/observability/overview` | 调用按开始时间落在 `[from,to)`：总量、业务 / 系统拆分、连续日桶（含 0 的日子）、Token 前五任务与 Agent；任务按创建时间：状态计数、完成任务墙钟 P50 / P95 / 最大值与样本数 |
| `GET /api/observability/tasks` | 按创建时间的可见任务，键集分页每页 25；每行显示该任务全程用量 |
| `GET /api/observability/tasks/:id` | 任务全程：摘要、各调用（≤2000，超出标截断）及其节点 / 尝试标签、泳道数据 |
| `GET /api/observability/agents` | 窗口内按 Agent 汇总，按 Token 排序取前 200 |
| `GET /api/observability/models` | 窗口内按运行时 × 实际模型汇总，标出未定价 |
| `GET /api/observability/system` | 窗口内按系统类别汇总 + 最近系统调用（键集分页） |
| `GET /api/observability/pricing` · `GET …/pricing/:runtimeId/history?model=` · `POST …/pricing/:runtimeId` | 价格线目录（运行时 × 配置模型与实际出现过的模型）、单条价格线历史、新增版本（CAS） |

**权限**：统计路由的门是 `tasks:read`（与任务页同档），范围再由账号的范围点决定：有 `tasks:read:all` 时统计全部调用；有 `tasks:read:own` 时先取窗口内出现的任务 ID（≤20,000，超出返回 `partial` 并提示缩小范围），经 `ObservationTaskFactsPort.visibleTaskIds` 批量判定后只聚合可见任务，外加本人发起的无任务系统调用；两者都没有则为空。调用聚合都是可加的，因此按 500 个 ID 分块执行后合并。价格目录、历史与写入都需要 `settings:write`（与运行时设置同权）。

时区：前端传当前 UTC 偏移（分钟），日桶按固定偏移切分；跨夏令时当天的边界可能差一小时，界面不宣称按 IANA 时区。

## 6. 界面

入口不变（运行与仓库 → 运行观测与统计）。顶部：时间范围 `Segmented`（近 24 小时 / 近 7 天 / 近 30 天）+ 刷新；运行中的数据每 30 秒自动刷新（页面可见时）。四个页签：

1. **总览**：四张指标卡（期间消耗、人民币估值、任务完成情况、任务时长 P50/P95）；按天堆叠的 Token 柱图（四类颜色，悬停 / 键盘焦点显示精确值）；Token 最多的任务与 Agent 各五条；业务 / 系统消耗拆分。
2. **任务**：任务表（名称、状态、创建时间、时长、调用数、四类 Token 分列、人民币），关键词与状态筛选，分页；点进任务详情。
3. **Agent 与模型**：Agent 表与运行时 × 模型表；模型表未定价行提供“配置价格”入口。
4. **系统执行**：按类别汇总 + 最近系统调用列表，与业务任务分开。

任务详情：摘要（墙钟、运行态时长、调用数、Token、人民币）、调用泳道（复用公共 `ExecutionSwimlane`，按节点分组，失败 / 中断有文字标记）、调用表。时长统一用可读格式（如“3 分 12 秒”），Token 分四列而不是每行重复标签；文案使用“任务 / Agent / 调用 / 模型 / 系统执行”。设置 → 运行时 → Token 成本：每个运行时展开其配置模型与实际出现过的模型，各自配置价格、查看历史。全部复用 `Card`、`TabBar`、`Segmented`、`TableViewport`、`Dialog`、`Form`、`EmptyState`、`ErrorBanner`、`LoadingState`。

## 7. 迁移

- SQLite `0256_rfc371_observation_v2.sql`：先删他域表上的 330 个 `obs_src_*` / `obs_delta_*` 触发器，再按外键依赖顺序删除 v1 的 81 张观测表（含 0248 中的 14 张 `observation_projection_*`），最后建 v2 三张表。v1 数据不迁移（用户确认无现网存量）；删除后本机库的 23 GB 派生页进入空闲页，可由“数据库维护”或 `VACUUM` 回收。
- PostgreSQL 由 `db:rfc349-postgresql-schema --append 0032_rfc371_observation_v2` 从同一 Drizzle 声明生成退役 + 新增步骤。迁移引擎的退役边补一项能力：被退役表连带的他表触发器与函数（v1 的变更捕获）先 `DROP TRIGGER` / `DROP FUNCTION` 再删表；既有步骤的回放结果不变。PG 历史链不可变，回放 0017–0031 仍需 v1 的三个 PG 投影生成器，它们保留在 `platform/persistence` 并标注“仅用于回放已发布的迁移历史，禁止新增调用方”。
- 已应用的迁移文件一字不改。

## 8. 测试策略

- 领域：快照合并（去重、替换、推理子集、未知 ≠ 0）、计价（整数纳元、部分定价、未归属、极小值）、价格选择（生效时间 / 创建时间 / 回填不改历史）、分位数、连续日桶。
- 驱动：OpenCode stdout 合并与 `task` 工具 → partial；原生库夹具（根 + 多层子会话、恢复会话时间下界、读失败回退、`:memory:`）；Claude assistant 分片去重、`modelUsage` 替换、恢复调用 partial、`error_during_execution` 全零不覆盖。
- 持久化（`describeEachProvider`，SQLite + PG）：受理 / 原地更新 / 结束 / 开机修复、模型行整组替换、价格 CAS 409、聚合查询（窗口、日桶、分组、上限截断）、非管理员可见性（不可见任务不计入、本人系统调用计入、超上限 partial）。
- HTTP：权限、参数校验、各接口形状。
- runner 接线：受理先于 spawn、受理失败不启动、节流写入、终态顺序、系统 Agent 走同一合同。
- 迁移：0256 后无 `obs_*` 触发器与 v1 表、tasks / node_runs 写入不再触发额外写；PG 0032 退役边回放与执行语句（含触发器 / 函数删除）。
- 前端：四个页签、筛选与分页、任务详情泳道与调用表、可读时长、未定价 / partial 展示、价格编辑 CAS 冲突、1280 / 390 宽度与明暗主题（e2e）。
- 架构守卫：platform 层无观测业务代码、`run-observability` 不读他域表、领域无 CrewStation 字样。

## 9. 能力影响清单（相对 v1 收缩的能力）

用户已授权完整重设计；以下为相对 v1 实现的收缩，均为“未发布、无现网存量”的开发期能力：

| v1 能力 | v2 处理 | 理由 |
| --- | --- | --- |
| 模型 / 工具调用级 span 泳道 | 删除；泳道粒度为调用（进程） | span 采集是存储大头；工具明细已在任务页的会话记录里可看 |
| 完整报告 / 计算缓存 / 增量投影 / 投影水位 / WS 版本推送 | 删除，改为按需聚合 + 30 秒刷新 | 派生数据 194 倍于原始事实、积压与滞后 |
| 用量逐记录修订账本、完整性证明、原生补采基线与修复缺口 | 删除，改为每调用一份可替换快照 + `partial/complete` | 同一口径（未知 ≠ 0、不重复计费）用更简单的结构表达 |
| 异常规则与持续异常列表、存储容量统计、维护操作、执行对比 | 删除 | 噪音大、用户未要求保留 |
| 历史回填（RFC-371 之前的执行、意图 / 记忆 / MCP 历史事实） | 删除；统计从 v2 上线开始 | 用户确认无现网存量 |
| v1 已采集的数据与价格 | 不迁移 | 同上 |
| CrewStation 托管观测同步与 `crewstation` 分支 | 删除，未来随 RFC-370 阶段 B 另立 | 未接线、违反 RFC-370 约束 |
| 任务子树汇总、`cohort=usage` 的任务列表 | 不提供；任务列表按创建时间、消耗统计按调用开始时间，两种口径在界面上分别注明 | 降低复杂度 |
| 按 IANA 时区分桶 | 改为按当前 UTC 偏移 | 同上 |
| 价格按运行时只有一条线 | 扩展为按运行时 × 实际模型 | Claude 子 Agent 常用不同模型 |

## 10. 不做 / 后续

- O8 风格的异步化不涉及本 RFC。
- 采集实时子 Agent 明细、OTel 导出、预算提醒、历史重算：如需要另立 RFC。
