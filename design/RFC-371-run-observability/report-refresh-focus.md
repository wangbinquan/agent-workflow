# RFC-371：后台报告替换后的泳道焦点恢复

## 已发生的问题

首次显示已完成报告后，后台仍生成新的完整报告。Windows 原 CI 37962987431 的观测无障碍用例已记录：重载后的旧报告 f0c65a24 先显示泳道，用户在 175323ms 打开尝试详情；新报告 3a9dc3dd 在 175918ms 完成，随后新泳道分页在 176189ms 返回。旧详情按现有 reportId 绑定规则关闭，旧按钮已卸载，原 Dialog 无法恢复焦点。原用例及重试在原 15000ms 预算下均失败。这是实际替换后的焦点丢失，不以删除焦点断言、增加预算或重试通过处理。

## 设计与范围

保留新报告完成时整体替换、原 reportId 详情关闭、所有四桶/CNY/缺口/人口/ACK/EOF及原明细错误规则。只修复 CompleteObservationTimeline 的原尝试按钮焦点恢复；共享 Dialog、ExecutionSwimlane、原完整分页合同不更改。

选择尝试时，同时保留其确切任务、原 filters 与 parent 的显示范围。当相同范围的新 reportId 替换已打开的尝试详情时，清除旧选择并记住原 attempt.id。等该新报告的原泳道分页成功显示后，通过现有 data-execution-id 找到相同身份的按钮并恢复焦点；查询不完整、错误、对应按钮不存在或用户已把焦点移到别的控件时不抢焦点。不同任务、filters、parent 或卸载时不恢复跨范围焦点。恢复完成后清除待恢复状态，不能在后续刷新中再次抢焦点。

不保存旧统计值到新报告，不延迟完整报告发布，不显示旧详情作为新详情，不设置人口或累计分页上限。其他详情、任务返回与滚动使用原实现，不引入全局弹窗状态或新共享组件分支。

## 实施与验证

在现有时间线组件加入范围绑定的待恢复状态与两个作用明确的 effect，继续复用共享 Dialog 和 ExecutionSwimlane。增加独立原组件回归：相同范围后台替换时旧详情关闭，新分页延迟返回后恢复同一 attempt.id；不同范围不恢复；错误/无匹配按钮不抢焦点；用户主动聚焦其他控件不抢焦点；恢复一次后后续数据更新不再次抢焦点。保留全部原案例、数字与预算，并保留原 E2E 的无障碍、390px/dark、Escape 和 toBeFocused 断言。仅 hosted CI 执行 AW 产品测试；本机仅精确格式检查及有限功能设计/实现门。
