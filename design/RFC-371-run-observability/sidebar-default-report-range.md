# RFC-371：侧栏返回复用实际完成的默认范围

## 问题与目标

`NavGroup` 的观测入口是没有查询参数的 `/observability`。原路由每次以 `Date.now() + 1` 生成不同的近七天范围；即使同一浏览器刚显示过完整报告，侧栏返回也不能命中它的原范围指针。2026-10-10 的正式侧栏实测生成新范围，原报告 `158588a6-5fda-4d82-bbc8-14c51e6b4cd4` 从创建至终态花费 19,033 ms，仍有完整的 37,533 行和 16,259 分组。此前相同显式范围重开约 907 ms 的修复不能代表这个入口已经变快。

本片只修复同一应用会话内的普通返回：默认入口继续打开最近实际显示过的、无筛选的近七天完整快照。保留原 URL 日期及“完整统计截至……；刷新可纳入后续记录”说明。初次进入、不同范围和首次完整生成仍单独验收；不改变统计范围、人口、四桶、人民币或缺口规则来获得性能数字。

## 原语与接线

新增前端 `observationDefaultRange.ts`，只保留一个内存中的原 reportId、from/to、timezone 及原 bookmark 的 `current()` 闭包。不保存统计数字，不新增持久存储、API、后端缓存或数据库结构。只有 `completeReportClient` 在原 GET/POST 响应通过既有身份、ID、精确 filters、taskId、内容及消费时间事实校验后，才登记范围；ready 与带已资格 facts 的 not-ready 都可登记，building、failed 和没有 facts 的响应不能登记。

登记仅接受无 taskId、没有 cohort/q/status/repository/workflow/selection 的原报告，并要求范围恰为七天、timezone 是浏览器当前时区。保存原边界，不取整、不挪动 to、不跨筛选拼接。调用方仍先执行原取消及身份检查。闭包或时区失效时不给路由范围；原 `discardObservationReportBookmark(id)` 同步退役相同 ID 的内存范围，不能清掉另一份后来完成的报告。

原 `validateObservationSearch` 只在原输入没有字段、或仅有 tab 时使用上述实际默认范围；任何显式 from/to、period、task、cohort、筛选或其它字段仍逐字按现有验证与缺省逻辑处理。侧栏、桌面/移动导航和历史链接保持原 Link 和样式。路由仍将实际验证范围 replace 到 URL，原任务/趋势下钻及浏览器前进后退不改。

再次进入页面后，原查询仍按相同 filters/taskId 获取同一报告，并执行所有原 GET 资格及明细校验；内存范围本身不能产生数字，也不能令坏报告恢复可见。原刷新按钮继续一次新完整构建与整体替换，构建期间保留上次已资格快照及其时间。显式周期选择仍以原当前时间生成新范围。新应用/新浏览器没有该内存记录时，仍走原初次生成；本片不宣称已解决首次约十九至二十秒的生成耗时。

正式返回验收另发现 QueryClient 的旧版本问题：刷新产生 B 后，初始 revision=0 的 A 仍可能在五分钟缓存中；页面重挂载重置 revision=0，原选择顺序会先取 A。同样，下一次刷新也可能误取上次 revision=1 的 B。修复只对原完整报告查询设置 `gcTime: 0`：最后一个观察者离开后收集该查询，不保留跨页面的旧 revision 数值；其它查询、原 key、GET/POST、404、非 404、取消与失效处理逐字保持。页面内原 `previous` 及被观察的有效性标记继续保留刷新期间的上次合格快照和时间。返回后走已经批准的原冷恢复，重新 GET 当前精确 bookmark B 并完成全部资格校验，不从指针复制数字。B 的 404 仍按原冷路径仅生成一次新报告，不能 GET/复活旧 A；403/502 等仍按原错误规则处理。真实 Router/完整页面回归保留应用的五分钟默认缓存，证明离开后原完整查询被收集、返回只读取 B、再次刷新产生第三份新报告，以及 B404/A仍可读时没有旧数字复活。A 的迟到退役不能移除 B；本修改不宣称首次生成已经变快。

## 验证与发布

先进行限定独立功能设计门。实现后保留原全部断言和预算，增加真实 Router/Link 与原完整页面的回归：默认报告完成后经其它路由返回，原日期、四桶、CNY、趋势和报告 ID 保持且没有第二次 POST；已有不完整 facts 的已知值同样保留；刷新仍产生唯一新报告。另验原显式 URL/筛选/Task/窗口消费及月/自定义周期不受记忆范围影响、不同身份/时区/撤销旧 ID 不复用，以及 building/失败/不合资格报告不能登记。

AW 本机不运行产品测试、typecheck、build、新服务或规模 CI。源码有限实现门、一次必要的原 canonical 配套及 exact-SHA hosted CI分别验收。正式页面在已授权的原服务/原 dev-admin 上实际执行侧栏返回；记录是否新增报告、真实时间范围及显示耗时，不以静态 PASS 代签性能或整个 RFC 完成。
