# 完整范围中的独立指标恢复

本修复恢复已批准RFC-371的正式统计能力。当前一个原始调用缺口使完整事实转换把全部Agent、运行时、模型、用途、趋势、尝试和调用指标替换为同一全范围缺口；这会抹掉已经独立核对完成的数据。

沿用同一原快照、所有Task/调用/用量到EOF及原scope fold。每条允许的事实行保留自己的原三态metrics；ready行必须严格满足十进制计数、四桶总和、已观测调用及原人民币状态，not-ready不允许数字，not-applicable不造零。任何包含缺口的该范围仍未知，全范围summary仍不能用完整子集小计替代。

模型维度只代表原始记录所确定的实际模型归属，未知模型/缺用量调用保留原质量记录与全范围缺口，不推测模型。原完整membership与全部scope人口保持；不从当前显示页重算，不限制Task/调用/记录/页数。

span-facts没有独立三态资格时仍不暴露usage/cost，原allocations/native/platform-capture等数字集合仍保持完整资格要求。生产file spool与持久页读取应用同一事实行资格，原seal/digest/manifest/count/receipt/EOF和故障拒绝保持。

同一完整Task遍历额外记录ready/not-ready/not-applicable的精确任务人数，其和必须等于该报告Task人口；用于说明哪些任务已有用量及哪些任务真实缺记录，不生成Token或费用下界。旧报告缺此字段时不猜人数。后台cache与SPA scope升级scope-metrics/3，旧不可变报告原样保留。

正式页显示各scope四桶/CNY，缺口提示描述自己的范围，并显示完整/缺口任务人数；不再使用“完整统计尚未就绪”让用户误以为任务和执行记录不可用。中英文一致。总范围缺记录仍如实说明，不能保证丢失的供应商原记录可恢复。

回归保留全部原断言与预算，更新仅属于旧全范围遮罩错误的期望；双provider以缺捕获Task和完整Task的实际独立报告逐scope对拍，核分页到EOF、混合Agent/runtime/purpose/模型、错误四桶/未知泄漏拒绝、旧cache及SPA升级，并核真实七天页面、原八Task集合和已有原始账单。AW本机只做精确format/lint/静态byte/AST，运行用例和全仓结论使用hosted CI。没有新增设计全景、总量限制或供应商费率。
