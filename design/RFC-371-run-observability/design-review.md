# RFC-371 / CS RFC-034 设计检视

2026-09-28，独立只读子代理 `observability_design_review` 按仓库功能设计门执行；范围为两份 RFC 三件套及必要的公开源码合同，未审阅/修改 RFC-370 并行改动。专用 review 插件不可用，采用仓库规定的独立审阅替代。

首轮 FAIL，四项均有具体反例：

1. 恢复调用累计 100→130 被按两次 invocation 加成 230。
2. CS 已有执行费用，但缺给托管 AW 的执行级人民币读取合同。
3. 崩溃 final 全零覆盖此前已知的 120 Token。
4. 0.1 元/百万 Token 的单次 1 Token 在微元存储中归零。

修订：native-session 谱系/基线/代次；usage 与 valuation 分开修订的业务接口；无效 final 不替代已知值；金额精确到 pico 元。复审又定位到 hidden→可见且任务无新事件时，已有费用无法通过增量游标补回，补充 visibilityRevision 与固定水位分页快照。

最终定向复审 **PASS**：原四项及追加反例均在正文闭合。此结论只证明设计合同，不代表生产采集、双部署联动、界面、性能或实机验收已通过。

2026-09-28 实施批次 1 功能门 **PASS**：计量算术与运行时目录投影；目录保留不可变注册身份及配置修订，只暴露协议、模型和启用状态，不读取启动材料或触发探测。配套 CS 价格配置的两项恢复缺陷在定向复审后关闭。后续账本、采集、两种部署联动与正式观测页面不在本批结论内。

AW 价格持久化／设置界面定向复审最终 **PASS**。前三项修复为 PG 已存在 head 的并发请求返回业务修订冲突、拒绝 Date.parse 无法解析的时区时间、不可变迁移表归属 run-observability。后续复审发现事务内真实 runtime directory 会再次占用 base pool，单连接配置自等待；已移至价格事务前查询，新增真实目录与持久层在仅剩一个可用连接时的回归。价格事务仍先读幂等回执，价格精确绑定预读配置修订。UI 原请求重放、关闭重开、配置变化保留草稿、导航保护和 CNY/null 呈现均通过源码功能检视。本结论不代替尚待执行的 hosted CI。

实施批次 2 用量账本定向复审最终 **PASS**。首轮发现无效终态先到时，旧有效修订被 stale 分支丢弃，投影依赖到达顺序；改为对迟到修订分页读取原始证据并按修订序重建。复审确认重复修订不重复贡献，明确 correction 可下降；四组正反顺序用例比较完整记录。此结论只覆盖账本基础，不代替真实源接线与 hosted CI。
