# RFC-371 原生会话集合采集实现

同一次 Task 调用可能创建 A、重置到 B，再返回 A。原来的单会话完成证明不能代表这一完整集合。本次实现按已批准的 `native-root-set.md` 增加显式 `opencode-child-root-pages-v3`，保留原 v2 严格单会话协议及已有数据。

## 原始事实与完整遍历

成功的 fresh、resume、reset 租约事务同时写入原始会话切换记录。记录绑定实际 Task、节点、调用、领取栅栏和原始租约；事务失败则不留下已接受的切换事实。采集完成前冻结原始切换水位，之后禁止改变该调用的会话集合。

原始切换和去重会话均使用键集分页，持续读取到真正 EOF。每页 40 个会话只是传输批次，没有最大会话数；所有原始 native 页面、步骤和数值覆盖也逐页读到 EOF。返回 A 时只采集 A 一次。开始时续跑的 A 保留并核对原始 baseline；随后新建的 B 使用实际出生时间与进程启动事实，不能把旧会话的步骤作为本次新消耗。

新增四张 Task 元数据表记录切换头、切换事实、冻结引用和逐会话完成引用，不保存第二套 Token 汇总。输入、缓存读取、缓存写入、输出及估值仍进入同一个既有数值账本。完成证明仅保留小型引用和摘要；消费者重新检查全部原始会话、页面、数值来源、ACK 与结果摘要。

## 部分采集与人民币

某个会话缺页时继续采集其他会话，保留已经提交的四类 Token 和可计算的人民币数值，并将完成状态标为不完整。输出未知、进程退出或 drain 事实缺失、原始出生时间不匹配，都不能产生完整标记。完成 ACK 丢失后的重试读取原始保留事实，同一调用不重复计费。

验收费率只用于明确标注的验证配置，不代表供应商账单。新增真实 Bun 子进程用例通过原始 SQLite/WAL、Task 领取和租约写入、原始数值账本及正式 CNY 定价器核对四类消耗：两会话 810 个步骤的验收值为输入 810、缓存读取 2430、缓存写入 4050、输出 14580，人民币 0.076140 元。还覆盖 A→B→A、超过一页的 41 个会话、较早会话缺页、未知输出、缺少或晚到的 settle、旧出生时间、真实文件 generation 被替换、完成 ACK 丢失后重建原 owner 和失败切换回滚；两个数据库 provider 使用同一行为用例。

## 迁移与发布边界

新增 SQLite `0240_rfc371_native_root_set.sql` 和 PostgreSQL `0016_rfc371_native_root_set.sql`，保留所有旧迁移的原始内容。原始 schema 生成器得到 221 张源表、215 张活动表和 6 张原有归档表；升级、备份和 schema 断言仅同步这四张真实新增表和第 240 项迁移，不修改原始行为断言和预算。

本机不运行 AW 候选测试、类型检查、构建或服务，只进行定向格式、静态 lint、原始 schema/迁移及 AST 元数据生成。新增用例的成功必须由精确提交的 GitHub CI 确认。全量验收仍使用原始 100000 个物理任务及 10000000 条调用用量，不降低规模、时间预算或完整遍历要求。

`rootSets` 默认关闭，尚未注入生产启动根。源代码和单元验收完成不等于生产采集已启用；开启前仍须完成精确提交 CI、真实运行回归、全量验收，以及 AW 独立部署和 CS 托管路径的实际采集闭环。此前 full-scale 失败证据保留，不改写为通过。
