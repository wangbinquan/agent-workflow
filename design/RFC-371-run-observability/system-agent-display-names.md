# 系统 Agent 名称显示修复

## 问题与原始证据

2026-10-08 的正式页面验收中，任务 `01M4D7YQ8KC4D9CB0H5WH51659` 的整体用量为 32,360 Token、验收人民币估值 0.043222 元；主执行及两次记忆提取均已进入原生记录，四类 Token、调用与尝试没有遗漏或重复。任务详情却将两次记忆提取显示为“未归属 Agent”，Agent 汇总显示“未观测”。

原因是 `completeObservationAgentNames` 仅查询普通 `agents` 目录。原始 `system_agent_observation_owners` 已在执行开始前保存 `agentId` 和 `agentName`，但名称查询没有消费它。框架工作流编排器同样没有普通目录行，其规范 ID 和名称由现行 `orchestratorAgent` 工厂定义。

## 设计

名称为展示属性，原有 Agent ID、版本、调用、原生记录、用量、费用、任务成员集合和统计分组键保持原义。

1. Task Execution 在原始报告的同一个数据库读取器上提供 `originalAgentName(id)` 公共只读查询。系统执行名称来自实际持久化的 owner 行：读取该规范 ID 的全部不同名称，只有唯一且非空的原名称才返回；缺失或冲突返回 null，不猜测身份。
2. 编排器规范 ID/名称移至 Task Execution 的纯领域常量。现行 `services/orchestratorAgent` 从同一常量构造原始 Agent，并保留原有导出兼容路径。查询对这个精确规范 ID 返回同一原始框架名称，不创建目录行，也不根据 ID 字符串推测。
3. 完整报告经 Task 的公共查询消费原名称。普通目录查询继续优先；无目录行时消费上述原始 owner/框架名称。正负工作缓存保持原行为及工作集预算。
4. 新报告缓存家族由 `scope-metrics/9` 更新为 `scope-metrics/10`，让刷新后的页面构建包含正确名称的新报告；已保存旧报告仍保持原有内容。
5. 原生报告 Worker 以 Task 公共 `CompleteTaskObservationFactsQuery` 约束实际工厂返回值，并把该同一值交给报告组合根。观测内部消费端口保留结构合同，删除其反向导入 Task 公共类型的边；不新增 RO→TE offered 边或豁免。现行 TE→RO 观测依赖及实际公共查询消费仍保留。

## 实施与验证计划

- 实现范围：Task 公共查询、完整 Task 查询与系统 owner 适配器；纯领域编排器身份常量及原工厂兼容导出；完整报告名称适配器、组合根、Task 消费端口及报告缓存家族。
- 增加双数据库回归：真实系统 owner 的无目录 Agent 显示原名称；框架编排器名称与原工厂一致；普通 Agent、未知 ID、缺失和冲突名称保持准确；名称修复前后原 ID、四类 Token、估值和分组数量不变。
- 保留原有限制和完整性断言，不增加统计人口上限，不修改原账本或历史执行事实。
- 运行一次必要的现行原始架构 census 及其归属输出；只更新真实新增消费/归属事实，保持原规则、基线及判据。
- 独立按路径功能设计门和实现门；不运行 AW 本地测试、类型检查、构建或 E2E，以远端 exact-SHA CI 为正式验证。
- 原任务及派生记忆执行结束后才写入后端源文件，避免本机 watcher 中断正在进行的真实验收。
- 用原任务重新构建报告，逐条证明 Token/CNY/成员 ID 与先前完整 EOF 回执一致，再验收正式页面名称和泳道。
