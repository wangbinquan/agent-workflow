# 分类 Token 展示与真实计量复验

日期：2026-10-01。状态：实现候选；独立实现复审、精确 SHA CI 和部署结果以后续回执为准。沿用已批准 RFC 与用户最新分类展示要求，不关闭完整 RFC。

## 统一口径

四类互斥消耗为非缓存输入、缓存读取、缓存写入、输出。总量为四类相加；输出包含 reasoning，不再把推理作为第五桶重复相加。OpenCode 原生输出与 reasoning 分开保存，原生入口合入输出一次；通用 completion/output_tokens、Claude 和平台已规范化用量保留原语义。

原生口径依据：实际调用使用 OpenCode 1.18.31；官方 `Session.getUsage` 从原生 output 中减 reasoning，processor 将此对象存入 message 和 step-finish：[源码](https://github.com/anomalyco/opencode/blob/014614d35b397775e5d397a490fc72368c894ec2/packages/opencode/src/session/session.ts#L321-L379)。新的 stream/native-child adapter 版本注明 1.15.5–1.18.31 和 @2。不能假定任意未来版本仍相同；旧受理记录只可在原 owner、原 record 的修订链内校正，不伪造补差记录或直接改账本。

## 页面

总览卡片、任务表、Agent 表、运行时/算力表及任务贡献表均直接显示总量与四类数值。分类区使用标准间距与无边框数字列表。任务趋势保持柱状图，四种颜色组成堆叠柱；柱顶显示实际总量，焦点/悬停区间显示四类精确整数，按键可选择并下钻到原时间区间。图例及标题包含分类，信息不依赖颜色或鼠标。

## 已知与完整性分开

兼容字段 `tokens.hasKnownBuckets` 是四个 boolean，来源为选中贡献逐桶非 null；已证明完整空树将四桶都设为已知。任务、Agent、运行时/算力、项目和系统汇总逐桶 OR，缺失 execution、截断或 native gap 不会擦掉已有的零证据。不能用 `unknownBuckets >= records` 推断全未观测，未知计数还可能含缺失执行，已证明空树则可能没有 record。

整体 `tokens.complete` 继续作为完整范围的严格判据。已知且完整显示数字；已知但范围未闭合显示 `≥ 数字`，包括 `≥ 0`；没有该桶证据显示“未观测”。仅输出未知时，输入仍可见，在完整范围未闭合时保守显示下界。旧响应缺新增字段时，完整数据和正数可以证明已知；非完整零保守保持未观测。金额不可见或未配置价格不改变 Token 证据。

计数格式及柱形比例使用 BigInt，金额沿用人民币精确小数；禁止美元展示和浮点汇总。分类证据是查询投影，不改价格合同，也不补造历史计量。

## 防护

原生 reasoning 合入、null 原生值回退 generic 时不重复合入、60 位整数/超安全整数、缺失 reasoning 保持未知、同 record 原修订替换均有回归。分类防护涵盖已知零+缺失执行、已证明空树+未知输出、native pending/partial、截断、隐藏费用、旧响应回退、两级/各分组数值和键盘选中堆叠柱。完整门禁和真实浏览器布局验收独立记录，不把只读夹具当作真实模型消耗。
