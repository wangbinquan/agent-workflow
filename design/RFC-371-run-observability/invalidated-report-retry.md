# RFC-371｜已失效报告的重试恢复

## 实际问题

2026-10-11 恢复原服务后，原正式总览显示 `Complete report was invalidated`。通过原“重试”按钮连续触发两次仍显示同一错误。现有 `completeReportClient` 保留原查询及 scope 内的报告 ID；被拒绝的 ID 留在 `completeReportBookmark` 的 rejected 集合中。普通 refetch 因而继续读取同一个不能再显示的快照。

## 设计与实现范围

沿用原顶部“刷新”的显式重新生成语义：统一一个页面回调，清除正在展开的维度，然后仅递增当前总览或当前任务的 revision。原 hook 由此取得新的 query key／refresh key，走原完整报告受理、完整人口采集、封存和整体发布。错误横幅“重试”和顶部“刷新”共用此回调。普通明细传输页的重试保持原协议。

不重新接受 rejected 快照，不解除原错误标记，不更改统计范围、任务／调用人口、四桶或人民币计算。任务详情只重新生成当前任务；总览重试只重新生成当前总览。原网络故障、失效报告与已经通过的报告回执继续保留。

## 验证

在原组件／Router 回归中令一次已完成报告的后续读取失效，点击原错误横幅的“重试”，断言新受理的 refresh key 不同、原筛选范围保持、后续完成报告显示完整已知数字及缺口。总览和任务路径均覆盖。实际执行依然以精确提交的 hosted CI 为准；正式浏览器另核重试后的柱状图、分类 Token 与金额。发布使用共享 main、限定文件；并行 RFC-370 输出完整保留。
