# RFC-371：运行观测与统计

- 状态：Draft，2026-09-28；本次交付为全景设计与可交互设计原型。
- 入口：运行与仓库 → **运行观测与统计**，独立于任务操作页。
- 配套：[技术设计](./design.md) · [交付计划](./plan.md) · [原型说明](./demo/README.md)
- 取证基线：`37a0e4978ff2c06211b4853c063ac9de6e86331f`。本 RFC 不宣称真实采集、告警或费用结算已实现。

## 1. 产品定位

让使用者能回答：一次任务花了多少 Token、多久、由谁花掉；多个 Agent 如何协作；哪里在等待、重试或失败；相同工作最近是否越来越贵、越来越慢。

把“看这一次如何执行”和“看一段时间如何变化”连在一起：汇总指标可以钻取到任务，任务可以钻取到 Agent、执行尝试、模型调用和工具调用；明细可返回原筛选条件下的统计页。已有任务页继续负责启动、取消、恢复、交付与评审；观测页负责解释发生了什么。

## 3. 用户与核心路径

1. **任务发起人**：总览看到异常 → 打开任务 → 在泳道定位耗时或重试 → 查看具体 Agent 的单次消耗与事件。
2. **Agent / 工作流维护者**：按定义版本、模型、仓库和任务类型筛选 → 看成功率、P50/P95、单位成功任务消耗 → 比较相同工作负载的运行。
3. **团队管理者**：在有权限的任务范围内查看趋势、模型分布、预算风险与数据覆盖率。统计权限不会扩大任务可见性。
4. **平台维护者**：查看采集延迟、用量缺失、重复或乱序事件、无定价模型；用户内容访问仍遵守原权限。

典型例子：任务用时 20m42s，6 个 Agent 累计占用 35m47s。这是并行执行的结果。泳道显示 2 分钟人工等待，Backend Engineer 的失败尝试产生 25K Token；重试成功也不能抹掉这笔消耗。

## 4. 信息架构

```text
运行与仓库
  任务
  运行观测与统计   /observability
    总览
    任务追踪        → 任务详情 → Agent → 执行尝试 → 调用 / 事件
    Agent 分析      → Agent 跨任务汇总 → 单任务贡献 → 全部尝试
    Token 与成本    → 模型 / 仓库 / 来源归因 → 关联任务
    性能与异常      → 慢任务 / 重试 / 失败 / 等待 / 采集健康
  定时任务
  事件中心
  远端仓
```

顶层共用筛选：时间范围、时区、仓库 / 仓库组、任务来源、工作流 / 工作组版本、Agent、模型、任务状态。首屏只露常用条件，其他放“更多筛选”；条件同步 URL，返回与分享保留筛选。任务来源至少包含单 Agent、工作流、工作组和数字员工启动的任务。数字员工 Case 是业务上下文，不是新增一笔用量。

### 4.1 总览：先发现问题

- 运行中 / 等待中数量；成功率明确终态分母；总 Token、已知费用、P95 完成耗时、采集覆盖率。
- Token 堆叠趋势与任务吞吐分图，避免双轴造成误读；点击时间桶进入同条件任务列表。
- 任务消耗排行、Agent 消耗排行；异常摘要指向实际任务。
- “我的可见任务”范围提示、统计时间范围与 asOf 水位始终可见。缺失用量时显示“已知用量”及覆盖数，不显示虚假的精确总额。
- 空筛选显示调整筛选入口；采集未启用与无任务是两种空状态；部分失败仍显示成功分区；禁止把接口失败渲染成 0。

### 4.2 任务追踪：本次交付重点

列表：任务名 / 来源 / 仓库 / 状态 / 总 Token / 历时 / Agent 数 / 重试 / 数据质量。支持排序、分页、比较同一工作负载的两次任务，以及 CSV 导出。

详情固定显示任务范围与数据完整性，并提供三个互相联动的视角：

| 视角             | 内容                                                              | 关键动作                                     |
| ---------------- | ----------------------------------------------------------------- | -------------------------------------------- |
| 执行泳道（默认） | 调度与人工等待、Agent、子任务、重试、模型 / 工具调用，统一时间轴  | 展开、选择片段、缩放、定位关键路径、查看事件 |
| Agent 汇总       | 此任务内每个 Agent 的运行数、Token 分项、累计占用、重试与失败消耗 | 点击 Agent 查看此任务所有尝试                |
| 执行明细         | 每个 NodeRun / 调用的精确身份、状态、模型、时间、用量及来源       | 从泳道到明细双向定位                         |

**泳道语义：**

- 横轴是任务起点之后的相对时间，可切绝对时间；纵轴默认按“Agent 在此任务中的身份”分组。同 Agent 的并行尝试排子行，不覆盖、不伪装成串行。
- 工作组按成员 / 回合展开，工作流按节点 / 容器帧 / 循环 / 分片展开；同名 Agent 以稳定 ID 与版本区分。
- 单条 Agent 长条表示执行生命周期；展开后显示模型、工具、排队、人工等待等互不混淆的片段。暂停与恢复拆段，不能把等待涂成模型计算。
- 错误有文字与标记，重试显示 #1/#2 及连接关系；人工等待使用纹理；运行中有开放右端与快照水位；未知时间段用虚线并标“缺少事件”。
- 父级汇总是轮廓条，叶子活动是实心条；父级和子级不能一起求和。工具调用耗时与父模型请求若重叠，不能直接相加。
- 关键路径只在依赖与时间覆盖足够时展示；否则提示“依赖数据不足”。不能拿最长 Agent 当关键路径。
- 选择片段显示状态、起止、独占 / 包含耗时、Token、费用依据、失败码和相关事件。默认不加载 Prompt、代码正文或推理文本。
- 大任务默认折叠 Agent，支持按失败 / 名称查找、时间范围缩放、虚拟行。窄屏保留横向时间轴，固定名称列；另有完整执行明细作为键盘 / 阅读器等价入口。

### 4.3 Agent 分析：看单次，也看累计

- 跨任务汇总按稳定 Agent ID + 定义版本（可合并版本）聚合；显示参与任务数、执行次数、Token、输入 / 输出 / 缓存、累计占用、失败率和重试率。
- 单 Agent 详情先显示趋势和模型构成，再列“每个任务贡献”，展开后列所有回合 / 分片 / 重试。
- 区分主 Agent、平台调度 Agent、runtime 内部委派 Agent。无法归因的部分保留“未分配用量”，不可复制到所有成员。
- 同一个 Agent 多个并发实例的总占用允许大于任务墙钟；Agent 汇总不是人效排名。

### 4.4 Token 与成本：解释消耗构成

- 非缓存输入、缓存读取、缓存写入、输出四桶堆叠，推理 Token 作为输出的已知子集，不再重复相加。
- 按模型、Agent、工作流版本、仓库、来源查看分布和明细；选择某柱直接钻取任务。
- 区分上报费用、按价格版本估算、未知费用。页面统一人民币 CNY，清楚标价目生效时间、元/百万Token单位、覆盖率；没有价格显示“未定价”，不显示 ¥0。
- 缓存命中率 = cacheRead / (inputUncached + cacheRead + cacheWrite)，分母为 0 时不可用；未知数据不参与伪精确比率。
- 可配置“单次任务”和“期间范围”的提醒预算。提醒不是执行限额，不改变已有 maxTotalTokens 语义；如需自动停止，另立行为变更并明确授权。

### 4.4.1 运行时 Token 成本配置（2026-09-28 补充）

**AW入口：工作台设置 → 运行时 → 选择运行时 → Token 成本**。观测页“Token与成本”增加“配置 Token 单价”快捷入口，指向同一份配置。

当前 `/settings?tab=runtime` 由 `packages/frontend/src/routes/settings.tsx:432`、`:537–547` 挂载 RuntimeList；现有运行时编辑支持协议和模型（`packages/frontend/src/components/RuntimeList.tsx:496`、`:554`），`RuntimeView:67–95` 尚无价格字段。因此本节是设计增量，生产当前不能在这里填写Token单价。

- 每个运行时注册项按模型服务与实际模型分别定价；相同 OpenCode / Claude Code 协议不能共用一个隐式价格。Agent覆盖模型或执行中换模型时，按实际身份匹配，匹配不上显示未定价。
- 系统管理员填写非缓存输入、缓存读取、缓存写入、输出四项价格，单位固定人民币元/百万Token；0表示明确免费，未知不能填0。
- 价格配置和运行参数分开保存；不触发现有运行时编辑的模型测试、进程重启或模型切换。
- 生效时间与版本明确；只追加新版本，之后新受理的执行采用新价，历史和已受理执行固定原价。历史重算独立、显式、可审计。
- Demo新增价目表、单个运行时配置弹窗和版本历史；所有费用改为人民币，人工示例价格不代表真实厂商报价。关闭表单保留草稿，保存仅影响当前演示会话中的待生效版本。

**与CrewStation的关系**：AW独立执行时在AW维护价格。AW经CrewStation执行时，以CS返回且被合同授权的执行级CNY估算为成本来源，AW按业务任务/Agent归因，不再叠加本地推算。同一请求的CS统计与AW统计是两个视角。当前CS合同尚未提供该费用投影，未接入之前显示未定价；不从CS管理员采购单价或其他项目推断成本。该联动在RFC-370/CS RFC-034后续合同中验收，本原型不宣称已实现。

### 4.5 性能与异常：解释为什么慢与贵

- 完成耗时分布、P50/P95/P99 与样本数；排队 / Agent 活动 / 人工等待 / 其他状态时间分解；运行中任务单列，不能塞进完成延迟分布。
- 模型调用延迟、首 Token 延迟、输出速度、工具耗时 / 错误率，仅在 driver 支持时展示。
- 重试放大、失败消耗、预算阈值、人工等待超时、工具超时、用量缺失、采集延迟。
- 告警带阈值、观察窗口、最少样本数、去重 / 恢复逻辑和证据链接。原型展示异常规则效果；规则创建与通知投递为后续阶段。
- 质量指标另列：采纳、评审通过与返工需要可关联的交付事件，不能用 `done` 替代质量得分。

## 5. 必须固定的统计口径

1. **实际消耗保留全部执行尝试**：失败、取消、被新代替换、返工产生的真实消耗都计入。另提供“最终采用路径”过滤，但不作为默认成本总额。
2. **树形只展示，叶账本求和**：同一 usage record 只贡献一次；父 Agent 汇总、子 Agent 明细、任务总额不是三笔费用。
3. **任务生命周期 vs 窗口消耗分开**：任务列表按开始时间选样本，金额 / Token 趋势按用量发生时间；两者切换时显示口径，跨日任务不硬塞回开始日。
4. **完整性是一等结果**：未采集、尚未上报、部分缺失、估算、最终值明确区分；已有历史 0 不能自动证明真实零消耗。
5. **墙钟不等于运行态，也不等于 Agent 累计占用**：各列命名固定，详情提供区间与公式；P95 取任务终态分布，不平均每日 P95。
6. **多仓不翻倍**：同一调用属于多个仓库上下文时标“共享 / 未分摊”。按仓库筛选取集合去重，不能把每个仓库的包含总数再相加。
7. **统计服从权限**：列表、图、分母、排行、搜索建议、导出均先授权后聚合；看得见 Agent 定义不等于看得见他人运行。

## 7. 验收标准

- AC01：独立入口位于运行与仓库，任务详情和 Agent 详情能相互回跳，条件不丢失。
- AC02：6 个 Agent、8 次执行、有并发 / 重试 / 人工等待的样本，任务、Agent、尝试、Token 分项可逐层对账。
- AC03：相同事件重复投递、迟到、父子累计上报不会重复计费；失败与取消消耗不丢失。
- AC04：工作组回合不误计为技术重试，循环 / 分片 / 容器身份不混淆，嵌套子任务只计一次。
- AC05：并发累计占用、墙钟和等待时间解释一致，关键路径缺依赖时不编造。
- AC06：未知 / 部分用量、未定价、运行中、重启中断、空结果、加载失败均有明确状态。
- AC07：授权过滤覆盖全部统计与导出；撤销权限及时生效，无计数 / 排行旁路。
- AC08：桌面 / 390px 窄屏 / 明暗主题、键盘选择片段、展开与弹窗关闭可用；长泳道独立横滚，页面不截断。
- AC09：新采集有水位和可恢复 offset；100K 任务筛选与聚合达到 design 的目标预算，无全量拉到浏览器。
- AC10：UI 复用现有 TabBar、TableViewport、Card、Select、Segmented、Dialog 与 token；完整实现经对应 exact-SHA hosted CI 验收。

## 8. 本次原型的评审路径

从总览进入“认证模块重构与回归验证” → 在泳道展开 Backend Engineer → 点击失败尝试和重试 → 切到 Agent 汇总核对 206K → 到 Agent 分析看跨任务明细 → 切仓库与时间范围 → 查看部分数据任务和性能异常。

原型使用明示的合成样本和示例费率，所有统计由同一 fixture 派生。它复用现有前端公共组件，但运行在 design 目录的独立静态入口，不注册生产路由、不调用真实后台、不创建真实任务。
