# 历史完整统计的功能 CI 修复

## 原始失败与范围

`c81fc950` 的主 CI `37796345707` 确认了历史统计类型错误、旧缓存版本断言和遗漏的弹窗登记。`976f590e` 的 Windows CI `37796671343` 确认两个历史来源适配器违反原 RFC-143 的运行时判别守卫；980 个用例通过，1 个失败。失败原日志保留，不能用定时 CI 的通过替代主 CI 或 Windows 终态。

本批仅修复这些已批准观测能力的接线和类型问题；全量来源、原生数值、四种 Token 分类、历史去重、人民币费率快照、Task cohort 和未知事实语义均保持。

## 修复设计

1. `CompleteTokens` 的兼容趋势输入并不声明历史引用数，读取可选历史覆盖字段前按真实字段存在性收窄。历史指标仍显示原引用覆盖，兼容趋势仍显示已记录四桶，不生成不存在的历史人数。
2. 历史 UI 夹具将已知 `not-ready` 指标声明为该分支。原部分人民币缓存用例仍保留 capability 7 的旧数据和全部原断言，仅把新请求的期望缓存键对齐生产中的 `scope-metrics/11`。
3. 为 `CompleteHistoricalObservations` 的两个实际共享 Dialog 添加原双向弹窗清单登记，行为测试仍由历史 UI 用例负责，原清单算法、全部原记录、移动端责任和断言保持。
4. 仅在完整观测的内部贡献类型上声明已收到的可选原始 `measurement.usage`；平台贡献不伪造这个字段。写入本机原始去重证据时要求该字段实际存在，保持原四桶原值，不能用分摊后的贡献代替原值。
5. 原 OpenCode 读取器对克隆的泛型身份作显式类型绑定，再冻结同一对象；返回页作显式同身份绑定再交给原 pending/ACK 流程。原 SQLite 快照、分页调度、全部树深度、数值解析、重复页和 EOF 均保持，无类型强转抹掉检查。
6. 原历史报告测试使用公共 `CompleteObservationSection` 类型声明页参数，并给原严格相等断言明确可空类型；预期值、人口和预算不变。
7. Task/Intent 历史来源使用既有公共运行时状态合同的 `protocol` schema 验证保存的原协议值。业务适配器不再自行枚举协议、推断当前注册表或选择驱动；原支持的协议和未知值返回空保持。补充真实双数据库来源查询验证两种原协议及未知值。

## 验证与交付

实施前后使用独立有限功能检视，核对原断言、完整输入及候选字节。原源登记按最终候选一次派生，不修改规则、阈值、库存基线或既有 opaque why。仅进行本批格式和 lint 自查，不在本机启动 AW 测试、typecheck、build、服务或 E2E。

精确路径提交和远端同步后，以该 SHA 的 hosted 主 CI 与 Windows 终态分别验收，再核对正式页面的历史四桶、人民币和缓存刷新行为。所有类型任务的真实模型验收仍须继续；本批 CI 修复不声明它已经完成。
