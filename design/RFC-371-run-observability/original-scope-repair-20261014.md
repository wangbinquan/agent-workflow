# 原始归属、诊断 EOF 与记录库存修复

正式页面原库只读快照发现 3 条当前贡献引用的历史组已失效。其组历史均在 root 单组件的 original-bootstrap-upgrade 中撤下，引用的 task 组件仍保留旧组 ID。原 owner 的当前会话可以指向另一个 session；仅用根 ID 查询当前 owner 不足以恢复历史事件关系。

原资格计算在同一原始快照中读取受影响 root 的耐久组关系，将原 owner 纳入受影响闭包，再读取该 owner 的当前原始事实。删除或会话变化都更新整个有关 bundle，不能保留悬空引用；不打开其他不相关任务，不通过数字回退或补零隐藏缺口。indexed-details-v4 独立 checkpoint 重建当前派生索引，v1/v2/v3 的旧 checkpoint 和游标保留。原始事实、价格、native EOF 和版本区间不变。

CI 的 historical-executions/original-source 差异来自旧用量窗口路径遗漏执行诊断。原窗口现在与增量窗口共用原始诊断判定，保留全部原执行、记录、关联和版本诊断；数值准入仍按原筛选及半开时间窗，不将诊断数字加入选定总量。所有旧 EOF/数量/完整文档断言保留，额外用例要求数值排除时两个原执行仍可逐页到真实 EOF。

库存计数与获准计费的记录不同：混合归属原记录仍属于已收到库存，原 cohort numericRecords 保留，只有 usage 窗口按获准范围 fold.records 统计。未解析归属不再丢失原 inventory 字段。明确维度排除的 Task 不携带被排除源的缺口；选中调用或历史引用的原缺口仍保留。

生产实现与全部用例先写齐，再集中修复验证。首次隔离 SQLite 的 31 个原数值用例为 27 通过、4 失败，保留原日志；其后针对这些失败及新根关系的 6 例通过、0 失败，288 断言。该隔离诊断用原内存 fixture 和私有临时 native 文件，不读取或修改正式数据库。双 provider 和整仓结论仍以新提交 GitHub CI 为准；有限 SOURCE、正式页、实时更新和长期存储验收分别记录，不能据定向结果宣布两个 RFC 完成。
