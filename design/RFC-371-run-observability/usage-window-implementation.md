# 实际消耗时间窗口实施

## 既有要求与当前差额

本片落实已批准设计 §5 的 `cohort=usage` 和剩余清单 AW-R06；原默认 `cohort=started` 保持。任务开始时间选择的是整项任务的生命周期消耗。实际消耗窗口选择原账目中可证明发生于 `[from,to)` 的贡献，跨日任务可以出现在多个日桶。日期、时区、查询、状态、仓库与维度选择继续使用正式完整报告，不增加“更多筛选”、CSV 或统计总量预算。

当前 `ObservationTaskPageQuerySchema` 没有口径参数；Task owner 的完整读取按 `startedAt` 筛选。`CompleteObservationAllocation` 只有接收时间 `observedAt`，完整 cohort 的趋势也用任务开始时间。因此不能仅增加一个标签或把 `observedAt` 改名为 `occurredAt`。本片的实现、实际页面及精确 SHA CI 尚未完成。

## 查询与报告合同

1. 增加可选 `cohort: started | usage`，省略仍为 started。省略参数的旧筛选 echo 不增加字段；旧默认缓存、任务直达和生命周期数值保留。
2. 完整报告的 usage 分支要求 Task owner 读取同快照的全部可见候选，保留原搜索、状态、仓库、工作流、排序和游标。移除这个分支的开始时间谓词，不以 `from=0` 或某个很大的 `to` 模拟“全部”。出生在窗口前的任务不能被提前漏掉。源页面大小只控制传输，全部来源仍读到真实 EOF。
3. 旧同步 GET 在不能提供完整 usage 合同时明确拒绝该新参数；不得接受 usage 后静默返回 started。正式页面使用完整报告。
4. 原记录的去重、修订、覆盖选择和计价先完成。随后按发生时间分为 `in-window`、`outside-window`、`unassigned-time`，分区不修改数字或原价，不再执行第二套 Token 选择。
5. 三个分区的原分配身份构成原候选贡献的精确不相交集合。四桶 Decimal 字符串和 CNY Decimal 字符串逐项对账；未知桶、隐藏/未知费用保持原状态。区间外仍保留分区证明，不计入窗口数值。
6. 增加分页的时间未分配明细及独立摘要。窗口总览、各维度、Task、Agent 逐任务贡献、原生调用和日趋势只累计窗口内贡献；时间未分配值单列。不能把全生命周期金额或未分配金额塞进窗口金额。
7. 有不能定位的非零/未知贡献时，窗口总体保留不完整状态和已知四桶/CNY。未分配摘要保留原已知值及缺口；空记录、没有匹配、未采集不能证明零。只有原完整空证明能支持相应已知零。
8. 有发生时间的原步骤按用户时区进入唯一日桶；日桶不改变 `[from,to)` 的毫秒边界。未知发生时间不按比例分配，也不使用 Task 开始/完成、受理、接收或补采时间代替。

## 发生时间的原始证据

### 本地 OpenCode

`ObservationMeasurementSchema` 已持久保存独立的 `occurredAt`；`nativeUsagePageEmission` 直接取原 `step.occurredAt`。首先保留这份原测量时间，不能丢失之后再用接收时间补。原 `opencode:step:` 单步测量及具有原 request 级离散时间合同的 self 贡献可使用其已证发生时间；不能只凭 `reporting=delta` 推断离散时刻。`self-total` / `tree-total` 等累计 summary 不因存在一个最终时间就整笔进入该时刻。

旧记录没有原测量时间时，`stageHistoricalObservationSources` 已在同快照读取原 owner 引用、原 native 根及步骤至 EOF，并保留版本。复用这份 TEMP 原始资料，按原 native source、原 `opencode:step:` 身份及原四桶 usage 匹配分配证据；模型/provider 的已知值不得冲突，未知值不借时间匹配补价。

- 被分配四桶是已有覆盖选择的贡献；匹配使用 `original-native-allocations` 保留的原测量，不能拿扣除子树后的贡献去冒充原 SDK 测量。
- 原步骤匹配唯一且所有相符版本的发生时间相同，才能给出原 `step.occurredAt`。无时间、版本间时间冲突、不同来源/模型/原测量、非步骤 summary 都给出具名时间缺口。
- 历史更正属于原步骤的发生时间；保留原 invocation/Task/Agent 和原冻结价格。缺失旧原版本时保持时间未分配，不借当前步骤的不同数字反推旧时间。
- 原 accepted 分配和被其覆盖的历史步骤不重复进入任何分区。未受理的历史原步骤仍沿用现有候选归属/修订判据；多义 Task/执行保持原缺口，不能为了给时间而挑选一个 owner。
- usage 分支同时移除独立 system group 和历史 owner 的开始时间资格。历史候选先仅按原 owner/root/record 身份及搜索、状态、仓库、工作流、维度判定非时间归属；owner 的 `startedAt` / `createdAt` / Task cohortAt 在窗口外或未知，均不得提前把步骤标为 excluded/unresolved。完整非时间候选、身份冲突和 accepted 去重处理后，才用原步骤发生时间分区；步骤时间未知仍进未分配池。started 分支保留原时间资格。独立记忆提取等历史执行不依赖 parentTask 才能纳入窗口。
- 不读取可变 SDK 存储来补报告，不改已提交的数值记录、源 hash 或原生 completion 证明，不为此重跑模型。

### 平台与其他来源

平台只接受原授权 usage 项自己的、可证明对应这笔离散贡献的 `occurredAt`：原 request 级单步的 self 测量，时间合同不能只由 `reporting=delta` 推断。缺少离散时间合同的累计/summary 来源保持未分配，原 CNY valuation 继续按原 item/revision 使用；不以 AW 费率重估。Claude 或旧协议没有发生时间证据时声明该能力缺失；Token 仍保留，不能用 stdout 收到时间伪装真实消耗时间。

## 汇总与下钻

- usage Task 列表按窗口内/时间未分配贡献产生任务成员，不把所有历史任务都显示成窗口内执行。已知零、时间不明、未采集各自保留可解释的原人口。
- invocation 与维度折叠依据同一分配成员，不能复用已含生命周期数字的 invocation fold。原执行完整性与“时间能否定位”分别保留；尝试数、状态和生命周期耗时标明其口径，不能把整段耗时冒充窗口活动耗时。
- Agent/运行时/模型/来源/用途及 Agent 逐任务下钻共享同一分区；现有服务端维度选择同时作用于窗口和未分配池。没有数字但有原质量证据的成员仍有说明。
- 任务详情继续展示全生命周期，明确提示“此处显示任务全程”。从 usage 页面进入、返回，保留原窗口、时区、查询、状态、维度、口径、焦点与滚动；详情不能把窗口小计称作任务整体。
- 内存仍使用有界缓存与 TEMP 关系；索引或页面只影响读取方式，不改变人口或四桶。

## 正式页面

在现有趋势区域放置紧凑的“任务全程 / 窗口内消耗”口径控件，切换更新 URL 和完整报告范围。窗口模式的时间未分配量以简短说明和明细入口呈现，不新增整屏告警、灰色占位柱或任务分类大卡片。柱形仍只用四桶颜色，并显示实际 Token 数值。全局摘要仍只在总览显示；其他页签保留各自内容。

## 必需回归与退出证据

- 原默认查询和 started 全部分区/四桶/CNY/任务范围不变；旧同步 GET 对 usage 不产生错误口径的成功响应。
- 开始在窗口外、两个实际原步骤分别在窗口内外；同一 Task 跨日，两种口径手算不同且可解释。边界 `from` 包含、`to` 排除；跨时区与夏令时保持原毫秒归属。
- 真实 provider 覆盖独立历史 owner 窗外而步骤窗内、owner 全无时间而步骤已知、步骤时间本身未知；验证非时间过滤及归属多义仍保持原判据，不能由 Task 查询放宽掩盖历史 owner 提前漏算。
- 已知发生时间、未知、冲突版本、没有 native source、错误模型/来源/原测量；接收很晚、历史更正及完整空证明分别覆盖。
- 超原 200 Task/10000调用等旧边界；同一个巨大 Task/根、续页、取消和失败仍保持完整分区。分页不改变总览/日桶/Task/Agent/维度数值。
- 原 accepted 与 historical 去重；原四桶贡献及原冻结 CNY 与三个分区之和逐项相等。不合并重叠报告，也不重新调用估值获得当前价。
- 真实 SQLite 和 PostgreSQL、公共 API及正式页面的中英文、键盘/URL/返回/原焦点、窄屏与颜色数字验证。AW 本机不运行测试、构建或服务，执行测试以本次确切 SHA hosted CI 为准。
- 有限设计门、实现门、必要架构原登记、精确路径发布、确切 SHA CI和实际页面分别留证；完成之前 AW-R06 与两个 RFC 保持进行中。其他内置 Agent/Git/定时/事件实跑和 CS 发布例外的待答复项继续保留。
