# 自由调整观测时间窗

用户要求 AW 与 CS 一样允许自由调整起止时间。原 AW 已支持 `period=custom` 和精确的 `from/to`，但筛选栏仅提供近 7 天、近 30 天、全部；自定义范围只能由趋势图或已有链接带入。这是正式页面入口缺口。

在原 `ObservationFilters` 中增加常驻起止时间输入和“应用时间范围”，复用 AW 的 `Field`、`TextInput`、`Select` 和标准按钮，并对齐 CS 正式页的两行布局：第一行起止时间、应用和快捷时间按钮，第二行任务搜索、状态和仓库；标签置于控件上方，按钮底部对齐，窄屏使用标准间隔换行。输入采用浏览器本地时区，应用后仍使用原 epoch 毫秒、原 URL、原完整报告查询和预计算投影。编辑过程中不变更查询；应用有效范围后设置 `period=custom`、清除旧分页与行级选择，并保留页签、仓库、任务查询和维度条件。自定义范围不随实时投影推进移动边界；该范围内的新数据继续沿原刷新机制更新。

快捷范围补齐近 1 天，保留近 7 天、近 30 天和全部。四种快捷范围共用当前截止时间，不因切换周期产生另一份数值构建。起止时间常驻显示，直接编辑后应用即进入自定义范围；删除重复的时间下拉。未修改的边界保留原秒和毫秒；空值、逆序、相等、日历溢出或不存在的本地时间拒绝应用，使用紧凑错误文案和控件关联。

回归覆盖原组件编辑延后应用、精确边界、原筛选保留与分页清除、四个快捷按钮共用截止时间、CS 两行入口、中英文本及无效时间。既有趋势下钻、共享链接、详情返回、投影实时刷新和完整 EOF 回归保留。新增用例执行以原 hosted CI 为准；源码检视、实际页面与远端 CI 各自记录，不相互代签。

日期编辑期间仅暂停快捷周期的截止时间推进，已提交数据仍按当前精确时间窗刷新。草稿保留编辑开始时的完整毫秒边界；外部趋势下钻或后退改变时间窗后丢弃旧草稿，防止旧输入覆盖新范围。实组件投影更新回归覆盖仅编辑开始时间时结束时间的秒／毫秒保持，以及应用后的自定义边界固定。

## 正式头部与 Token 卡修订

按用户要求，时间控制复用 CS 的交互布局，不再保留与日期输入重复的周期下拉。观测时间口径保留在可访问的时间控件组名中，快捷按钮保留当前选择状态。日期编辑离开到任务详情时通过卸载回收解除父级暂停；返回后新的投影版本继续推进普通周期。

分类 Token 数值与记录覆盖计数分区：四类值只显示 Token 数字，完整分类采集用一行明确的记录说明，不完整分类则在独立“分类用量采集情况”组内保留每类分子／分母。总 Token、未知分类、实际零、未采集调用、历史引用与人民币估值的原信息保持。摘要列宽按最长的完整数值确定，窄卡片减少列数，数值保持单行。

本机原服务正式页自定义窗口 `2026-10-01 08:15` 至 `2026-10-10 19:30`（Asia/Shanghai），URL 为精确 epoch `1790813700000`／`1791631800000`，呈现 145 任务、460 次执行、2,845,407 已记录 Token（1,323,978 输入、1,324,928 缓存读取、0 缓存写入、196,501 输出）、已记录 ¥4.244782，缺口标记保留。1280／1024／390 宽度下数值均为单行，390 的页面宽度和滚动宽度均为 390；恢复默认浏览器尺寸。截图在本机验证目录，源码门与 hosted CI 独立核对。本地未执行 AW 功能测试、typecheck、build 或完整门。

原刷新回归中“点近30天会改用 Date.now”的旧期望与共享截止时间合同冲突；本修订将四项时间期望对齐原窗口截止毫秒，保留原第二报告、缓存与返回断言。没有以缩小人口、延长预算或删除用例来掩盖旧失败。
