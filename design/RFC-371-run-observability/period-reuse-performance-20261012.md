# 统计周期复用的性能修复

2026-10-12 继续处理正式页面的周期切换。原同月热报告仍为 10,171.229 ms；189 Task 数值缓存命中时，历史 owner/native 读取和原关联构建仍在运行，不能称为性能验收完成。

周期控件原来每次用 `Date.now()+1` 生成不同截止时间，切回旧周期也成为新条件。修复为周期切换沿用当前截止时间，显式刷新才推进 week/month/all 截止时间；custom 原边界保持。仍从正式报表接口读取、校验对应的完整报表，不从展示页累加统计。

后台历史准备使用原主库计算版本/明细表，沿原 snapshot 和原 Worker 导出、关闭原 reader 后导入。键包含完整 55 关系 revision、原 native 连续版本证明、Actor scope 和算法版本。不同周期共享完整原执行、父 Task、事件引用、原生记录/版本、全部归属候选、完整来源回执；scopeMatch、cohortAt、timeBasis 和选中成员由当前完整 Task 页与精确时间边界重新判定。

每个历史命名空间的数量和摘要通过独立 group 行记录，版本头只保存总数量和摘要，不把所有分组放进一个无界数组。导入与缓存读取均到真实 EOF，完整比较所有分组、每条记录顺序、总数与摘要后再恢复原数据。100/200/250/500 是 I/O 批次，不限制统计总体。缺行、损坏、额外分组或源变化时继续原全量读取。历史准备保留每一个已知原生读取缺口及其原始回执；复用时逐条重试无法读取的根，重建它涉及的完整归属候选，不把未完成原 native EOF 变成完整 Token，也不因一个旧缺口重复解析全部可读根与 owner。

缓存恢复在同一 TEMP relation 内完整复制命名空间，减少每个分组一次往返；当前 Task 归属按页批量读取和重写。缓存不改变四类 Token、未知值/零值、原任务/调用归属、重复及冲突判断、原费用版本和人民币金额算法。

新增真实双 provider 回归覆盖超过 1,000 原生记录、完整候选、不同周期及返回旧周期、缓存损坏和 Actor/业务/native 变更；正式 Worker 回归继续比较全部可读组、四桶和人民币。前台回归验证固定截止时间的旧周期 GET 复用、显式刷新获得新报表。当前候选已接入原 Worker、原读写通道、文件 transport 和 reader 关闭后的 writer 导入；新用例已编写，尚未执行，测试以提交的确切 SHA hosted CI 为准。新真实 API/正式页面耗时和完整结果对照未验收，不宣称已达到目标性能。两个 RFC 保持 In Progress。

首次接线实测（v399）仍需 11,344.102 ms；历史准备因旧缺口整体未保存（prepared=false），任务计算命中 189 个。原四桶及人民币、全部 87 个实际 API 页保持一致。此失败测量保留；后续候选修正为独立重试缺口，新的耗时另验。
