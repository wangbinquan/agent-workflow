# 原始 before 快照：CI 查询计数修正

2026-10-06，确切提交 `b386d3108c6cd8474ca286e88ccd1f1f3d2c99d7` 的
[CI](https://github.com/wangbinquan/agent-workflow/actions/runs/37341993640)
在 SQLite 与 PostgreSQL 的 2,501 个原始成员用例中均报出：预期 81，实际 82。

原始 `verifyNativeUsagePass` 读取 81 个完整页后，还执行一次 `count(*)` 核对
页总量。语句记录器记录该聚合查询返回的一行；原用例误把它算成第 82 个完整页。
生产校验没有漏页，也不能为了满足测试去删除总量核对。

本次仅修正测试的计数方式：完整页读取仍必须精确等于原始 `pageCount`，
原始页总量聚合查询必须恰好执行一次。随后逐批核对全部 2,501 个成员，并要求
完整页读取数量和所有页查询次数均不增加，继续防止每个成员包重复全量扫描。
查询原始 before 的成员不存在时、快照关闭后拒绝读取、真实 SQLite WAL 并发
变更及输入、缓存读取、缓存写入、输出四类 Token 断言均保留。

不改生产代码、原始验证器或架构分类规则，不改变新测试的外部数据库调用站点。
本地仅作本次文件的格式与 lint 检查；修正后的测试结果以 GitHub Actions 为准。
默认 producer、CS v2 消费、规模验收和两个 RFC 的完整交付仍未完成。
