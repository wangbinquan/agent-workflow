## 动态工作组确认节点误判

原任务有五条执行记录和四个已受理模型执行。`openDwGate` 用相同的 `__dw_orchestrator__` 节点 ID 创建人工确认记录，但明确保存 `rerunCause=dw-gate`；生成执行保存 `dw-generate`。确认后 task.workflow_snapshot 替换为真正生成的 DAG，旧确认记录已不在当前图中。

现有 observationAttemptKinds 只读被替换后的 DAG，因而把真实人工确认记录判成 unknown，再报 invocation-unobserved。修复读取原任务冻结工作组配置与原执行 cause：只有动态工作组中的 `__dw_orchestrator__ + dw-gate` 是 non-agent；`dw-generate` 仍是 agent。普通 Agent、缺失/坏配置和其他未知执行仍保留缺口。所有执行记录与时长都保留，不删除确认节点、不编造零 Token、不缩小统计人口。

回归在原 SQLite/PostgreSQL 工厂上验证：完整确认后的报告可用；同名真实生成 Agent 缺量仍失败；非动态任务或错误 cause 不能获得零消耗豁免。代码与测试交准确提交的 hosted CI，本机不跑 AW 测试。
