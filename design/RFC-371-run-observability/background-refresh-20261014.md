# AW 后台刷新保留已验收快照

用户指出正式页面在数据与整页加载之间反复切换。已有实现只对 building 和请求尚未返回保留旧报告；当新版本先返回 not-ready，代码会同时废弃另一个仍有效的旧 reportId。React Query 已收到新 ready 数据但 fetching 尚未结束时，也可能因新旧 ID 不同而清空显示。这两条都是前台状态错误。

后台读取替代版本期间保留当前同范围的原已核对快照，继续显示原四类 Token、人民币、图表和截至时间。只有服务器实际拒绝那个旧 reportId、它的原事实页失效、查询范围变化或原身份检查失败，才撤下旧快照。新报告全部接收并核对后原子替换；替代报告未就绪的提示留在紧凑更新状态，不能与已有数据叠加整页加载。用户更换实际筛选或自定义范围的隔离语义、原丢失记录预言和来源完整性保持。

补三个正式组件回归：新 not-ready ID 期间始终保留四桶/CNY/原 asOf，原刷新按钮仍可在没有新 projection 的情况下显式重试；新 ready 数据已写入 QueryClient 但请求仍 fetching 时不撤下原卡片；该交错窗口内原展示快照的事实失效标志立即撤下原卡片，随后完整接受新报告。not-ready 不是仍在运行的请求，不能永久禁用刷新；有效性订阅跟随实际展示候选的 reportId。保留所有既有无效原记录、错范围、任务/维度返回、连续取消、焦点与时间端点用例。先完成全部代码和用例，再静态/有限功能检视及 GitHub CI；实际运行与页面证据另记录，不能把静态结论冒充 CI 或性能通过。
