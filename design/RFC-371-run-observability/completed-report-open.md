# RFC-371：重新打开直接读取已完成报告

实测相同范围首次完整生成仍需约 20.5 秒。页面的 `useCompleteObservationReport` 取回持久指针所指的原报告后，只将其作为 previous，再立即 POST 一次新生成；浏览器重新打开、冷 QueryClient 即使有可读取的同范围完成报告也会重复全量汇总。已有报告的总数可先显示，但仍产生一次完整后台构建和明细切换。

## 行为与接线

仅调整 `completeReportClient.ts` 原恢复分支：revision 为 0、当前 query 无报告 ID、持久指针存在时，仍先 GET 原报告，执行原 `assertCurrent`、报告 ID、filters、taskId、消费窗口事实及撤销判断。取得可显示的原完成内容后，将原 ID 写入当前 scope 的 retainedIds，返回该原响应作为当前 query 结果，不再额外 POST。所有页签、四桶、人民币、趋势及分页明细继续读同一报告 ID。存储始终只保留指针，不能从存储读出数字或拼接报告。

保留正式页现有“完整统计截至……；刷新可纳入后续记录”的时间说明。重新打开使用该时间的完整快照，不宣称包含截至时间之后的任务或用量。点击原“刷新”递增 revision，仍只产生一个新的完整构建；构建期间保留上次完成内容及日期，刷新按钮禁用，完成后全部页和数值换到新报告。首次没有指针、不同任务/筛选/身份范围、存储不可用，以及原 GET 404 均继续原完整生成路径。其他原 GET/明细错误、范围变化、无完成事实及中途取消仍按原逻辑撤销旧显示和指针，不能因提速静默保留坏数字。

不改后端人口、分页 EOF、原生采集、记录身份、汇总、金额、报告准入或发布协议；不加 TTL、任务数/调用数上限或部分成功。原未完成记录的四桶/人民币已知值和缺口标记继续由原事实决定。

## 验证与边界

现有冷恢复两种摘要、已知值/未知缓存桶/部分人民币、失败恢复回归改为先证明重新打开只 GET 原报告、不 POST；再通过实际刷新按钮启动新构建，保留所有原替换、禁用/防重复、失败撤销及旧指针不可清掉新指针断言。增加正式页面重新打开用例，核对原日期、四桶、CNY、柱状图和原明细 ID 一致，按钮可用且无额外 POST；原作用域、404、403/502、范围/任务冲突、取消/身份变化、存储不可用及坏明细回归保持。

限定设计和实现分别做独立功能复核；不在 AW 本机运行产品测试/构建，测试由 exact-SHA hosted CI 验证。实际页面只读取已授权原本机服务：先重新打开已完成范围，确认数字/图表/明细显示和没有新的构建；再一次显式刷新，确认唯一完整报告替换及所有原记录/四桶/人民币核对。重开速度与首次生成速度分开记录，本片不把首次约 20 秒重建写成已解决。
