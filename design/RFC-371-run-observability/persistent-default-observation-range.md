# RFC-371 重开默认观测范围的持久化

## 已确认的问题

正式页面普通刷新 `2df44dfe-2fea-4444-8857-b8319fff7959` 完整生成耗时 19,730 ms。只读采集原报告进度显示，首次观察到已提交页面时为 13,908 ms，此后保存、校验和发布共 5,822 ms；首次观察已经提交两页，200 ms 采样不是精确内部阶段计时。原 19,758 ms、21,668 ms、19,722 ms 等真实首建结果保留，不宣称首建已提速。此前 TEMP 结构复用候选在正式页面未表现出有效收益，三项源码和原测试已经仅通过本会话逆变更恢复原字节，设计和全部回执留在私有证据目录，不发布无收益候选。

现有 `observationDefaultRange.ts` 只在模块内保存已校验报告的默认七天范围。应用重新载入、随后通过空搜索的侧边栏进入时，该内存为空；`validateObservationSearch({})` 按新的 `Date.now()+1` 产生不同的范围，原先按精确范围保留的完整报告书签不能命中，重新触发全量生成。原已完成报告的读取与全量重建是两个不同路径；本次只修复重开路径的重复重建。

## 设计与实现计划

保留原默认范围的全部资格：只有原请求已经核对报告 ID、完整内容、Task 根范围和精确筛选后，才调用现有 `rememberObservationDefaultRange`。七天跨度、当前时区、无 Task/消耗窗口/名称/状态/仓库/工作流/维度筛选等条件保持。以现有认证服务地址与原 Token 的 SHA-256 为持久化键，沿用已存在的浏览器 SHA-256 纯 JS 实现，不新增摘要算法；键内不含原 Token。持久化仅包含原 `reportId/from/to/timezone` 四个指针字段，不保存统计事实、任务、Token、费用或声明报告已完成。

现有 `observationDefaultRange()` 仍同步返回范围：优先原有效内存；内存为空时仅从当前服务、同一 Token 对应的指针恢复合法的七天范围，并重新绑定本次认证版本和当前时区。不改原路由校验、URL 固定、任务切换、显式日期或任何筛选。随后现有报告客户端仍按精确筛选书签执行原 GET，对原 ID/内容/筛选/Task 范围和明细数量逐一核对；本次不新增直接展示数字的路径，不改变 404 回退、其他原错误、失败报告退休及手动刷新的全量 POST。原统计截至时间和记录缺口标识保持。

内存的原身份或时区发生变化时，先按原报告 ID 退休它的持久化指针，再清空内存；切走账号后再切回也不能复活已失效范围，保留原回归预言。现有 `discardObservationDefaultRange(id)` 同时删除该 ID 的默认范围指针，只按精确 ID 删除，不删后续已完成的其他报告。坏 JSON、错误字段类型、时间区间、缺失存储或摘要原语均回退原默认范围；存储失败不妨碍原已校验内存和报表路径。

候选只包含 `observationDefaultRange.ts`、新增聚焦回归文件和本设计文档。只增加一个私有作用域键构造函数；原路由、书签、报告客户端、后端、分页/完整遍历/EOF/四桶/人民币公式以及全部旧测试不改。STATE 仅在已验证批次发布时追加事实，不改并行输出。

## 验证与结论边界

新增回归通过实际模块重载和当前原路由校验/书签组合，证明默认范围及完整报告 ID 可以跨页面模块重开恢复、存储不含事实；覆盖当前服务/Token/时区不一致、切换后返回、错误指针、存储读写失败以及精确退休不删新报告。完整原 `rfc371-report-refresh-display.test.tsx` 的所有用例、206 处断言、原四处五秒预算及完整原 `rfc371-report-default-range.test.tsx` 均逐字保持，不修改任何旧失败证据。

先做有限独立 DESIGN，再实施、精确格式与 lint、有限 SOURCE；稳定候选只运行一次原四算法、原已提交基线加本会话完整候选、空 metadata seed 的规范投影，并做独立 MATCHING 后精确提交和推送。按用户要求不运行 AW 本地产品测试、类型检查、构建、E2E、压测或新增服务。整仓结论以精确提交的 GitHub CI 为准，不启动 observability-scale。正式页面需重载真实应用、从空搜索侧边栏重新进入，读取已校验报告并核对全部明细/汇总组、四桶、人民币、趋势；该验收不得冒充全新报告首建性能、全类型任务、规模验收或 CS 部署已经完成。
