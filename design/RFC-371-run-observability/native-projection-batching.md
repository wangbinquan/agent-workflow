# RFC-371 原生用量投影批量读取

状态：实现设计，属于已批准的完整统计性能修复范围。2026-10-10。

## 原始证据与范围

报告发布事务合并后，同一标记验收任务的报告 `6e274ab3-7457-4124-b329-78a822699fbc` 实测 16,222 ms。完整 summary、31,826 条派生行的所有字段及顺序、14,997 个分组计数与上一份报告完全一致；4,066 份原生及历史证据全文一致，3,732 份派生遍历收据全部 EOF 完成且人口相同，它们使用新报告和新快照身份。全部 7,798 份收据和 110 页仍然保留。

原始后端日志显示历史原生用量读取仍占 6,707.05 ms，其中 `native.next` 1,744 次共 5,072.29 ms。本次只优化合格原始 part 的数值投影读取，不调整历史来源选择、归属、时间范围、Token 规则、价格或报告发布。

只读原库研究对 2,743 个 session、13,030 条 message、49,527 条 part 做了正反顺序核对。连续键批量投影与原始逐键投影的全部字段、顺序及 9,321 个 step-finish 完全一致，完整哈希为 `a9f08d5361fe549489ec4a83ec1b0522026c1808ca6919d77be86b3647bd15e8`。两轮逐键读取为 2,623.49 / 3,153.30 ms，批量读取为 1,359.22 / 2,302.87 ms。这只证明该原库快照的投影等价，不能代替产品协议与性能验收。

## 设计

- 将当前原始 part 资格检查、键窗口和投影选择提取为同目录的内部辅助模块。保留现行 JSON 资格 SQL、逐键与非合格范围 SQL、字段表达式和顺序；主读取器仍负责原始计数、指纹、模型缓存写入、未完成 step、ACK、EOF、取消和关闭。
- 对现行最多 200 键的窗口，仅在原始资格检查通过且每个键都是非空字符串时，使用 `json_each` 的输入键 ordinal 驱动原始主键查找，并按 ordinal 返回同样的数值及模型字段。只投影原字段，不读取文本或工具正文。
- 必须验证投影行数和每个行 id 与原键列表完全一致。任何批量 SQL 错误、缺行、重复行或不一致都舍弃批量结果，继续原来的逐键或范围路径。保留异常源的原始成功前缀及原始错误，不把批量失败伪装成 EOF。
- 仍逐个处理原始行。只有原逻辑成功接收该行，才能推进键索引与原始 cursor、计数和 fingerprint；超过 packet 字节预算的行留到下一页。辅助模块返回当前投影的副本，避免删除 `cache_message` 或重试影响缓存窗口。
- 模型字段来自同一个原始只读快照。批量查询提前读取时尚未写入的 TEMP 模型缓存，只能改变内部缓存命中标志；该标志仍不进入原始指纹。模型、计数和归属不得改变。
- 200 只沿用原始传输窗口的工作量边界，不能限制 session、任务、调用、part、step、树深度或总页数。每个原始 root 保留独立快照，遍历所有行直到真实 EOF，不跨 root 或跨快照复用投影。
- 主读取器因提取而缩短，内部辅助模块保持在 500 行内；不通过新增大文件许可或增大现有许可上线。

## 验收

1. 独立功能设计检视完成后实施。既有原生读取、1,201 root、WAL 新写入、并行 ACK、模型未知、损坏子树及清理失败回归全部保留，原断言和预算保持。
2. 新增真实 SQLite 文件回归，以独立原始标量 SQL 作为全字段、顺序及 EOF 指纹预言；覆盖超过 200 原始 part、packet 字节提前分页、不同消息模型、未知数值、批量查询故障回退，以及 malformed JSON 的原始成功前缀。
3. 同一已授权标记任务再构建完整正式报告，逐项核对 summary、分类 Token、人民币估值、全部派生行和分组、全部来源证据与 EOF，并记录整体实际耗时。不得用纯 SQL 研究的提升代签正式页面性能。
4. 本机不运行产品测试、类型检查、构建或新服务；静态格式和 lint 可执行，产品回归以远端精确提交 CI 为准。

本设计不代表完整统计重算速度、全类型真实任务、规模验收、CS 部署或整体 RFC 已完成。
