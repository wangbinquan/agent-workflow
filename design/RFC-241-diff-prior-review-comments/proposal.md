# RFC-241 — 对比模式同屏只读显示上一版检视意见

## 背景

评审页 diff 模式(RFC-005/010)把当前待评版本与最近一次已决策版本
(priorVersion)做渲染态对比,但上一轮评审提出的检视意见(review
comments)在 diff 模式下不可见——评审者要自己另开历史版本页对照,无法
在对比现场直接核对"上次的意见是不是真的都改了"。

用户需求(2026-07-31):对比时同屏显示上一版文档的检视意见,**仅显示、
不可编辑**。三项形态决策已由用户拍板:右侧只读侧栏 / 仅显示上一版
(priorVersion)的意见 / 纯展示无"已解决"勾选态。

## 目标

1. diff 模式开启且 priorVersion 存在时,右侧出现**只读意见侧栏**:逐条
   展示上一版意见的正文、作者(含角色徽标,沿用现有 UI-only 语义)、
   时间与锚点路径文本(`sectionPath` + 行号标签,纯文本呈现,不做到
   diff 文中的内联锚定——合并文档章节会变,锚定必漂)。
2. 侧栏与正常模式的评论侧栏(`ReviewDocPane` 的 comment-bubble 视觉)
   同风格;顶部标注来源版本(如"上一版 v3 的检视意见 · 5 条")。
3. 上一版无意见时侧栏显示既有 `<EmptyState>` 风格的空态,不隐藏(让
   评审者确知"上轮没有意见"而非"没加载出来")。
4. 只读:无添加 / 编辑 / 删除入口,选区划词不触发评论 popover。

## 非目标

- 不做"已解决"勾选态与任何持久化(用户拍板;后续确有需要再立 RFC)。
- 不做历史全轮次意见汇总(仅 priorVersion;多轮历史另有 rounds 视图)。
- 不做意见到合并 diff 文档的内联锚定。
- 零后端改动:数据已由既有
  `GET /api/reviews/:nodeRunId/versions/:versionId`
  (`DocVersionWithBodyAndComments`)返回,diff 模式的 `priorBody` 查询
  已在取。

## 验收标准

- [ ] diff on + prior 存在 → 右侧只读意见侧栏,数量、正文、作者、锚点
      路径与该版本详情页一致。
- [ ] 上一版 0 条意见 → 空态文案可见。
- [ ] 无任何可编辑控件;正常模式的评论交互不受影响。
- [ ] diff off / prior 不存在 → 侧栏不渲染,页面与现状逐像素一致。
- [ ] i18n(zh/en)、渲染级测试(计数 / 只读性 / 空态 / 关闭态)。
